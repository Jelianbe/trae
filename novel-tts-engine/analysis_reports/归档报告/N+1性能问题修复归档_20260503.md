## 二、核心改动清单

### 2.1 N+1 问题诊断

#### 问题描述

**什么是 N+1 问题**：
```python
# ❌ 旧代码：N+1 查询问题
entities = session.query(Entity).all()  # 1 次查询获取所有实体

for entity in entities:
    # 每个实体单独查询关联的角色
    character = session.query(Character).filter_by(id=entity.character_id).first()
    # ... 处理逻辑
    # N 次额外查询！
```

**性能影响**：
- 100 个实体：1 + 100 = 101 次数据库查询
- 1000 个实体：1 + 1000 = 1001 次数据库查询
- 每次查询 ~10ms → 1000 实体需要 ~10 秒！

---

### 2.2 修复方案

#### 改动 1：使用 JOIN 预加载

```python
# ✅ 新代码：使用 JOIN 一次性获取所有数据
from sqlalchemy.orm import joinedload

entities = session.query(Entity)\
    .options(joinedload(Entity.character))\
    .all()  # 1 次查询，包含所有关联数据

for entity in entities:
    character = entity.character  # 无需额外查询，已预加载
    # ... 处理逻辑
```

**性能提升**：
- 100 个实体：1 次查询（从 101 次降低）
- 1000 个实体：1 次查询（从 1001 次降低）
- 1000 实体耗时：~10ms（从 ~10 秒降低）

#### 改动 2：批量处理优化

```python
# ✅ 批量查询关联数据
entity_ids = [e.id for e in entities]
characters = session.query(Character)\
    .filter(Character.id.in_(entity_ids))\
    .all()

# 建立映射字典
char_map = {char.id: char for char in characters}

for entity in entities:
    character = char_map.get(entity.character_id)
    # ... 处理逻辑
```

**旧代码**：
```python

    # 每次都查询同一批角色
    character = get_character(entity.character_id)

**新代码**：

    character = char_map.get(entity.character_id)
```

#### 改动 4：使用 IN 查询替代多次单条查询

```python
# ❌ 旧代码：N 次单条查询
for char_id in char_ids:
    char = session.query(Character).filter_by(id=char_id).first()

# ✅ 新代码：1 次 IN 查询
chars = session.query(Character).filter(Character.id.in_(char_ids)).all()
```

## 五、技术要点

### 5.1 何时使用预加载 vs 懒加载

| 场景 | 推荐策略 | 原因 |
|------|---------|------|
| 需要访问大部分关联数据 | 预加载 (joinedload) | 减少查询次数 |
| 只访问少量关联数据 | 懒加载 | 避免加载无用数据 |
| 关联数据很大 | 批量查询 + 映射 | 避免 JOIN 过大 |

### 5.2 SQLAlchemy 加载策略

```python
from sqlalchemy.orm import joinedload, subqueryload, selectinload

# JOIN 预加载（适合 1:1 关系）
query.options(joinedload(Entity.character))

# 子查询预加载（适合 1:N 关系）
query.options(subqueryload(Entity.children))

# SELECT IN 预加载（适合大集合）
query.options(selectinload(Entity.related))
```
