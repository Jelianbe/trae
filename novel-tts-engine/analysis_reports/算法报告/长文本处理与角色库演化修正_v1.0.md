## 长文本处理与角色库演化机制修正文档

**版本**: V1.0  
**日期**: 2026-05-02  
**背景**: 基于泛化性测试结果与业界实践分析，对现有方案（v3.11）进行针对性修正  
**关联模块**: `EntityClusterer`, `EntityLinker`, `SpeakerMatcher`, `PipelineRunner`

---

## 一、修正总览

| 修正项 | 原方案 | 修正方案 | 理由 |
|--------|--------|---------|------|
| **冷启动基准** | 按章节数（前3章） | **按累积字数（≥3000字）** | 统一度量，兼容无章节小说 |
| **聚类激活阈值** | 文本≥10000字 | **≥3000字** | 匹配网文单章发布习惯，覆盖更多场景 |
| **短文本聚类策略** | 不激活聚类 | **查询已有角色库（三级联动）** | 小文本复用历史积累，保持效果 |
| **聚类安全性** | 仅靠相似度阈值 | **增加上下文检查，重名不强制合并** | 防止“王管家A”与“王管家B”错误合并 |
| **代词消解** | 全局最近活跃 | **局部对话窗口（3次发言内）** | 提高长文本中“他/她”判断精度 |
| **长文本流式处理** | 逐章处理 | **保留并强化，增加增量聚类流式API** | 快速呈现结果，支持实时更新 |

---

## 二、冷启动机制修正

### 2.1 基准统一为“累积字数”

不再使用“前N章”作为冷启动判定，改为统计已处理的累积字符数。当 `PipelineRunner` 处理的总字符数首次达到 **3000字** 时，自动执行一次批量聚类，将所有满足条件的实体从 `is_confirmed=0` 升级为 `is_confirmed=1`。

**实现**：
- `PipelineRunner` 内部维护 `_total_processed_chars` 计数器。
- 每次处理完一章后累加，检查是否 ≥ 3000 且 `_cold_start_done == False`。
- 达到条件后调用 `EntityClusterer.cluster(write_back=True)`，然后将 `_cold_start_done` 置为 `True`。

### 2.2 未达阈值的行为

累积字数不足3000字时，所有实体以 `is_confirmed=0` 状态入库，不触发自动确认。此阶段用户的任意手动确认（`locked=1`）会立即生效，且不受后续批量聚类影响。

## 三、聚类模块修正

### 3.1 激活阈值调整

`EntityClusterer` 的短文本保护门槛从 `10000字` 降低为 `3000字`。

```python
# 调整前
SHORT_TEXT_LIMIT = 10000

# 调整后
MIN_CLUSTER_CHARS = 3000
```

低于3000字的输入，不执行完整聚类，改为加载已有角色库别名映射，通过 `EntityLinker` 完成链接。

### 3.2 增加重名消歧保护

当两个实体上下文相似度极高，但各自拥有独立章节出现记录、稳定代词和不同头衔时，`EntityClusterer` 不以高置信度自动合并，而是创建 `ambiguous` 标记，写入 `character_change_log` 供用户审核。

**判定条件**：
- 余弦相似度 > 0.85
- 且双方各自出现 ≥ 3章，且各自独立作为说话人 ≥ 2次
- 同时满足时标记为 `ambiguous`，置信度保持0.6，不升级。

### 3.3 预留流式API

新增 `ingest_mentions(chapter_id, entities)` 方法，用于处理新章节的实体提及，实时返回更新的聚类关系。该方法不立即写库，而是返回变更列表，由 `PipelineRunner` 决定是否批量写回。

## 四、说话人匹配修正

### 4.1 局部对话窗口代词消解

在 `SpeakerMatcher` 中为代词匹配增加“最近3次发言内的唯一性别候选”规则，替代仅依赖全局活跃度的模糊匹配。

**逻辑**：
1. 查找当前句代词（他/她/它）。
2. 获取最近3次对话的说话人（从 `_recent_speakers` 中取最后3个实际说话角色）。
3. 若该集合内只有1个角色性别匹配，直接返回该角色，置信度0.90。
4. 仍无唯一解则走L2语义排序。

该修正无需新增模型，仅优化现有规则。

---

## 五、三级联动机制（已有角色库时）

处理任意长度文本时，若已有角色库积累（`characters` 表非空），按以下优先级联动：

1. **别名/标准名精确匹配**：直接链接，置信度1.0。
2. **角色向量相似度**：查询已有角色向量，计算余弦相似度，高于0.85则链接。
3. **实体链接器**：`EntityLinker.link()` 自动完成上述匹配，并返回 `standard_name` 或 `alias` 字段。
4. **聚类模块**：仅在全文累积字数 ≥ 3000 且无历史聚类结果时启动。

这保证单章重分析时，仍能利用全书的聚类信息。

## 六、实施计划与影响评估

| 任务 | 预计工时 | 涉及文件 | 预期收益 |
|------|---------|----------|----------|
| 冷启动基准改为字数 | 0.5天 | `PipelineRunner` | 兼容所有文本格式 |
| 聚类阈值降为3000字 | 0.5天 | `EntityClusterer` | 西幻NER +10~15% |
| 重名消歧保护 | 1天 | `EntityClusterer` | 防止长文本误合并 |
| 局部对话窗口代词 | 0.5天 | `SpeakerMatcher` | 说话人匹配精度 +2~3% |
| 流式API接口预留 | 0.5天 | `EntityClusterer`, `PipelineRunner` | 为实时处理打基础 |
| 三级联动测试与联调 | 1天 | 全套评估脚本 | 验证组合效果 |

**综合影响**：预计西幻NER从55.6%提升至68-72%，说话人匹配提升2-3%，整体新权重综合分提升5-8分。

## 七、回归验证计划

使用现有三份测试文本（修仙、都市、西幻），在三轮稳定性测试框架下：
- 验证冷启动≥3000字时聚类是否正确触发。
- 验证西幻文本中“弗莱迪”、“摩罗”、“弗莱迪伯爵”的合并率。
- 验证都市文本无此模式时是否产生误合并。
- 验证单章重分析（有角色库积累）时，NER和说话人匹配得分是否维持。
