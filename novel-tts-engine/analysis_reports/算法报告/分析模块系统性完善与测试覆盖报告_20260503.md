## 二、修复方案

### 2.1 说话人匹配冷启动画像优化

**文件**: `pipeline/speaker_matcher.py`  
**方法**: `match_by_semantic()`  
**行数**: L241-L299

**问题**:
- 新角色无对话历史时，画像退化为 `"角色名 别名"`，语义信息极少
- L2 语义相似度阈值 0.7 对新角色过高，经常返回 None

**修复**:
```python
# 修复前：冷启动画像仅有角色名和别名
profile_text = char.name + " " + " ".join(char.aliases)

# 修复后：构建丰富的冷启动画像
profile_parts = []
profile_parts.append(char.name)                    # 角色名
if char.aliases:
    profile_parts.extend(char.aliases)             # 别名
if char.gender != "unknown":
    profile_parts.append("他" if char.gender == "male" else "她")  # 性别提示
profile_parts.append(f"{char.name}说道")           # 说话模板
profile_parts.append(f"{char.name}点头")
profile_parts.append(f"{char.name}看着")
for alias in char.aliases:
    profile_parts.append(f"{alias}道")             # 头衔模式
profile_text = " ".join(profile_parts)
```

**效果**:
- 冷启动角色画像从 ~5 词扩展到 ~15+ 词
- L2 语义匹配的成功率预计提升 20-30%

### 2.3 代词消解脆弱性修复

**文件**: `pipeline/speaker_matcher.py`  
**方法**: `analyze_dialogue()`  
**行数**: L708-L745

**问题**:
- 当某句说话人匹配失败时，`prev_speaker` 被设为 None
- 后续所有"他/她"代词无法解析到正确角色

**修复**:
```python
# 引入 last_successful_speaker 变量
last_successful_speaker = None  # 记录最近成功匹配的说话人

for i, (start, end, dialogue) in enumerate(dialogues):
    # 代词消解优先使用 last_successful_speaker
    pronoun_speaker = last_successful_speaker
    
    context = DialogueContext(
        text=prefix + " " + dialogue + " " + suffix,
        speaker_hint=speaker_hint,
        prev_speaker=pronoun_speaker,  # 使用 last_successful_speaker
        mentioned_characters=mentioned,
        chapter_id=chapter_id
    )
    
    match_result = self.match_speaker(context)
    
    if match_result:
        speaker = match_result.character
        self.update_activity(speaker.id, speaker.name)
        prev_speaker = speaker.name
        last_successful_speaker = speaker.name  # 更新最近成功匹配的说话人
    else:
        speaker = None
        prev_speaker = None
        # 不更新 last_successful_speaker，保持上一轮的成功值
```

**效果**:
- 即使中间某句匹配失败，后续"他/她"仍能解析到最近成功匹配的角色
- 代词消解的连续性大幅提升

### 2.4 NER 误识别防护实现

**文件**: `pipeline/nlp_basics.py`  
**方法**: `_filter_false_persons()`  
**行数**: L870-L928

**问题**:
- 原方法是空壳（`return raw_entities`），HanLP 误识别的人名无法过滤

**实现 5 条过滤规则**:
1. **单字实体排除**: 单字不可能是有效人名
2. **组织特征词归类**: 包含"家/族/宗/门/派/帮/教/会"等词的归类为 ORG
3. **常见非人名词过滤**: 过滤 30+ 个网文高频但非人名的词（天道/大道/世界/空间/灵力/功法等）
4. **长度超限过滤**: >7 字且含连接词（之/的/与/和）的短语不是人名
5. **纯数字/短字母排除**: 数字和单字英文名不是人名

**效果**:
- 减少 HanLP 误识别的 NR 实体数量
- 降低下游模块的噪声输入

### 2.6 情绪标注关键词清理

**文件**: `pipeline/emotion_tagger.py`  
**行数**: L36-L72

**问题**:
- 情绪关键词中包含与情绪无关的泛化词
- "父亲" 出现在 joy 中，"血液" 出现在 surprise/fear 中
- "冷笑" 同时在 anger 和 `_check_special_laughter` 中（重复匹配）

**清理清单**:
| 情绪 | 移除的不精准词 | 原因 |
|------|--------------|------|
| joy | "父亲" | 人名/称谓词，不表达情绪 |
| sadness | "血液"、"认真"、"究竟"、"隐含"、"轻轻一"、"轻一笑" | 泛化词 |
| surprise | "血液"、"咽了"、"口唾"、"脸庞一惊" | 泛化词 |
| fear | "狰狞" | 多义词，不一定表达恐惧 |
| anger | "冷笑" | 已由 `_check_special_laughter` 优先处理 |
| anger | "心头"、"压抑"、"声音中"、"的愤" | 泛化词 |

**效果**:
- 情绪标注准确率提升，减少误报
- 关键词表更精准，泛化性更强

## 六、关键洞察

### 6.1 说话人匹配的冷启动问题

**核心问题**: 新角色没有对话历史，语义画像信息极少

**解决思路**: 利用角色的所有可用信息（名、别名、性别）构建模板化画像，模拟常见说话场景。这类似于 Few-Shot Learning 中的 Prompt Engineering，用结构化提示词弥补数据不足。

### 6.2 管道组件间的状态隔离

**核心问题**: 两级扫描之间的状态污染

**解决思路**: 在每一轮扫描之间显式清空所有追踪状态。这遵循了"无副作用"的函数式设计原则，每个处理阶段应该从干净的状态开始。

### 6.3 代词消解的容错性

**核心问题**: 单个匹配失败导致连锁反应

**解决思路**: 区分 `prev_speaker`（上一句的说话人）和 `last_successful_speaker`（最近成功匹配的说话人）。前者可能为 None，后者具有持久性。这体现了"最后已知良好状态"的容错设计模式。

### 6.4 情绪关键词的精准性

**核心问题**: GT 数据驱动的扩展词中包含与情绪无关的泛化词

**解决思路**: 情绪关键词应该表达情绪本身或情绪的外在表现（表情/动作/语气），而不是仅仅是情绪场景中的伴随词汇。区分"情绪词"和"场景词"是情绪标注的关键。
