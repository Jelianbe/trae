基于你将 NER 目标收敛为“只识别说话角色”以及已有的 `ContextDiversityValidator`，这份改进方案将两者正交融合，形成一套可泛化、高精确的实体发现与验证机制，直接服务于说话人匹配与最终有声制作。

---

## 一、核心思想：两条逻辑链交叉验证

```
文本 ──→ HanLP + 规则增强 ──→ [候选实体 100+]
                │
                ├── 逻辑链A (ContextDiversityValidator)
                │      └─ 按上下文多样性、频率调整置信度
                │
                └── 逻辑链B (说话角色过滤器)
                       └─ 只保留出现在“对话引导词”附近的实体
                       └─ 对低频但多次出现在不同对话中的实体启用 L2 置信度补偿
                │
                ▼
         最终实体列表（只含说话角色，高精确）
```

**关键收益**：  
- 大量只存在于旁白中的词汇（如“暗影会”、“总监”、“组织”）被直接剔除，因为它们从未出现在对话引导词附近。  
- 西幻低频说话角色（如“莫洛克”）由于在多个不同对话场景中作为说话人出现，被说话角色过滤器“兜底捞回”，不再被误杀。

### 2.1 新增模块：`pipeline/speaker_role_filter.py`

该模块负责对实体进行“是否为说话角色”的判定，并利用 L2 语义交互验证增强低频实体的置信度。

### 2.2 修改 `ContextDiversityValidator`，使其可配置“模式”

为 `ContextDiversityValidator` 添加一个 `mode` 参数：
- `mode='general'`：默认行为，使用原先的阈值（min_occurrences=3, high_conf_threshold=5）。
- `mode='speaker_role'`：说话角色模式，阈值降低（min_occurrences=2, high_conf_threshold=3），因为说话角色本身信号强，不需要太高频次。

```python
class ContextDiversityValidator:
    def __init__(self, mode='general'):
        if mode == 'speaker_role':
            self.min_occurrences = 2
            self.high_conf_threshold = 3
        else:
            self.min_occurrences = 3
            self.high_conf_threshold = 5
        # ... 其余不变
```

## 三、风险与回退

1. **漏掉从未说话的重要旁白角色**：  
   - 风险评估：这些角色在最终有声书中没有台词，不需要声线，不属于核心业务目标。  
   - 回退：若不满意，可将 `SpeakerRoleFilter` 设计为可插拔组件，通过开关控制。

2. **L2 交互验证带来额外性能开销**：  
   - 缓解：`_extract_dialogue_entities` 只做一次，L2 补偿仅对极低频实体触发（一般少于 5 个），不影响整体性能。

3. **若效果不符预期**：  
   - 先移除 `SpeakerRoleFilter`，保留 `ContextDiversityValidator` 的说话角色模式调整，逐步迭代。
