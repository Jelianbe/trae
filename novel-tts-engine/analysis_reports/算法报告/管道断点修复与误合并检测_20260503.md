## 一、问题背景

### 1.1 "萧炎冷"误报问题

斗破苍穹NER测试中，"萧炎冷"持续作为False Positive出现：

- **HanLP原始输出**: `萧炎冷笑道` → `萧炎冷`(PERSON) + `笑道`(动词)
- **统计验证结果**: `ContextDiversityValidator` 正确将"萧炎冷"降级为0.3低置信度
- **最终结果**: "萧炎冷"仍出现在False Positives列表中

### 1.2 根本原因诊断

通过 `trace_xiaoyan_cold_pipeline.py` 逐段调试，确认管道中存在信息断裂：

| 步骤 | 组件 | "萧炎冷" confidence | 状态 |
|------|------|---------------------|------|
| 1 | nlp.analyze() | 0.90 | HanLP原始输出 |
| 2 | ContextDiversityValidator | 0.30 | ✅ 统计验证正确降级 |
| 3 | SpeakerRoleFilter | 0.45 | ⚠️ L2补偿提升0.15 |
| 4 | EntityLinker | 0.45 | 未链接，保持 |
| 5 | 最终过滤 (>=0.5) | 被拦截 | ✅ 被过滤 |

**关键发现**：
- 统计验证正确工作（0.9 → 0.3）
- SpeakerRoleFilter的L2补偿过度提升（0.3 → 0.45）
- L2补偿机制没有上限，能够覆盖统计验证的降级结果

## 二、修复方案

### 2.1 修复1：限制L2补偿范围

**文件**: `pipeline/speaker_role_filter.py`  
**方法**: `_apply_l2_boost()`

**问题**：
```python
# 旧代码：L2补偿可以任意提升置信度
if scene_count >= 3:
    return 0.8  # 直接将0.3提升到0.8
else:
    return 0.65  # 直接将0.3提升到0.65
```

**修复**：
```python
def _apply_l2_boost(self, entity: Entity, full_text: str) -> float:
    """
    检查该实体作为说话人的场景次数，提升置信度
    
    2026-05-02 修复：L2补偿不应覆盖统计验证的降级结果。
    统计验证（ContextDiversityValidator）已经将某些实体降级为低置信度（如0.3），
    这表示该实体在统计意义上不可靠（右邻字单一、共现多样性低等）。
    L2补偿只能在原始置信度的基础上做小幅增量，不能超过原始值的1.5倍。
    这确保统计验证的降级结果不会被意外覆盖。
    """
    original_conf = entity.confidence
    scene_count = self._entity_scene_count.get(entity.text, 0)
    
    if scene_count >= 2 and self.semantic_ranker.is_available():
        # 根据场景次数计算L2提升后的置信度
        if scene_count >= 3:
            l2_boosted = 0.8
        else:
            l2_boosted = 0.65
        
        # 修复：L2补偿不能超过原始置信度的1.5倍
        # 防止统计验证已降级的实体（如0.3）被提升到过高值（如0.65）
        max_allowed = min(0.95, original_conf * 1.5)
        return min(l2_boosted, max_allowed)
    
    return entity.confidence
```

**效果**：
- "萧炎冷" (confidence=0.3) 在L2后变为 min(0.65, 0.3*1.5=0.45) = 0.45
- 0.45 < 0.5，被最终过滤正确拦截

### 2.2 修复2：统计误合并检测

**文件**: `pipeline/context_diversity_validator.py`  
**新增方法**: `_detect_mis_merged_entities()`

**设计原则**：
- 不使用硬编码黑名单（FALSE_PERSON_ENDINGS）
- 基于统计验证和语言学特征
- 利用全文级别的统计信息（出现次数、已知角色等）

**检测逻辑**：
1. 实体长度≥3
2. 末端1-2字是常见表情/动作词
3. 去除末端后，剩余部分是出现≥5次的高频角色名

```python
def _detect_mis_merged_entities(
    self,
    entities: List[Entity],
    stats: Dict[str, Dict],
    full_text: str,
) -> set:
    """
    误合并检测（2026-05-03 新增）
    
    检测HanLP将"人名+动词"误合并为更长的"人名"的情况。
    例如："萧炎冷笑道" → "萧炎冷"(PERSON)
    
    检测逻辑：
    1. 实体长度≥3
    2. 末端1-2字是常见表情/动作词
    3. 去除末端后，剩余部分是一个出现≥5次的高频角色名
    
    如果满足以上条件，标记为误合并。
    """
    # 常见单字表情/动作词（这些字在人名末尾极不常见）
    SINGLE_CHAR_VERBS = {
        '冷', '笑', '怒', '喜', '愁', '悲', '愤', '急', '惊', '疑',
        '呆', '愣', '痴', '醉', '困', '累', '饿', '渴', '痛', '痒',
        '羞', '恼', '恨', '怨', '叹', '泣', '吼', '喊', '叫', '骂',
    }
    
    # 找出出现≥5次的高频角色名（作为已知角色）
    known_persons = set()
    for entity_text, stat in stats.items():
        if stat['occurrences'] >= 5:
            known_persons.add(entity_text)
    
    mis_merged = set()
    
    for entity in entities:
        if entity.type != 'PER' or len(entity.text) < 3:
            continue
        
        # 检查末端1-2字
        for suffix_len in [1, 2]:
            if len(entity.text) <= suffix_len:
                continue
            
            prefix = entity.text[:-suffix_len]
            suffix = entity.text[-suffix_len:]
            
            # 如果前缀是已知高频角色
            if prefix in known_persons:
                # 检查后缀是否是常见动词
                is_verb = False
                if len(suffix) == 1 and suffix in SINGLE_CHAR_VERBS:
                    is_verb = True
                elif len(suffix) == 2:
                    # 检查是否是"动词+道"等结构
                    if suffix.endswith('道') and suffix[0] in SINGLE_CHAR_VERBS:
                        is_verb = True
                
                if is_verb:
                    mis_merged.add(entity.text)
                    logger.debug(
                        f"检测到误合并: {entity.text} → "
                        f"prefix='{prefix}'(出现{stats[prefix]['occurrences']}次) + "
                        f"suffix='{suffix}'"
                    )
                    break
    
    return mis_merged
```

**在validate方法中集成**：
```python
def validate(self, entities: List[Entity], full_text: str, ...):
    # ... 统计验证 ...
    
    # 误合并检测（2026-05-03 新增）
    mis_merged_entities = self._detect_mis_merged_entities(all_entities, stats, full_text)
    for entity_text in mis_merged_entities:
        if entity_text in stats:
            for entity in all_entities:
                if entity.text == entity_text:
                    entity.confidence = 0.1
                    logger.debug(f"误合并检测: {entity_text} → confidence=0.1")
    
    # ... 最终过滤，confidence<=0.1的实体被过滤 ...
```

**效果**：
- "萧炎冷" → prefix="萧炎"(267次) + suffix="冷" → 标记为误合并 → confidence=0.1 → 被过滤
- "陈承喏"（真实人名）→ 右邻字多样 → 不满足误合并条件 → 保留

## 四、关键洞察

### 4.1 管道断点问题

**问题本质**：统计验证的正确结果在管道传输中被覆盖。

**根本原因**：
1. `ContextDiversityValidator` 正确地将"萧炎冷"从0.9降级到0.3
2. `SpeakerRoleFilter` 的L2补偿机制没有上限，将0.3提升到0.65
3. 这种提升覆盖了统计验证的降级结果

**修复原则**：
- L2补偿只能做小幅增量，不能超过原始值的1.5倍
- 统计验证的降级结果必须被尊重和传递
- 下游组件不能随意覆盖上游的统计判断

### 4.2 黑名单 vs 统计验证

**黑名单的问题**：
- 是对问题的"记忆"而非"学习"
- 无法处理"熊家强"、"岗村宁次"、"云岚"等真实人名
- 维护成本高，需要不断添加新的黑名单字符
- 泛化能力差

**统计验证的优势**：
- 基于全文级别的统计信息（出现次数、右邻字多样性等）
- 利用已知高频角色名作为参考
- 结合语言学特征（表情/动作词尾）
- 不依赖硬编码词表，泛化能力强
