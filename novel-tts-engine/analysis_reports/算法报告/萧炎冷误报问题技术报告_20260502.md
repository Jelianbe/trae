## 一、问题描述

### 现象

在斗破苍穹第1-10章测试中，"萧炎冷"被误识别为人名实体（PER类型），导致：
- **False positives**: 1个（萧炎冷）
- **Precision**: 6/(6+1) = 85.7%
- **NER F1**: 85.7（原本可达92.8+）

### 根因

HanLP中文NER模型将"萧炎冷笑道"错误切分为：
- **"萧炎冷"** → 被识别为人名（PERSON）
- **"笑道"** → 动词

这是HanLP的已知问题——它将人名后的表情/动作修饰字错误地合并到人名中。类似问题还包括：
- "萧炎承喏道" → "萧炎承"(人名)
- "萧炎皱眉道" → 可能识别为"萧炎皱眉"
- "萧炎淡然道" → 可能识别为"萧炎淡然"

## 二、已尝试的修复方案

### 方案1：`_filter_false_persons`方法

**实现位置**：[nlp_basics.py L862-897](file:///D:/trae/novel-tts-engine/pipeline/nlp_basics.py#L862-L897)

**逻辑**：
```python
FALSE_PERSON_ENDINGS = {
    '冷', '笑', '怒', '喜', '愁', '悲', '愤', '急', '惊', '疑',
    '呆', '愣', '痴', '醉', '困', '累', '饿', '渴', '痛', '痒',
    '羞', '恼', '恨', '怨', '叹', '泣', '吼', '喊', '叫', '骂',
    '承', '喏', '应', '答', '回', '点', '摇', '转', '走', '站',
}

def _filter_false_persons(self, entities):
    for e in entities:
        if len(e.text) > 1 and e.text[-1] in FALSE_PERSON_ENDINGS:
            continue  # 过滤掉
    return entities
```

**调用位置**：
1. `_extract_entities_from_pos()` L858（jieba回退路径）
2. `_enhance_entities()` L423（HanLP主路径）

**测试结果**：

| 测试场景 | 结果 | 说明 |

| 单句测试：`nlp.analyze('萧炎冷笑道')` | ✅ 成功 | 返回"萧炎"，"萧炎冷"被过滤 |
| 直接调用`_filter_false_persons(['萧炎冷', '萧炎承', '萧炎'])` | ✅ 成功 | 只返回"萧炎" |
| 完整文本评估：`evaluate_generalization_v3.py` | ❌ 失败 | "萧炎冷"仍在false positives中 |

- 调试脚本`debug_xiaoyan_cold_full.py`在完整文本中找到了"萧炎冷"

### 推断根因

**最可能的原因**：Python模块加载/缓存问题。虽然清除了`__pycache__`和`.pyc`文件，但评估脚本可能通过某种方式加载了旧版本的模块。

**其他可能性**：
1. `_combine_entities`方法可能在`_filter_false_persons`之后又创建了"萧炎冷"
2. `discover_compound_entities`可能在统计发现时重组了"萧炎冷"
3. 评估脚本中的某个中间步骤绕过了过滤逻辑

**实现位置**：`evaluate_generalization_v3.py` L176之后

**代码**：
```python
# 后过滤：过滤HanLP误识别的虚假人名
# "萧炎冷"、"萧炎承"等以表情/动作字结尾的3字"人名"

    '冷', '笑', '怒', '喜', '愁', '悲', '愤', '急', '惊', '疑',
    '承', '喏', '应', '答', '回', '点', '摇', '转', '走', '站',
}

    e for e in high_conf_entities

]
```

**优点**：绕过模块加载问题，直接在评估管道中过滤
