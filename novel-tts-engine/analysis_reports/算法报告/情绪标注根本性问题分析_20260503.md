# 情绪标注根本性问题分析

**日期**: 2026-05-03
**类型**: 架构反思报告
**状态**: 待验证
**触发**: 外部审查指出管道方向性错误

---

## 一、核心指控

> 你们在优化错误的东西。

管道围绕"谁在说话"设计，但 TTS 需要的是"怎么说话"。

---

## 二、数据验证

### 2.1 情绪 F1 均值 26.7% vs 角色 F1 92.3%

| 指标 | 分数 | 工程投入 |
|------|------|---------|
| 斗破 NER | 92.3% | ~50 小时 |
| 说话人匹配 | 76.2% | ~30 小时 |
| 情绪标注 | **26.7%** | ~5 小时 |

情绪标注是管道里最低的分数，但得到的工程投入最少。

### 2.2 规则系统 neutral 占比 80%

测试 150 条对话：
- neutral: 120 (80%)
- sadness: 14 (9%)
- surprise: 9 (6%)
- joy: 6 (4%)
- anger: 1 (0.7%)
- fear: 0 (0%)

**"全体集合！准备战斗！" → neutral**
**"稳住阵型！" → neutral**
**"轰隆！" → neutral**

如果 TTS 用中性语气读"你给我滚出去"——声线对了，语气死了。

### 2.3 管道数据流验证

```
文本 → chapter_splitter (保留全文)
  → dialogue_classifier (提取引号内对话，丢弃引导词)
  → sfx_detector (检测拟声词)
  → NER (提取人名，保留)
  → context_diversity_validator (过滤假人名，保留)
  → speaker_role_filter (过滤非说话角色，丢弃非对话实体)
  → character_manager (别名映射，保留)
  → speaker_matcher (分配说话人，保留)
  → semantic_ranker (语义排序，保留)
  → emotion_tagger (规则情绪标注 ← 只剩纯文本)
```

emotion_tagger 拿到的是**已经被 10 步处理过的纯文本**。原始文本的标点密度、句式长短、脏话分布、感叹号频率——这些情绪信号在管道流经 `dialogue_classifier` 的时候就被丢弃了。

## 三、三个错误的数据支持

### 错误 1：角色归属优先级过高

**证据**: 六级漏斗、冷启动画像、状态污染修复、代词消解 = 至少 30+ 小时工程时间。情绪标注只有关键词匹配，无 ML 模型支持。

**影响**: 一个苏夜的愤怒台词被林雪的声线读出来——不舒服，但情绪还在。一个苏夜的愤怒台词被苏夜的声线用中性语气读出来——灾难。

### 错误 2：情绪信号在管道前端丢失

**证据**: emotion_tagger 只接收 `sentence` 参数（纯文本字符串），没有上下文、没有引导词、没有标点统计、没有句式分析。

**影响**: 80% 的对话被标注为 neutral，因为规则系统只能匹配显式情绪词（"怒"、"哭"、"惊讶"），而大量情绪通过标点、句式、上下文传递。

### 错误 3：从未定义"好的 TTS 体验"

**证据**: 整个项目文档中没有任何一段描述"什么叫好的有声书"。KPI 是"端到端正确率"，但这是一个工程指标，不是体验指标。

**影响**: 管道围绕工程指标优化，产出物在听感上不合格。

---

## 四、三种改进方案

### 方案 A（激进）：情绪优先管道

```
文本 → dialogue_classifier（保留原始文本窗口）
  → emotion_extractor（直接从原始文本提取情绪特征，不依赖角色）
  → speaker_matcher（降级为辅助，只影响声线选择）
  → tts_generator（情绪为主要输入，声线为次要输入）
```

### 方案 B（务实）：双管道并行

```
管道1（角色）：文本 → 现有管道 → speaker输出
管道2（情绪）：文本 → 独立情绪模型（BERT fine-tune） → emotion输出
合并：speaker决定声线，emotion决定语气 → TTS
```

### 方案 C（最快验证）：LLM 离线跑一轮

用 qwen2.5-3b 或等效模型对测试文本做情绪标注，直接看 F1。
- 如果 LLM 能做到 50%+：有了一条明确的路
- 如果也做不到 30%：说明文本本身的情绪标注就是极难任务

---

## 五、结论

**指控成立。**

1. 情绪标注 F1 26.7% 是管道里最低的分数
2. 规则系统 neutral 占比 80%，大量明显有情绪的对话被标注为中性
3. 工程投入严重倾斜于角色归属（30h+）而非情绪识别（5h）
4. 管道在 dialogue_classifier 阶段丢弃了情绪信号，导致 emotion_tagger 在贫瘠数据上猜测
5. 从未定义"好的 TTS 体验"
