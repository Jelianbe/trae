# 情绪标注模块 — 验证、策略与长线演进

**版本**: V2.0

**日期**: 2026-05-03

**背景**: 基于假设驱动开发方法论，对情绪标注模块进行验证，发现方法论缺陷，制定分阶段开发策略，并纳入分层情绪映射体系作为长线演进蓝图

**关联模块**: `emotion_tagger.py`、TTS集成、`pipeline_runner.py`

---

## 一、当前状态

### 1.1 模块现状

| 维度 | 状态 |

|------|------|

| 实现方式 | 纯规则（正则匹配 + 关键词词典） |

| 支持情绪 | joy, anger, sadness, surprise, fear, neutral（6种） |

| 标注方式 | 单标签 |

| 强度分级 | 无 |

| TTS参数映射 | 未实现 |

| 验证状态 | ⚠️ 存疑，需人工复核 |

### 1.2 已验证能力

在16句测试集上获得100%准确率，可正确识别**包含明确情绪关键词的句子**。

### 1.3 已知局限

| 局限 | 详情 | 影响 |

|------|------|------|

| 无法处理隐晦情绪 | “他沉默了很久”当前误判为neutral | 丢失细腻情感 |

| 无法处理否定句式 | “并不高兴”当前误判为joy | 错误放大情绪 |

| 无法识别讽刺 | “真是太好了”（实际愤怒）误判为joy | 严重误判 |

| 无法感知上下文 | 无法利用`speaker`参数追踪角色情绪变化 | 缺乏连续性 |

| 强度不可控 | 只有标签没有强度 | TTS只能“有感情朗读”，无法“有层次表演” |

## 二、验证方法论缺陷

### 2.1 自检盲区

16个测试样本**全部由AI自行生成**，这是验证而非训练的问题。AI知道情绪标注器用`"笑"`判断joy，在创建测试句时无意识地包含此词，导致100%准确率是虚假高分。

类比：一个人同时给自己出题、答题、评分，结果不可信。不是代码有问题，是测试方法有问题。

### 2.2 修正后的验证方法

| 阶段 | 方法 | 约束 |

|------|------|------|

| **短期** | 从《斗破苍穹》前10章抽取50句真实对话，人工标注预期情绪 | 标注者须独立于AI生成 |

| **中期** | 引入开源数据集（如Scientific Data的2588故事对话情绪标注集）作为交叉验证 | 确保测试覆盖多样性 |

| **长期** | 使用上下文感知的自动评估框架 | 覆盖混合情绪和复杂语境 |

## 三、行业主流方案调研

### 3.1 三条技术路线

| 路线 | 核心思路 | 代表方案 | 优势 | 劣势 |

|------|---------|---------|------|------|

| **文本理解+情感计算** | NLP自动预测情绪标签 | BERT-BiGRU情感词典模型(F1=92.6%)、Rule-BertAtten | 无需人工标注，能发现复杂情绪 | 需训练模型 |

| **AI质检师** | 用AI评估合成语音情感 | Dopamine Audiobook的GPT评估框架 | 自动化大规模评估 | 依赖大模型 |

| **工程取巧** | 使用现成开源数据集 | Scientific Data的2588故事对话数据集 | 零成本，即拿即用 | 无中文数据 |

### 3.2 核心洞察

业界趋势是**让模型自动学习**而非手工设计标签。情感计算领域的研究表明，将基于知识的词汇特征（如Hownet情感词典）与深度学习模型结合，能显著提升情感分析的准确性。这印证了我们“规则兜底、统计增强”的架构方向是正确的。

## 四、分阶段开发策略

### 4.1 关键决策：开发阶段允许使用云端AI辅助

**原则**：区分“开发工具”与“用户产品”。

*   **开发阶段**：可以使用任何工具（包括云端AI、Trea、我）来辅助标注、调试、验证。

*   **用户产品**：严格纯本地运行，零外部API依赖，零联网。

当前阶段属于开发阶段，使用AI辅助标注不违背项目原则。

### 4.2 短期（当前迭代）：AI辅助标注 + 人工校准，建立高质量基准

**目标**：1小时内完成50句真实对话的情绪标注，建立有外部约束的测试基准。

**操作模式**：

1.  从斗破前10章抽取50句对话，每句带前后各一段上下文。

2.  由我来做初标——逐句给出情绪标签、强度分级、判断依据。

3.  你负责抽查和统一校准——有问题的纠正，没问题的通过。纠正的样本我会学习你的偏好。

**优势**：

*   **效率**：你的角色从“标注+判断”降为“抽查+校准”。

*   **一致性**：同一类上下文我不会今天标joy明天标sadness。

*   **可追溯**：每句标注都有我的判断依据。

### 4.3 中期（后续2-3轮迭代）：训练本地轻量情绪分类器

**目标**：完全本地运行的情绪分类器，准确率70-80%。

**方案**：以短期产物（50+句人工校准标注）为训练数据，微调BGE-small或FastText情绪分类器。输出连续的情绪强度分数，而非离散标签。

**预期效果**：

*   支持6种基础情绪 + 中性 + 强度分数（0-1）

*   模型体积 < 100MB，可打包进安装包

*   完全本地推理，CPU可用

### 4.4 长期（战略储备）：分层情绪映射体系

**目标**：实现从“标签化的朗读”到“情感化的表演”的跨越。

详见第五章节。

## 五、分层情绪映射体系 — TTS长线演进设计

### 5.1 设计动机

现有6种基础情绪标签可覆盖约60%的常见对话场景，但无法表达复杂情绪：癫狂、傲慢、慵懒、讥讽等。这些情绪无法通过“增加更多标签”来有效解决——因为数量会膨胀到不可维护。正确的路径是：**用少量基础标签的组合 + 强度参数来模拟复杂情绪**。

### 5.2 三层架构

#### 第一层：细化核心标签库

将现有5个标签扩充至**15个左右**的关键情感锚点，覆盖80%的常见小说场景。

| 我们的标签 | 业界方案 | 代码参数参考 (SSML / 音素) |

| :--- | :--- | :--- |

| `joy` | **兴奋 (excited)**、**欢快 (cheerful)**、温柔 (tender) | `rate="fast"`, `pitch="high"` |

| `sadness` | **悲伤 (sad)**、**忧郁 (melancholy)**、绝望 (desperate) | `rate="slow"`, `pitch="low"` |

| `anger` | **愤怒 (angry)**、**严厉 (strict)**、抱怨 (complaining) | `rate="medium"`, `pitch="high"`, `volume="loud"` |

| `surprise` | **惊讶 (surprised)**、好奇 (curious) | `pitch="high"`, `volume="medium"` |

| `fear` | **恐惧 (fearful)**、**紧张 (nervous)**、焦虑 (anxious) | `rate="fast"`, `pitch="high"`, `volume="low"` |

| `disgust`(缺失) | **厌恶 (disgusted)**、轻蔑 (contemptuous) | `rate="slow"`, `pitch="medium"` |

| `neutral` | **平静 (calm)**、沉稳 (serious) | `rate="medium"`, `pitch="medium"` |

同时，为每个基础标签设置**3个强度层级**，解决“强度不可控”问题：

| 强度 | 语速调节 | 音高调节 | 音量调节 |

|------|---------|---------|---------|

| mild | ±5% | ±3% | ±5% |

| moderate | ±15% | ±10% | ±10% |

| strong | ±30% | ±20% | ±15% |

例如，`joy`可细分为 `joy_mild` (欣慰)、`joy_moderate` (高兴) 和 `joy_strong` (狂喜)，通过不同参数来体现。

#### 第二层：混合情绪与参数融合

通过为对话分配**多个混合情绪标签**并分别赋予权重来模拟复杂情绪：

*   “傲慢的”：`70% contemptuous + 15% calm + 15% cheerful`

*   “癫狂的”：`90% excited + 10% angry`

TTS引擎中，分别提取各标签对应的语速、音高参数，按权重混合后生成最终语音风格。

#### 第三层：连续情感维度（战略储备）

取代所有标签，直接输出VAD三维参数。TTS引擎只接收三个连续值（愉悦度、激活度、支配度），自行映射到语音参数。

**启动条件**：混合情绪覆盖率超过30%的对话且仍不够用时启动。

### 5.3 实施优先级

| 层级 | 状态 | 适用场景 | 标注难度 |

| :--- | :--- | :--- | :--- |

| 6种基础情绪 | ✅ 已实现 | 明确情绪表达的对话 | 低 |

| 增强标签 + 3级强度 | 🔄 当前优先 | 80%的常见对话 | 低（只需多标一个强度） |

| 混合情绪 | 📋 后续迭代 | 复杂场景（傲慢、讥讽等） | 中（需标多次权重） |

| 连续情感维度 | 🗄️ 战略储备 | 情感细腻度要求极高的场景 | 高（需直接标三维参数） |
