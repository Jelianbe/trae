# 通用实体统计发现 — 专项改进方案

**版本**: V1.0
**日期**: 2026-05-02
**背景**: 确认放弃"语料库白名单"策略，转向基于统计特征的通用实体发现机制，从根本上解决《绍宋》《诡秘之主》等任意新小说的实体识别泛化问题。
**核心原则**: 纯本地、低资源、无大模型、统计为主、可解释。
**关联模块**: `nlp_basics.py`, `ContextDiversityValidator`, `EntityClusterer`

---

## 一、核心思路

**一句话总结**：让系统从每本小说自身的文本中，自动发现"哪些词可能是人名/角色"，而不是靠人事先告诉它"哪些词是人名"。

### 1.1 为什么必须这么做

*   **领域迁移困境**：不同小说的实体是完全不同的，比如：《斗破苍穹》的实体包括“药老”、“萧炎”、“云岚宗”；《绍宋》的实体则包括“赵玖”、“宗泽”、“岳飞”；《诡秘之主》的实体则是“克莱恩”、“愚者”、“值夜者”。不可能为每本小说预先准备词表。GenWebNovel语料库提供了400章玄幻和历史小说的标注数据，其研究本身就是为了解决"不同体裁之间实体分布重叠很少"的问题。
*   **统计规律的跨体裁通用性**：虽然实体本身不同，但它们在文本中的**统计行为**高度一致——真实人名倾向于出现在对话引导词附近、具有多样的右邻字、符合中文人名构词法、在多个章节中出现。这些规律换到任何小说中都不变。
*   **RICON 的启发**：学术界已经证明，中文命名实体（如LOC、ORG）存在明显的**内部构词规律**，模型可以学习到这些结构模式来提升识别准确率。对于玄幻小说中人名往往带有特定后缀（如“尊者”、“道人”、“之主”）的现象，这套思路同样适用。

### 1.2 与原有架构的关系

这不是推倒重来，而是**扩展已有统计模块的能力维度**：

| 模块 | 现有能力 | 扩展方向 |
|------|---------|---------|
| `ContextDiversityValidator` | 右邻字种类、出现频率、章节分布 | 新增构词法后缀检查、上下文边界词命中率 |
| `_enhance_entities` | 单字姓氏 + 已知称谓（“老+姓”、“姓+管家”） | 扩展为“单字姓氏 + 任意潜在称谓候选”，支持模式发现 |
| `EntityClusterer` | BGE-small语义聚类 | 新增字面特征辅助（后缀一致性、核心名一致性） |

## 二、技术路线：三个新增统计维度

### 2.1 构词法后缀自动发现

**原理**：玄幻小说中的角色名/称号往往呈现高度的构词规律性，如“X尊者”、“X道人”、“X之主”、“X皇”等后缀反复出现。RICON等研究表明，中文命名实体存在明显的内部构词规律，这些规律可以作为识别信号。系统可以通过一次全文扫描，自动发现当前小说中的高频人名后缀模式。

**发现算法**：
1.  从HanLP的NER输出和`_enhance_entities`的高置信度结果中，收集所有已确认的PER实体（出现≥5次且右邻字多样）。
2.  对这些PER实体的末端字符（单字或双字）做频率统计。
3.  将出现频率显著高于随机水平的后缀（如“尊”、“皇”、“之主”、“道人”）加入**当前小说的临时后缀白名单**，该白名单仅对当前小说生效，不写入全局配置。
4.  回扫全文：任何具有这些后缀、且出现在对话引导词附近的2-4字词，标记为候选PER实体。

**预期收益**：玄幻类小说中，像“冰皇”、“药尊者”、“虚无之主”这类由称号构成的实体，即使从未出现在任何词典中，也能被自动发现。

### 2.2 上下文边界词命中率

**原理**：真实的说话角色名字，在全文范围内会反复出现在固定的“边界模板”中。学术界构建的13类多体裁NER语料库（覆盖260部小说、13个体裁）为跨体裁的统计特征分析提供了数据基础。基于此，可提炼出通用的统计特征，这正是我们在“授人以渔”策略下识别陌生人名的核心。

**边界词模板**：
以下模板由高频姓氏和固定语言使用习惯构成，是比具体词汇更通用的统计信号：
*   引导类：`{候选词}说道/问道/喊道/笑道/淡淡道`
*   动作类：`{候选词}来到/走出/看着/点了点头`
*   所有格：`{候选词}的/之`
*   称呼类：`{候选词}师兄/师姐/前辈/大人`

**判定逻辑**：统计每个候选实体出现在这些边界词模板中的**命中次数**。如果一个候选实体在全文范围内命中 ≥ 3种不同的边界模板，且总命中次数 ≥ 5，则大幅提升其置信度。

**预期收益**：对于“药老”这种无法通过构词法发现、但在大量对话中出现的实体，边界词命中率能提供替代的统计信号。

### 2.3 多维度综合打分

**原理**：单一的统计维度可能存在盲区。将三个维度组合使用，可以互相弥补。当一个候选实体在某一维度上得分较低（如：低频出现），但在其他维度上表现良好（如：出现在对话引导词附近且具有特定构词后缀），综合得分仍可保持在较高水平，从而避免被误过滤。

**打分公式**：
```
综合置信度 = 基础置信度 × (0.3 + 0.25 × 出现频率归一化 
                            + 0.25 × 右邻字多样性归一化 
                            + 0.20 × 边界词命中率归一化)
```
（维度权重可调。对于长文本，建议提升出现频率权重；对于玄幻文本，可提升构词法后缀权重）

**等级划分**:
| 综合置信度 | 处理方式 |
|-----------|---------|
| ≥ 0.8 | 确认实体，`is_confirmed = 1` |
| 0.5 - 0.8 | 候选实体，`is_confirmed = 0`，参与匹配但不作为最终结果 |
| < 0.5 | 低置信度暂存，跨章节累积3次以上后重新评估 |

## 三、实施路径

### 3.1 改造的模块

| 模块 | 改动内容 |
|------|---------|
| `ContextDiversityValidator` | 新增三个方法：`_discover_name_suffixes()`：后缀自动发现；`_calc_boundary_hit_rate()`：边界词命中率统计；`_calculate_composite_score()`：多维度综合打分 |
| `_enhance_entities` | 将以前缀称呼为代表的确定性规则（老/小 + 姓）作为高置信锚点，与统计维度的边界词命中率、后缀模式进行分层综合判断 |
| `nlp_basics.py` | 新增 `POSTFIX_PATTERNS_CANDIDATES` 全局变量，预设跨体裁通用的高频人名后缀候选集（如`尊、皇、帝、主、者、道人、圣人、之主、尊者、大帝`），供后缀自动发现时作为先验加速 |
| `config.py` | 新增统计维度权重配置项，允许高级用户按文本类型调整 |

### 3.2 不引入的依赖
- 不引入任何新的大模型
- 不引入任何GPU推理
- 不引入任何联网查询
- 不引入任何外部语料库（语料库仅用于规则提炼，不进入运行时）

## 五、成功标准

1. **不降低现有分数**：《斗破苍穹》前10章、都市异能、西幻、修仙四份测试文本的综合得分不得低于当前基线。
2. **新小说自动发现能力**：在一本全新的玄幻/历史/都市小说上（不提供任何GT标注），系统自动发现的PER实体数量相比改造前提升 ≥ 30%。
3. **零新依赖**：改造后项目仍满足“纯本地、无GPU、无联网”的运行条件。
4. **purity_check通过**：检测脚本不报告任何新增的硬编码污染。
