# 统计误合并检测通用优化方案

**版本**: V1.0  
**日期**: 2026-05-03  
**背景**: 当前 `_detect_mis_merged_entities` 方法依赖硬编码的 `SINGLE_CHAR_VERBS`，泛化能力受限。需升级为基于统计的通用检测逻辑。  
**关联模块**: `context_diversity_validator.py`

---

## 一、修正目标

将误合并检测的核心逻辑从“硬编码后缀黑名单”替换为“统计压缩率检测”——不再判断一个字是不是动词后缀，而是判断一个长实体是否是一个已知短实体的低频、低多样性的扩展。

**核心指标**：
- 斗破苍穹 NER F1 在当前92.3的基础上不降
- 能够检测出“萧炎冷”（`萧炎 + 冷`）、“萧炎承喏”（`萧炎 + 承喏`）等任意后缀的误合并
- 零新增硬编码
- 零新增外部依赖

---

## 二、技术路线：结构压缩率检测

### 2.1 核心逻辑

```
如果：
  1. 实体A长度 ≥ 3
  2. 且实体A包含实体B（B是A的前缀，B在文本中出现 ≥ 5次，B是高频角色名）
  3. 且实体A出现的次数远小于实体B出现的次数（A的出现次数 < B的10%）
  4. 且实体A的右邻字种类 ≤ 2（说明A的上下文单一，不是独立的真实角色）

则：
  实体A是实体B的误合并扩展 → 降为置信度0.1
```

这个逻辑不依赖任何硬编码后缀——“冷”、“承喏”、“皱眉”、“嗤笑”——全部通过统计关系自动发现。

### 2.2 与旧方案对比

| 维度 | 旧方案（硬编码） | 新方案（统计压缩率） |
|------|----------------|-------------------|
| 后缀发现方式 | 人工枚举`SINGLE_CHAR_VERBS` | 自动通过前缀-实体关系 |
| 覆盖范围 | 只覆盖被枚举的后缀 | 覆盖所有可能的后缀 |
| 泛化风险 | 高（“承喏”不在集合中） | 低（全自动，无硬编码） |
| 误杀风险 | 中（“陈承喏”可能被杀） | 低（除非“陈承喏”出现次数远小于“陈”） |
| 计算成本 | 低 | 低（只在已有`stats`上做检查） |

### 3.2 实现伪代码

```python
def _detect_mis_merged_entities_v2(self, entities, stats):
    """
    基于统计的结构压缩率检测，替代硬编码后缀黑名单。
    
    核心逻辑：
    对于每个类型为PER且长度≥3的实体A，检查是否存在一个更短的实体B
    （B是A的前缀，且B是高频角色名），满足：
      - A的出现次数 < B出现次数的10%
      - A的右邻字种类 ≤ 2
    
    如果满足，则A是B的误合并扩展，标记为mis_merged。
    """
    # 找出出现≥5次的高频角色名（作为prefix候选）
    known_persons = set()
    for entity_text, stat in stats.items():
        if stat['occurrences'] >= 5:
            known_persons.add(entity_text)
    
    mis_merged = set()
    
    for entity in entities:
        if entity.type != 'PER' or len(entity.text) < 3:
            continue
        
        entity_text = entity.text
        entity_occ = stats.get(entity_text, {}).get('occurrences', 0)
        entity_diversity = len(stats.get(entity_text, {}).get('right_neighbors', set()))
        
        # 检查所有可能的prefix（去掉末端1-2字）
        for suffix_len in [1, 2]:
            if len(entity_text) <= suffix_len:
                continue
            
            prefix = entity_text[:-suffix_len]
            
            # 条件1：prefix是已知的高频角色
            if prefix not in known_persons:
                continue
            
            prefix_occ = stats[prefix]['occurrences']
            
            # 条件2：实体出现次数远少于prefix（<10%）
            if entity_occ >= prefix_occ * 0.1:
                continue
            
            # 条件3：实体的右邻字种类少（≤2）
            if entity_diversity > 2:
                continue
            
            # 满足所有条件 → 标记为误合并
            mis_merged.add(entity_text)
            
            import os
            if os.environ.get('DEBUG_MIS_MERGED'):
                suffix = entity_text[-suffix_len:]
                print(
                    f"[detect_mis_merged] {entity_text} → "
                    f"prefix='{prefix}'({prefix_occ}次) + "
                    f"suffix='{suffix}' | "
                    f"entity_occ={entity_occ}, diversity={entity_diversity}"
                )
            break
    
    return mis_merged
```

### 3.3 在`validate`方法中集成

```python
# 在 validate() 方法中，_calculate_confidence 之后
mis_merged_entities = self._detect_mis_merged_entities_v2(all_entities, stats)
for entity_text in mis_merged_entities:
    for entity in all_entities:
        if entity.text == entity_text:
            entity.confidence = 0.1  # 直接降至极低置信度
```

- 所有针对 `SINGLE_CHAR_VERBS` 的判断逻辑

## 四、验证方案

### 4.1 预期行为

| 实体 | 前缀 | 实体次数 | 前缀次数 | 比率 | 右邻字种类 | 判定 |
|------|------|---------|---------|------|-----------|------|
| 萧炎冷 | 萧炎 | 1 | 267 | 0.37% | 1 | ✅ 误合并 |
| 萧炎承 | 萧炎 | 1 | 267 | 0.37% | 1 | ✅ 误合并 |
| 陈承喏 | 陈 | 15 | 50 | 30% | 4 | ❌ 保留（比率高，多样性高） |
| 萧薰儿 | 萧薰 | 8 | 3 | 266% | 3 | ❌ 保留（实体次数 > 前缀） |

### 4.2 风险场景

| 场景 | 风险 | 缓解措施 |
|------|------|---------|
| 真实短角色名产生误判 | 如果“萧炎”出现100次，“萧炎冷”出现3次（3%），且“萧炎冷”确实是一个真实角色 | 阈值<10%已足够保守。极端情况下可通过`known_persons`白名单保护 |
| 从未出现的高频角色名被误判 | 如果“炎”不在`known_persons`中 | 只检查长度≥2的prefix，且prefix必须在`known_persons`中 |
