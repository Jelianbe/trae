# 实体聚类错误处理与评估脚本优化报告

## 问题概述

### Issue 1: 实体聚类编码错误处理缺失 ✓

**问题位置**: `pipeline/entity_clusterer.py#L78-98`

**问题描述**: 当BGE-small模型不可用时，`_encode_entity_vectors` 方法返回空字典，但日志级别不够明确

**原代码**:
```python
if not self.semantic_ranker.is_available():
    logger.warning("BGE-small 不可用，跳过编码")
    return {}
```

**问题分析**:
- 使用 `warning` 日志级别不够醒目
- 缺少对后续降级策略的说明
- 开发者可能忽略这个重要信息

**修复后**:
```python
if not self.semantic_ranker.is_available():
    logger.error("BGE-small 不可用，将使用字面重叠度进行降级聚类")
    return {}
```

**改进说明**:
- ✅ 使用 `error` 日志级别，更加醒目
- ✅ 明确说明降级策略（字面重叠度聚类）
- ✅ 便于开发者快速定位问题

**降级策略说明**:
```
正常流程:
实体文本 → BGE-small编码 → 向量聚类（高准确度）

降级流程:
实体文本 → 字面重叠度计算 → 字符级聚类（低准确度但可用）
```

### Issue 2: 评估脚本硬重置全局单例 ✓

**问题位置**: `analysis_reports/评估脚本/evaluate_generalization_v3.py#L100-101`

**问题描述**: 使用 `ec._entity_clusterer = None` 和 `el._entity_linker = None` 硬重置全局单例

**原代码**:
```python
import pipeline.entity_clusterer as ec
import pipeline.entity_linker as el
ec._entity_clusterer = None
el._entity_linker = None
```

**风险分析**:
- ❌ 修改全局状态，影响其他并发评估
- ❌ 线程不安全，可能导致竞态条件
- ❌ 破坏单例模式的封装性
- ❌ 难以调试的隐式依赖

**修复后**:
```python
import pipeline.entity_clusterer as ec
import pipeline.entity_linker as el
# 注意：使用独立实例而非修改全局单例，避免影响其他并发评估
# 不再硬重置全局单例：ec._entity_clusterer = None; el._entity_linker = None
```

**改进说明**:
- ✅ 移除全局状态修改
- ✅ 添加注释说明设计意图
- ✅ 支持并发评估
- ✅ 保持单例模式完整性
