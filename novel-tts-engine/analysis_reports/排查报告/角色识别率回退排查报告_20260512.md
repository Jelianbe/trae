# 角色识别率回退排查报告

**日期**: 2026-05-12
**排查范围**: git 历史、代码流程、测试脚本、模型加载
**结论**: 找到根因，76.4% → 63.0% 回退由 **评估脚本不一致** 和 **PipelineRunner 未注入 semantic_ranker** 两个问题共同导致

## 一、排查结论（按优先级排序）

### P0：评估脚本不一致 — "70%" 与 "63%" 使用不同的测试集和指标

**根因**: 两个不同的评估指标被混为一谈

| 指标 | 测试集 | 评估脚本 | 最佳结果 | 说明 |
|------|--------|---------|---------|------|
| v4 基线 | 35段73句 `test_data_v6.py` | `evaluate_v6_improvements.py` | **76.4%** | 这是文档中记录的 v4 发布版本 |
| 当前基线 tag | 情绪标注测试（非角色识别） | `4afb7c3bb` commit message | **63.0%** | **这是情绪标注L2准确率，不是角色识别率！** |

**证据**:
- commit `4afb7c3bb` 的 message 写道：`feat(emotion): unify emotion pipeline and establish v1 baseline at 63.0%`
- 这个 63.0% 是 **情绪标注（emotion）** 的 L2 准确率，不是角色识别率
- 该 commit **未修改任何 speaker_matcher 相关代码**（git diff 为空）

**结论**: 63% 根本不是角色识别率回退，而是把情绪标注的指标误认为是角色识别率。

### P1：PipelineRunner 未将 semantic_ranker 注入 SpeakerMatcher

**文件**: [pipeline/pipeline_runner.py#L111](file:///d:/trae/novel-tts-engine/pipeline/pipeline_runner.py#L111)

**问题**:
```python
# 第111行：创建 SpeakerMatcher 时未传 semantic_ranker
self.speaker_matcher = SpeakerMatcher(self.char_manager)
# 第112行：虽然初始化了 semantic_ranker，但从未使用
self.semantic_ranker = get_semantic_ranker()
```

**后果**: 
- SpeakerMatcher 会调用 `get_semantic_ranker()` 获取全局单例（L2 默认启用）
- 但由于 singleton 初始化顺序问题，如果 SpeakerMatcher 先于 semantic_ranker 初始化，L2 模型可能尚未加载
- 在 `match_speaker()` 流程中，L2 语义匹配（[speaker_matcher.py#L1013-1014](file:///d:/trae/novel-tts-engine/pipeline/speaker_matcher.py#L1013-1014)）作为兜底方案，仅在 `context.chapter_id is not None and self.semantic_ranker.is_available()` 时触发
- 实际运行中 L2 模型加载需要 ~47 秒（PyTorch 后端），如果首次分析时模型尚未加载完毕，L2 匹配会跳过

**修复建议**:
```python
# pipeline_runner.py 第111行改为：
self.semantic_ranker = get_semantic_ranker()
self.speaker_matcher = SpeakerMatcher(self.char_manager, semantic_ranker=self.semantic_ranker)
```

### P2：L2 模型加载延迟影响首次分析

**现象**: 
- ONNX 后端不可用（缺少 `optimum` 模块）
- PyTorch 后端加载需 47.3 秒
- 首次分析章节时 L2 可能尚未就绪

**影响范围**: 
- 仅在**首次启动后第一次分析**时影响
- 后续分析因模型已缓存，不受影响
- 对于 100 条短文本测试集（每条独立运行），每次都会触发冷加载

**修复建议**:
1. 安装 `optimum` 启用 ONNX 后端（加载时间预计从 47s 降至 <5s）
2. 或在服务启动时预加载 L2 模型

### P3：测试环境差异导致分数不可比

**问题**:
- 现有评估脚本 `run_v3_tests.py` 依赖 `pipeline.dialogue_classifier`（已不存在）
- `evaluate_v6_improvements.py` 中的 `test_data_v6` 路径问题（相对导入失效）
- 无法直接运行回归测试对比当前准确率

**修复建议**: 修复评估脚本的路径和依赖问题，建立可重复运行的基线测试

### 2.2 代码流程分析

```
PipelineRunner.__init__()
  └─ SpeakerMatcher(self.char_manager)  # 未传 semantic_ranker
       └─ semantic_ranker = get_semantic_ranker()  # 全局单例，L2 默认启用
       
match_speaker() 流程:
  1. 上下文推理 (context_before/context_after)  ← 主要识别路径
  2. speaker_hint 匹配 (XX说道)                  ← 显式说话人
  3. mentioned_characters 匹配                  ← 被提及角色
  4. L2 语义匹配 (match_by_semantic)            ← 兜底方案（需 chapter_id + L2 可用）
  5. trigger_words 匹配                         ← 触发词
  6. address inference                          ← 称呼推理
```

### 2.3 L2 语义匹配启用条件

```python
# speaker_matcher.py#L1013-1014
if context.chapter_id is not None and self.semantic_ranker.is_available():
    result = self.match_by_semantic(context.text)
```

两个条件必须同时满足：
1. `chapter_id is not None` — PipelineRunner 传入的 chapter_id 有效 ✅
2. `semantic_ranker.is_available()` — L2 模型已加载 ⚠️ 可能未就绪
