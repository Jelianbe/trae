### 2.3 pipeline_runner.py - 缓存容量限制

**问题**: `_result_cache` 无淘汰机制，长文本会内存溢出

**修复方案**: 使用 OrderedDict 实现 LRU 淘汰

**新增配置** (utils/config.py):
```python
MAX_RESULT_CACHE_SIZE = 10  # 最多缓存10本书的结果
```

**新增方法**:
```python
def _add_to_cache(self, key: str, value: List["ChapterResult"]):
    """添加结果到缓存，超过容量时淘汰最旧的"""
    if key in self._result_cache:
        del self._result_cache[key]
    self._result_cache[key] = value
    while len(self._result_cache) > MAX_RESULT_CACHE_SIZE:
        self._result_cache.popitem(last=False)
```

**影响**: 限制内存使用，防止长文本OOM

### 2.4 speaker_matcher.py - 角色提取缓存

**问题**: `_extract_descriptive_roles` O(n²)复杂度，无缓存，对话密集时性能差

**修复方案**: 
1. 将模式列表移到类变量，避免每次调用重新创建
2. 添加实例级缓存，相同文本直接返回结果

**修复后**:
```python
class SpeakerMatcher:
    ROLE_PATTERNS = [...]  # 类变量，只创建一次
    ROLE_PATTERNS_SORTED = sorted(ROLE_PATTERNS, key=len, reverse=True)
    
    def __init__(self, ...):
        self._role_extract_cache: Dict[str, List[str]] = {}  # 实例级缓存
    
    def _extract_descriptive_roles(self, text: str) -> List[str]:
        if text in self._role_extract_cache:
            return self._role_extract_cache[text]
        # ... 计算逻辑 ...
        self._role_extract_cache[text] = results
        if len(self._role_extract_cache) > 1000:  # 缓存容量限制

```

**影响**: 相同文本不重复计算，性能提升

### 2.5 context_diversity_validator.py - 正则编译优化

**问题**: `BOUNDARY_PATTERNS` 作为实例属性，每次创建实例都重新编译30个正则

**修复方案**: 移到类变量，全局只编译一次

**修复前**:
```python
class ContextDiversityValidator:
    def __init__(self, ...):
        self.BOUNDARY_PATTERNS = [...]  # 每实例编译
```

**修复后**:
```python
class ContextDiversityValidator:
    BOUNDARY_PATTERNS = [...]  # 类变量，全局编译一次
    POSTFIX_PATTERNS_CANDIDATES = [...]  # 同上
    
    def __init__(self, ...):
        # 不再编译正则
```

**影响**: 减少实例创建开销，正则只编译一次
