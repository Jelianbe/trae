### 3.1 连接池实现
**问题**: 每次数据库操作都创建新连接，性能低下

**修复**:
```python
@contextmanager
def _get_connection(self):
    conn = getattr(self._local, 'connection', None)
    created = False
    
    if conn is None:
        conn = sqlite3.connect(self.db_path, timeout=30.0)
        conn.execute("PRAGMA journal_mode=WAL")
        conn.execute("PRAGMA foreign_keys = ON")
        self._local.connection = conn
        created = True
    
    try:
        yield conn
    except Exception as e:
        if conn:
            conn.rollback()
            logger.error(f"数据库操作失败: {e}", exc_info=True)
        raise
    finally:
        if created:
            conn.close()
            self._local.connection = None
```

### 3.2 事务完整性
**问题**: `merge_characters` 方法中多步操作缺乏原子性保证

**修复**: 添加事务上下文管理器
```python
@contextmanager
def _transaction(self):
    with self._get_connection() as conn:
        try:
            yield conn
            conn.commit()
        except Exception as e:
            conn.rollback()
            logger.error(f"事务执行失败，已回滚: {e}", exc_info=True)
            raise
```

### 3.3 线程安全
**问题**: 使用 `check_same_thread=False` 存在安全风险

**修复**:
- 使用 `threading.local()` 实现线程隔离
- 添加 `timeout=30.0` 处理锁竞争
- 移除 `check_same_thread=False` 配置

## 四、SQL 注入漏洞修复

### 改动时间
2026-05-01

### 改动文件
- `pipeline/character_manager.py`

### 4.1 LIKE 查询参数化
**问题**: LIKE 查询使用字符串拼接，存在 SQL 注入风险

**修复前**:
```python
cursor.execute(f"SELECT * FROM characters WHERE name LIKE '%{name}%'")
```

**修复后**:
```python
escaped_name = self._escape_like_pattern(name)
cursor.execute(
    "SELECT * FROM characters WHERE name LIKE ? ESCAPE '\\'",
    (f'%{escaped_name}%',)
)
```

### 4.2 特殊字符转义
**问题**: LIKE 模式中的 `%`, `_`, `\` 未正确转义

**修复**:
```python
def _escape_like_pattern(self, pattern: str) -> str:
    # 必须先转义反斜杠本身，然后再转义其他特殊字符
    return pattern.replace('\\', r'\\').replace('%', r'\%').replace('_', r'\_')
```

### 4.3 动态 SQL 拼接修复
**问题**: 多处使用字符串拼接构建 SQL

**修复**: 全部改为参数化查询，使用 `?` 占位符
