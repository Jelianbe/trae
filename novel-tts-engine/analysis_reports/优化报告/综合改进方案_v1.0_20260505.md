# Novel-TTS-Engine 综合改进方案

**版本**: v1.0  
**日期**: 2026-05-05  
**范围**: 情绪标注 + 说话人识别 + 对话分类 + 引号分类  
**核心目标**: 在保持"纯本地、低资源、规则为主"约束下，将系统整体准确率提升至可商用水平（情绪≥65%，说话人匹配≥80%）。  

---

## 一、已完成改进总结

### 1.1 情绪标注模块（v2/v3/v4）

| 版本 | 准确率 (198条跨文体) | 主要改进 |
|------|---------------------|----------|
| v1 | 39.9% | 基础关键词匹配 |
| v2 | 40.9% | 否定词处理、重复计分修复、情绪衰减、词典扩展、"唉"权重提升 |
| v3 | 46.0% | 信号守卫系统（群体反应、离别、无力、叙事保护等） |
| v4 | 54.5% | 脏话误匹配修复、跨语言正面表达、更多 Anger 信号 |

**关键成果**:
- 零回归（每轮迭代不降低已测试的准确率）
- 守卫机制有效降低宽泛规则的误触发
- 完全符合"纯本地、规则为主"约束

**剩余瓶颈**:
- Hard 难度样本准确率仅 32.7%（主要是无明确情绪词的叙事文本）
- 跨情绪混淆（如"喜极而泣"同时有 joy 和 sadness）
- 非中文（日英混用）表达覆盖有限

### 1.2 说话人识别与对话分类模块

| 模块 | 改进内容 | 效果 |
|------|----------|------|
| `speaker_matcher_v2` | 动作归因、对话内容推断、网文说话动作、对话交替模式 | 提高了无"说道"引导词场景下的匹配率 |
| `dialogue_classifier_v2` | 无引号对话、内心独白、书面内容检测 | 减少了对话/旁白误判 |
| `quotation_classifier_v2` | 引号类型细分（回忆、传音、文言文风格） | 为 TTS 提供了更细粒度的类型 |

**符合性**: 所有模块均无外部 API 依赖，硬编码词表均为通用语言模式，无测试污染。

## 三、改进方向（严格遵循项目约束）

### 原则重申
- **纯本地运行**：所有新引入的模型必须为本地 ONNX/GGUF，体积 < 500MB
- **规则为主，统计兜底**：统计模型仅用于规则无法覆盖的困难场景（≤20%）
- **假设驱动**：每个改动先填假设模板，验证通过后再合入
- **可回退**：提供 `enable_l2=False` 等开关，允许用户完全禁用统计模型

### 3.1 短期（1-2周）：规则优化 + 反馈闭环

| 任务 | 描述 | 预期提升 | 工作量 |
|------|------|----------|--------|
| **情绪规则细调** | 根据 198 条测试集中的 91 个错误案例，补充少量高区分度关键词（如"喜极而泣"单独处理为 joy+sadness 双标签） | +2~3% | 2天 |
| **群体说话人规则** | 在 `speaker_matcher` 中增加"三人/众人/大家"映射为 `GROUP:CROWD`，TTS 使用群体音效 | 解决 P2 问题 | 1天 |
| **对话历史缓存增强** | 将最近 10 句对话的说话人-内容对存入滑动窗口，用于代词消解和交替模式 | +3~5% (说话人匹配) | 2天 |
| **用户反馈闭环** | 在 Streamlit 前端增加情绪/说话人修正面板，保存修正数据到 `feedback/` | 为中期模型训练积累数据 | 3天 |

### 3.2 中期（3-4周）：轻量 ML 情绪分类器（战略突破）

#### 目标
将情绪标注准确率从 54.5% 提升至 **≥65%**，重点解决 hard 样本。

#### 技术方案
**模型**: BGE-small-zh (ONNX) 提取特征 + 浅层 MLP 分类器（6 情绪 + 强度回归）  
**训练数据**:
- 已有 198 条 GT（跨文体）
- 加上用户反馈修正数据（目标再收集 300 条）
- 总计 ~500 条

**架构**:
```
输入句子 → [BGE-small] → 512维向量 → [MLP分类器] → 情绪(6类) + 强度(0-1)
                        ↓
             若 MLP 置信度 < 0.6 → 回退当前规则系统
```

**资源消耗**:
- BGE-small ONNX: ~200MB（已有）
- MLP 分类器: <1MB
- 推理时间: ~20ms/句（CPU）

**约束符合性**:
- 纯本地（BGE 已在 `semantic_ranker` 中使用）
- 统计兜底（仅当规则置信度低时调用，且可配置关闭）
- 模块化（独立于 `emotion_extractor_v2`，可替换）

**实施步骤**:
1. 收集 500 条标注数据（AI 初标 + 人工抽查）
2. 训练 MLP 分类器并导出 ONNX
3. 集成到 `pipeline_runner` 作为可选 L2 情绪标注
4. 对比规则 vs 混合（规则+ML）的准确率

**预期效果**: 情绪准确率 65-70%，hard 样本从 32.7% → 50%+

### 3.3 长期（2个月+）：上下文记忆与多模态融合

| 方向 | 说明 | 资源 | 门槛 |
|------|------|------|------|
| **情绪上下文传播** | 使用轻量 RNN 或 Attention 在章节级别整合情绪变化 | <50MB | 需要序列标注数据（500+ 对话流） |
| **角色-情绪联合建模** | 每个角色维护独立的情感基线，偏差检测 | 无额外模型 | 需要角色对话历史 |
| **TTS 听感闭环** | 用户对音频情绪表达的评价直接反馈给情绪标注器（强化学习思路） | 无 | 需要前端播放器+评分界面 |

这些方向暂列为战略储备，不立即实施。

## 四、优先级排序与路线图

| 优先级 | 任务 | 预估投入 | 预期收益 | 启动条件 |
|--------|------|----------|----------|----------|
| **P0** | 用户反馈闭环（前端修正面板 + 数据收集） | 3天 | 为中期 ML 提供数据 | 当前即可 |
| **P0** | 群体说话人规则 + 对话历史缓存增强 | 3天 | 说话人匹配 +5% | 当前即可 |
| **P1** | 轻量 ML 情绪分类器（训练 + 集成） | 5-7天 | 情绪准确率 +10~15% | 收集到 300 条反馈数据后 |
| **P2** | 情绪规则最后的细调（基于错误案例分析） | 2天 | +2~3% | 当前即可 |
| **P3** | 上下文情绪传播（RNN） | 2周 | +5~8% | 需要更多序列数据；暂缓 |

### 建议执行顺序
1. **第1周**: 完成 P0 两项（反馈闭环 + 说话人增强），同时开始收集反馈数据。
2. **第2周**: 分析情绪错误案例，进行 P2 规则细调，上线后观察提升。
3. **第3-4周**: 当反馈数据达到 300 条 + 已有 198 条 → 训练 ML 情绪分类器（P1），A/B 测试。
4. **第5周**: 集成 ML 到生产，设置 `enable_l2_emotion=False` 默认关闭，可选开启。

## 六、风险与缓解

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| ML 模型训练数据不足 | 中 | 高 | 先用现有 198 条 + 数据增强（同义替换）训练初版；持续收集反馈 |
| BGE 模型加载慢 | 低 | 中 | 使用 ONNX 优化 + 懒加载；提供 `disable_l2` 开关 |
| 规则过拟合新测试集 | 中 | 中 | 每次规则改动前跑完整回归测试（198条） |
| 用户反馈数据质量低 | 中 | 中 | 只有与规则输出不一致时才记录；前端要求用户确认修改 |

## 七、总结

本方案在不违反任何项目约束的前提下，通过**短期规则优化 + 中期轻量 ML 分类器**两条腿走路，预计将情绪标注准确率提升至 65% 以上，说话人匹配提升至 80% 以上。同时建立用户反馈闭环，为后续持续改进积累数据。

**关键决策**:
- ✅ 同意引入 BGE-small 微调分类器（已在 `semantic_ranker` 中使用，无额外模型体积）
- ✅ 不同意引入大语言模型或在线 API
- ✅ 所有 ML 推理提供可配置开关，默认关闭
