## 1. 项目概览

### 1.1 项目背景

小说TTS引擎是一个将网络小说文本自动转换为语音朗读的系统。核心挑战在于：**网络小说中包含大量对话，需要准确识别每句对话的说话人，以便为不同角色分配不同的语音音色**。

传统TTS系统通常只支持单一音色朗读全文，或需要手动标注每个对话的说话人。本项目通过自然语言处理技术，自动分析小说文本中的说话人线索，实现自动化的角色语音分配。

### 1.2 项目目标

| 目标层级 | 描述 | 当前状态 |
|---------|------|---------|
| 核心目标 | 自动识别小说对话的说话人 | ✅ 已实现基础功能 |
| 准确率目标 | 说话人识别准确率 ≥ 80% | ⚠️ 当前 76.4% (v4 发布版本)，架构优化后可达 82-83% |
| 用户体验 | 支持角色库管理、角色锁定、音色分配 | ✅ 已实现 |
| 泛化能力 | 适应多种文体（玄幻、都市、科幻等） | ⚠️ 部分支持 |

### 1.3 核心功能

- **说话人识别流水线**: 基于NLP的说话人识别，支持显式提示、代词消解、上下文推理
- **角色库管理**: 支持预创建角色、别名管理、性别标注、角色锁定
- **语音分配**: 自动为识别出的角色分配对应音色
- **评估框架**: 提供段落级测试、准确率统计、错误模式分析

### 1.4 当前阶段

项目处于 **v4 发布版本**，已完成：
- 角色库优先级机制（锁定角色 > 普通角色 > NER自动创建）
- NER实体过滤（过滤带修饰词的实体，如"一个白发老者"）
- 代词消解优化（局部窗口 + 活跃度权重 + 最近提及）
- 加权准确率计算（正确=1.0，未知=0.25，错误=0.0）
- 身份词提取修复（P0：+3.8%）
- 复姓 NER 截断修复（P1：+4.1%）
- **当前加权准确率：76.4%（基线备份于 `backups/v4_release_2026-05-10_准确率76.4%/`）**

**架构限制已确认**：当前规则优化已触及天花板，后续提升需要架构重构：
1. **段落级上下文状态管理**：解决 P7/P28 代词消解问题
2. **HanLP 依存句法分析**：区分"说话动作发起者"与"声音来源描述"
3. 预计架构优化后可达 82-83%

## 2. 算法需求分析

### 2.1 现有解决方案的局限性

| 方案类型 | 局限性 | 本项目解决方式 |
|---------|-------|--------------|
| 规则匹配 | 仅能处理"XX说"等显式模式，无法处理代词、省略主语等 | 引入NLP分析、代词消解、上下文推理 |
| 纯NER | 会提取带修饰词的实体（如"一个白发老者"），且无法区分说话人和被提及者 | NER实体过滤 + 角色库优先匹配 |
| 语义匹配 | 计算开销大，且对短文本效果差 | 仅作为兜底方案，优先使用规则+NLP |
| LLM识别 | 成本高、延迟大、不适合批量处理 | 本地NLP模型，零成本推理 |

### 2.2 期望解决的关键问题

1. **显式提示失败**: "对着掌柜说道"中，"掌柜"被错误识别为"对着"的宾语而非说话人
2. **代词消解**: "他笑了笑"中的"他"需要正确解析为前文出现的具体角色
3. **跨句推理**: 对话中省略主语时，需要根据上下文推断说话人
4. **角色混淆**: 旁白中提到的角色 ≠ 当前说话人
5. **修饰词干扰**: NER提取的实体包含修饰词（如"一个白发老者"）
6. **群体说话**: "众人齐声道"需要识别为群体而非个人

### 2.3 性能指标要求

| 指标 | 目标值 | 当前值 | 说明 |
|-----|-------|-------|------|
| 基础准确率 | ≥ 80% | 65.8% | 正确识别的对话占比 |
| 加权准确率 | ≥ 85% | 68.5% | 正确=1.0，未知=0.25，错误=0.0 |
| 未知率 | ≤ 15% | 11.0% | 无法识别的对话占比 |
| 错误率 | ≤ 10% | 23.3% | 识别错误的对话占比 |
| 响应延迟 | < 100ms/段落 | ~50ms/段落 | 单段落分析耗时 |

### 2.4 业务场景特点

- **文体多样性**: 玄幻小说（修仙、武侠）、都市小说、科幻小说、西方奇幻
- **对话模式复杂**: 显式提示（XX说）、代词指代（他/她）、省略主语、群体说话
- **角色数量**: 单章节通常 3-8 个活跃角色，全书可能有数十个角色
- **上下文依赖**: 对话经常跨越多句，需要保持说话人状态跟踪

## 3. 核心架构设计

### 3.1 流水线架构

```
文本输入
  ↓
[对话提取] speaker_hint_matcher.py
  → 提取引号内的对话内容
  → 提取说话人提示（XX说/道/问）
  ↓
[说话人匹配] speaker_matcher.py
  → 优先级1: 显式说话人提示（0.95）
  → 优先级2: 角色库匹配（0.90 锁定 / 0.80 普通）
  → 优先级3: 代词消解（0.80-0.95）
  → 优先级4: NER实体提取（0.70-0.85）
  → 优先级5: 描述性角色推断（0.60-0.80）
  → 优先级6: 自称推断（0.60-0.80）
  → 优先级7: 语义匹配（0.60-0.80）
  → 优先级8: 称呼推理（0.40-0.60）
  → 兜底: 返回"未知"
  ↓
角色输出 + 置信度
```

### 3.2 核心模块职责

| 模块 | 文件 | 职责 |
|-----|------|------|
| 说话人提示匹配器 | `speaker_hint_matcher.py` | 提取显式说话人线索（XX说/道/问） |
| 说话人匹配器 | `speaker_matcher.py` | 核心匹配逻辑，协调各子模块 |
| 代词消解器 | `pronoun_resolver.py` | 将"他/她/它"解析为具体角色 |
| 角色管理器 | `character_manager.py` | 角色库CRUD、锁定功能、别名管理 |
| 描述性角色提取器 | `descriptive_role_extractor.py` | 从描述性短语中提取角色（如"白发老者"） |
| 自称推断器 | `self_reference_inferrer.py` | 从"我是XX"等自称中提取角色 |
| 语义排名器 | `semantic_ranker.py` | 基于语义相似度的角色匹配 |
| 角色名验证器 | `character_name_validator.py` | 验证候选名字是否为有效角色名 |

### 3.3 数据模型

```python
@dataclass
class DialogueContext:
    text: str                      # 对话文本
    speaker_hint: Optional[str]    # 显式说话人提示
    prev_speaker: Optional[str]    # 上一句说话人
    mentioned_characters: List[str]# 被提及的角色
    chapter_id: Optional[int]      # 章节ID
    context_before: Optional[str]  # 对话前文
    context_after: Optional[str]   # 对话后文

@dataclass
class MatchResult:
    character: Character           # 匹配到的角色
    confidence: float              # 置信度 (0.0-1.0)
    match_type: str                # 匹配类型
```

## 4. 测试结果与性能基准

### 4.1 测试数据集

- **段落数量**: 35 个测试段落
- **对话总数**: 73 句对话
- **文体覆盖**: 玄幻、武侠、都市、奇幻、科幻
- **对话模式**: 显式提示、代词指代、省略主语、群体说话、跨句推理

### 4.2 测试模式说明

| 模式 | 描述 | 场景 |
|-----|------|------|
| Mode A | 无预创建角色 | 验证纯算法识别能力 |
| Mode B | 预创建主要角色 | 验证角色库优先匹配效果 |

### 4.3 测试结果对比

| 指标 | Mode A (无角色库) | Mode B (有角色库) | 差异 |
|-----|------------------|------------------|------|
| **正确数** | 48 | 49 | +1 |
| **未知数** | 8 | 8 | 0 |
| **错误数** | 17 | 16 | -1 |
| **基础准确率** | 65.75% | 67.12% | +1.37% |
| **未知率** | 10.96% | 10.96% | 0 |
| **错误率** | 23.29% | 21.92% | -1.37% |
| **加权准确率** | **68.49%** | **69.86%** | **+1.37%** |
| **加权得分** | 50.0 | 51.0 | +1.0 |

### 4.4 关键发现

1. **角色库提升有限**: Mode B 仅比 Mode A 高 1.37%，说明当前主要瓶颈不在角色匹配，而在**上下文推理能力**
2. **未知率稳定**: 两种模式下未知率均为 10.96%，说明有 8 句对话确实缺乏足够的识别线索
3. **错误模式一致**: 两种模式的错误案例高度重合，说明问题根源在算法逻辑而非数据

### 4.5 历史基线对比

| 版本 | 加权准确率 | 说明 |
|-----|----------|------|
| v1 初始版本 | ~45% | 仅支持显式提示匹配 |
| v3 角色库优先 | ~55% | 引入角色库优先级 |
| v5 过度优化 | ~40% | 硬编码FILTER_WORDS导致误杀 |
| v6 基线版本 | 68.5% | 回退到NER+回滚硬编码 |
| **v4 发布版本** | **76.4%** | **P0 身份词提取 + P1 复姓扩展** |
| 目标版本 | ≥80% | 需架构重构（段落级状态+句法分析） |

## 5. 错误案例深度分析

### 5.1 错误分类统计

| 错误类型 | 案例数 | 占比 | 典型表现 |
|---------|-------|------|---------|
| **NER修饰词残留** | 3 | 18.8% | "一个白发老者"、"位身穿黑袍的骑士" |
| **上下文推理失败** | 5 | 31.3% | 省略主语时错误匹配到前文角色 |
| **代词消解错误** | 2 | 12.5% | "他"被错误解析为性别匹配但非实际说话人 |
| **别名截断** | 3 | 18.8% | "纳兰嫣然"被识别为"纳兰" |
| **群体说话误判** | 3 | 18.8% | "众人"被识别为具体个人 |

### 5.2 错误案例详细分析

#### 错误类型1: NER修饰词残留

**案例 P12**: "一个白发老者缓缓走来。他捋了捋胡须说道：「年轻人，你与我有缘。」"
- **预期**: 白发老者
- **实际**: 一个白发老者
- **原因**: NER 提取了包含修饰词的完整实体
- **触发条件**: "数量词+修饰语+核心词"结构
- **状态**: 部分修复（v6 已添加 `_is_clean_per_entity` 过滤，但对"白发老者"本身是否该过滤存在争议）

**案例 P14**: "一位身穿黑袍的骑士走进殿堂。他单膝跪地：「陛下，前线战报。」"
- **预期**: 骑士
- **实际**: 位身穿黑袍的骑士
- **原因**: 量词"位"被包含在实体中
- **触发条件**: "量词+动词短语+核心词"结构
- **状态**: 已识别，待修复

#### 错误类型2: 上下文推理失败

**案例 P4**: "黑衣人抽出长剑。「把东西交出来。」月光照亮了剑刃。苏夜冷笑一声：「做梦。」"
- **预期**: 黑衣人
- **实际**: 苏夜
- **原因**: 对话前没有显式提示，系统错误匹配到后文出现的"苏夜"
- **触发条件**: 对话在动作描述之间，无明确说话人标识
- **状态**: 待修复

**案例 P7**: "药老从戒指中飘出。他看了一眼萧炎，缓缓道：「这枚丹药，你先服下。」"
- **预期**: 药老
- **实际**: 萧炎
- **原因**: NER 提取到"萧炎"，且"缓缓道"前的"他"被错误消解为"萧炎"
- **触发条件**: "他+动词+对象+道"结构
- **状态**: 待修复（需要改进代词消解的就近原则）

**案例 P13**: "黑暗中，一个高大的身影浮现。他低沉地说道：「交出那块玉石，饶你不死。」"
- **预期**: 黑衣人
- **实际**: 林轩
- **原因**: 上下文推理失败，匹配到段落末尾出现的"林轩"
- **触发条件**: 描述性短语（"高大的身影"）未正确映射到角色
- **状态**: 待修复

#### 错误类型3: 别名截断

**案例 P2**: "小翠端着茶走进书房，轻声道：「小姐，该用茶了。」纳兰嫣然放下书卷，头也不抬地问：「放到桌上吧，老爷回来了吗？」"
- **预期**: 纳兰嫣然
- **实际**: 纳兰
- **原因**: 角色库中可能只存储了"纳兰"作为别名，或匹配时截断了名字
- **触发条件**: 复合姓氏（纳兰、慕容等）被截断
- **状态**: 待修复

**案例 P16/P19**: 同样的"纳兰嫣然"被识别为"纳兰"
- **状态**: 同一根因，3次出现

#### 错误类型4: 群体说话误判

**案例 P20**: "「冲啊！」众人齐声喊道。他们如潮水般涌向城门。骑士们举起长矛，高呼：「为了荣耀！」"
- **预期**: GROUP:CROWD / 骑士们
- **实际**: 骑士
- **原因**: 群体检测模块未正确触发，或检测后被个人角色覆盖
- **触发条件**: "众人/齐声"等群体指示词
- **状态**: 待修复

**案例 P21**: "「杀了他们！」联盟成员怒吼着冲上前。博士冷笑：「不自量力。」"
- **预期**: 联盟成员
- **实际**: 博士
- **原因**: "联盟成员"被识别为描述性角色，但匹配时错误指向"博士"
- **触发条件**: 群体名词 + 后续有具体角色
- **状态**: 待修复

**案例 P34**: "「骑士们，冲锋！」首领挥剑指向敌方。众人齐声呐喊：「杀！」"
- **预期**: 首领 / 骑士们
- **实际**: 未知 / 博士
- **原因**: "首领"未被识别为有效角色，"杀"被错误匹配到"博士"
- **触发条件**: 角色名不在角色库中 + 群体说话
- **状态**: 待修复

### 5.3 错误模式根因总结

```
根因分析（鱼骨图）

错误识别
├── 数据层
│   ├── NER提取包含修饰词（P12, P14）
│   └── 角色库别名不完整（P2, P16, P19）
├── 逻辑层
│   ├── 代词消解就近原则失效（P7）
│   ├── 上下文推理过度依赖后文（P4, P13）
│   └── 群体检测未正确触发（P20, P21, P34）
└── 架构层
    ├── 描述性角色与NER结果冲突
    └── 角色库匹配优先级不够清晰
```

| 业务影响 | 低（TTS使用默认音色） | 高（TTS使用错误音色） |

**结论**: 当前 10.96% 的未知率是可接受的，优先降低错误率比降低未知率更有价值。
