## 三、核心问题诊断

### 问题1：DIALOGUE_PATTERNS 过度匹配

当前模式将以下内容误认为对话：
- 内心独白标记（`"命运"`、`"壮年"`）
- 地点名称引用（`"幽石林"`、`"火鸦涧"`、`"地火苔"`）
- 策略描述（`"求稳"`）
- 拟声词（`"嗤！"`、`"滋滋"`）
- 物品名称（`"蚀骨甲虫"`）

**建议**: 在 DIALOGUE_PATTERNS 中添加排除规则，或在对话后处理中过滤非人声内容。

### 问题2：NER 将 ORG/LOC 误识别为 PER

`"林家"`、`"张家"` 等家族名被 HanLP NER 标记为 PER 实体，因为网文语境中家族名常被当作人名使用。

**影响**: 对话3、4、6 错误

**建议**: 在 EntityCleaner 中添加家族名黑名单过滤。

### 问题3：说话动词列表不完整

当前说话动词列表包含 `道、说道、问、答道` 等，但缺少：
- `压低声音`
- `厉声喝道`
- `传音`
- `传递出来`
- `传入脑海`

**影响**: 对话7、24、26、27 错误

**建议**: 扩展说话动词列表，增加"意念传递"相关模式。

### 问题4：角色库不完整

修仙传中缺少以下角色：
- 祭坛存在/神秘大能
- 林家管事（只有"管事"）

**影响**: 4个对话错误（都是祭坛存在的台词）

**建议**: 对话识别前应自动从上下文中提取可能的角色名并创建临时角色。

## 四、代码分析

### 4.1 实体清洗链路

```
原始 NER → entity_cleaner.clean() → _extract_context_speakers() → 最终候选人
                ↓
    expand_surname → expand_single_char → trim_overextended → is_clean_per
```

**问题**: `expand_single_char` 可能将单字 ORG（如"林"）扩展为 "林家"，产生错误实体。

### 4.2 角色库匹配逻辑

```
角色库遍历 → 在上下文中搜索角色名 → 应用规则：
    1. 声音指示 (的声音/传音)
    2. 说话动词 (道/说道/问)
    3. 冒号主语 (角色名：)
    4. 动作暗示 (句首+动作)
```

**问题**: 规则列表不够全面，缺少"意念传递"、"厉声喝道"等网文特有模式。

### 4.3 被动动作主体过滤

```
passive_patterns = [
    'X点[头首]', 'X照做', 'X点头', 'X回应', 'X回答', 'X沉思', 'X喃喃'
]
```

**效果**: 正确过滤了"孙项明点点头"中的孙项明（作为被对话方）。

## 六、结论

当前系统在修仙传全文测试中表现：

- **有效对话准确率**: 55.2%（16/29）
- **包含非对话污染**: 约42%（16/38）

与测试集（74%模式B）相比，修仙传准确率显著偏低，原因包括：

1. **修仙传没有标准答案**，无法预创建完整的角色库
2. **修仙传包含大量意念对话/传音**，当前说话动词列表不覆盖
3. **修仙传有特殊命名模式**（家族名如"林家"），NER 容易误判
4. **DIALOGUE_PATTERNS 过度匹配**，将内心独白、地名引用误认为对话

**系统核心能力已验证**：在预创建角色库、标准对话格式的场景下（测试集），准确率达72.6%。修仙传的挑战更多在于文本格式和领域适配，而非说话人匹配算法本身。
