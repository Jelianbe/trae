## 1. 执行摘要

### 1.1 核心发现

| 数据集 | L2 Macro F1 | L1 准确率 | 核心问题 |
|--------|-------------|-----------|----------|
| **50条简单样本** | **0.961** | **0.980** | 情绪信号明确时系统可用 |
| 100条扩展样本 | 0.686 | 0.660 | 边界混淆区准确率大幅下降 |
| 20条泛化样本 | 0.076 | 0.250 | **系统几乎完全失效** |

### 1.2 错误类型分布（20条泛化样本）

| 错误类型 | 数量 | 占比 | 根因 |
|---------|------|------|------|
| **neutral 抢分** | 12 条 | 60% | 句号结尾+无情绪词触发 neutral 0.4 分 |
| surprise 误触发 | 3 条 | 15% | "什么"关键词过度匹配 |
| 情绪词缺失 | 5 条 | 25% | GT 情绪得分为 0，无关键词命中 |

### 1.3 关键结论

1. **neutral 重构方向正确，但当前参数仍导致抢分**：调参后 50 条 F1 从 0.940 提升到 0.961，但 20 条泛化样本仍有 60% 被 neutral 抢走
2. **规则系统在简单样本上可用，在泛化样本上几乎完全失效**：7.6% F1 说明当前架构无法处理含蓄表达
3. **"什么"关键词是过拟合补丁**：在 50 条上有效，但在泛化样本上制造了 3 条误报

## 2. neutral 重构调参过程

### 2.1 原始方案（文档三建议）

```python
neutral_score = 0.0
# 信号1：句号结尾 + 无感叹号/问号
neutral_score += 0.35
# 信号2：句子长度正常
neutral_score += 0.20
# 信号3：无情绪词命中
neutral_score += 0.25
# 信号4：日常词汇命中
neutral_score += 0.08
# 上限
neutral_score = min(neutral_score, 0.85)
```

**执行结果**：50 条 F1 从 0.940 跌到 0.602

### 2.2 第一次调参

```python
neutral_score = 0.0
# 信号1：句号结尾 + 无感叹号/问号
neutral_score += 0.2
# 信号2：无情绪词命中
neutral_score += 0.2
# 上限降到 0.5
neutral_score = min(neutral_score, 0.5)
```

**执行结果**：

| 数据集 | 调参前 F1 | 调参后 F1 | 变化 |
|--------|-----------|-----------|------|
| 50条 | 0.940 | **0.961** | +0.021 |
| 100条 | 0.680 | 0.686 | +0.006 |
| 20条泛化 | 0.069 | 0.076 | +0.007 |

### 2.3 调参结论

- **50 条略有提升**：说明调参方向正确
- **100 条和 20 条几乎无变化**：说明问题不在 neutral 参数，而在规则架构本身
- **neutral 仍抢走 60% 的泛化样本**：因为这些样本 GT 情绪得分为 0，neutral 0.4 > 0

### 3.2 surprise 误触发（3 条）

这些样本被 "什么" 关键词误触发为 surprise：

| ID | 文本 | GT | 预测 | 根因分析 |
|----|------|-----|------|----------|
| gen_010 | 为什么偏偏是你…… | subdued/sadness | excited/surprise | "为什么"触发 surprise 0.4 |
| gen_015 | 你不欠我什么。 | subdued/sadness | excited/surprise | "什么"触发 surprise 0.4 |
| gen_018 | 这算什么。 | excited/joy | excited/surprise | "什么"触发 surprise 0.4 |

**根因**：surprise 规则中的 `re.search(r'(怎么|居然|竟然|天哪|什[么幺]|竟然复活)', text)` 过度匹配。"什么"在中文中是常用词，不应作为 surprise 的强信号。

## 5. 改进方案

### 5.1 短期修复（可立即执行）

**修复 1：删除 "什么" 补丁关键词**

```python
# surprise 规则修改
# 原规则
if re.search(r'(怎么|居然|竟然|天哪|什[么幺]|竟然复活)', text):
    scores['surprise'] += 0.4

# 修改后
if re.search(r'(怎么|居然|竟然|天哪|竟然复活)', text):
    scores['surprise'] += 0.4
```

**修复 2：添加新关键词**

```python
# sadness 新增
if re.search(r'(也罢|何尝|失陪|值得吗)', text):
    scores['sadness'] += 0.3

# anger 新增
if re.search(r'(自己扛|当真以为|拦我|到此为止)', text):
    scores['anger'] += 0.3

# joy 新增（战斗场景）
if re.search(r'(再来|慢了)', text):
    scores['joy'] += 0.3

# fear 新增
if re.search(r'(别回头)', text):
    scores['fear'] += 0.3
```

### 5.2 中期优化（需要架构调整）

**问题**：当前规则系统只看单句，无法处理"月亮真圆"在离别场景=悲伤这类上下文依赖。

**方案**：引入对话上下文特征

```python
# 伪代码
class EmotionExtractorV2:
    def classify_with_context(self, text: str, prev_emotions: List[str]) -> EmotionResult:
        # 如果前文是悲伤/离别，"月亮真圆"更可能是悲伤
        if '月亮' in text and 'sadness' in prev_emotions:
            scores['sadness'] += 0.3
        
        # 如果前文是战斗，"再来"更可能是兴奋
        if '再来' in text and 'anger' in prev_emotions:
            scores['joy'] += 0.3
```
