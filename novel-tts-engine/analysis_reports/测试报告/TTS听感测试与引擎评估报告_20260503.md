## 二、发现的核心问题

### 问题 1：旁白与对话未区分声线 ❌

**现象**: 旁白文本和对话文本使用同一个声音，听起来像是同一个人在自言自语。

**原因分析**:
- 当前 `tts_generator.py` 对所有文本统一使用角色声音
- 旁白（无说话人标识的叙述性文本）不应带入角色情绪
- 正常有声书应该是：旁白用中性旁白声线，对话用角色声线

**修复方案**:
```
文本类型判断逻辑：
├── 旁白文本 → 使用 narrator 声音（中性、无情绪参数）
└── 对话文本 → 使用角色声音 + 情绪参数
```

### 问题 2：情绪表达仅靠语速变化 ❌

**现象**: 愤怒、恐惧、惊讶等情绪只是单纯加快语速，没有语调起伏、重音变化等情感表现。

**原因分析**:
- Edge-TTS 的 `rate`/`pitch`/`volume` 参数是简单的信号处理
- 真正的 TTS 情绪表达需要在声学模型层面实现（基频曲线、能量分布、音素时长）
- Edge-TTS 本质上是"带参数的朗读器"，不是"情感驱动的表演者"

**用户原话**:
> "你几乎只是单纯的加快语速，没有任何其他的改动，听起来怎么可能自然呢？"

### 问题 3：角色声线区分度不足 ❌

**现象**: 不同角色的声音听起来几乎一样，缺乏辨识度。

**原因分析**:
- Edge-TTS 只有两个男声（Yunxi/Yunyang）和两个女声（Xiaoxiao/Xiaoyi）
- 角色多时会重复使用相同声线
- 有声书需要至少 4-6 个不同声线才能区分主要角色

### 问题 4：Edge-TTS 音色质量一般 ⚠️

**现象**: 内置声线听起来机械感强，缺乏自然感。

**结论**: Edge-TTS 适合简单朗读场景，不适合有声书制作。

## 三、TTS 引擎替代方案评估

根据搜索结果，以下是可替代 Edge-TTS 的引擎对比：

| 引擎 | 中文支持 | 离线 | GPU 需求 | 声线数量 | 模型大小 | 情绪支持 | 推荐度 |
|------|---------|------|---------|---------|---------|---------|--------|
| **Kokoro** | ✅ 优秀 | ✅ | ❌ CPU 即可 | 100+ 中文音色 | ~82MB | ⚠️ 有限 | ⭐⭐⭐⭐⭐ |
| **Piper** | ⚠️ 基础 | ✅ | ❌ CPU 即可 | 2-3 个中文 | 50-100MB/声线 | ❌ 无 | ⭐⭐⭐ |
| **Coqui XTTS** | ✅ 良好 | ✅ | ⚠️ 建议 GPU | 可克隆任意声音 | ~1.5GB | ⚠️ 有限 | ⭐⭐⭐⭐ |
| **PaddleSpeech** | ✅ 优秀 | ✅ | ⚠️ 建议 GPU | 较少 | 较大 | ✅ 有 | ⭐⭐⭐⭐ |
| **Edge-TTS** | ✅ 良好 | ❌ 需要联网 | ❌ | 4 个 | 0 | ⚠️ 参数模拟 | ⭐⭐ |

### 3.1 首选推荐：Kokoro TTS

**理由**:
- 🏆 Hugging Face TTS Arena **排名第一**
- 📦 仅 82M 参数，CPU 实时推理
- 🗣️ 100+ 中文音色，可区分不同角色
- 📄 Apache-2.0 开源协议
- 🌐 支持中英混读（适合小说场景）
- ⚡ ONNX 推理，CPU 上接近实时

**安装**:
```bash
pip install kokoro
pip install ordered-set cn2an pypinyin_dict
```

**模型下载**:
```bash
# 使用镜像源
export HF_ENDPOINT=https://hf-mirror.com
huggingface-cli download --resume-download hexgrad/Kokoro-82M --local-dir ./ckpts/kokoro-v1.0
huggingface-cli download --resume-download hexgrad/Kokoro-82M-v1.1-zh --local-dir ./ckpts/kokoro-v1.1-zh
```

**使用示例**:
```python
import torch
from kokoro import KPipeline, KModel

# 加载不同音色（每个角色一个音色）
voice_male = torch.load('ckpts/kokoro-v1.1-zh/voices/zm_001.pt', weights_only=True)
voice_female = torch.load('ckpts/kokoro-v1.1-zh/voices/zf_001.pt', weights_only=True)

pipeline = KPipeline(lang_code='z')
# 旁白用中性音色
result = pipeline("萧炎缓缓站起身来，走向门口", voice=voice_male)
# 对话用对应角色音色
result = pipeline('"太好了，我终于突破了！"', voice=voice_male)
```

### 3.2 备选方案：Coqui XTTS

**优势**:
- 支持声音克隆（3秒音频即可克隆）
- 可录制真实有声书主播的声音进行克隆
- 16 语言支持

**劣势**:
- 需要 GPU（~1.5GB 显存）
- 推理速度较慢

### 3.3 轻量方案：Piper

**优势**:
- 极快（512MB 内存即可运行）
- 纯 ONNX，无 GPU 依赖

**劣势**:
- 中文声线极少（2-3个）
- 无情绪支持
- 音质一般

## 四、改进路线图

### 阶段一：解决声线区分（1-2天）

**任务**:
1. [ ] 迁移到 Kokoro TTS
2. [ ] 为旁白和对话分别配置不同音色
3. [ ] 为主要角色分配不同声线
4. [ ] 旁白文本不带情绪参数

**验收标准**:
- 旁白声音与角色声音明显不同
- 至少 3 个角色可区分

### 阶段二：优化情绪表达（3-5天）

**任务**:
1. [ ] 研究 Kokoro 的情绪/风格控制能力
2. [ ] 或集成 Coqui XTTS 的情绪表达
3. [ ] 实现旁白-对话自动切换逻辑
4. [ ] 音频合并功能（章节级 MP3）

**验收标准**:
- 愤怒/悲伤/喜悦有明显听感差异
- 情绪表达不止是语速变化

### 阶段三：离线化（2-3天）

**任务**:
1. [ ] 完全移除 Edge-TTS 依赖
2. [ ] 本地模型推理优化
3. [ ] 缓存机制（避免重复生成）

**验收标准**:
- 断网环境正常生成音频
