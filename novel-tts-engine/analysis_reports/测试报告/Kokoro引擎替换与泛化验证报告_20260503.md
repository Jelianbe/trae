### 任务 2：Kokoro 适配器实现 ✅

**文件**: `pipeline/tts_kokoro.py`  
**类名**: `KokoroTTSGenerator`  
**核心方法**:
- `initialize()` - 懒加载模型
- `load_voice(voice_id)` - 加载音色（带缓存）
- `generate_audio(text, voice_id, emotion, intensity)` - 生成音频返回 bytes
- `generate_audio_to_file(text, voice_id, output_file)` - 生成音频并保存
- `get_voice_for_speaker(speaker)` - 根据说话人名称获取音色

**角色音色映射**：
| 角色 | 音色 | 描述 |
|------|------|------|
| 旁白 | zf_001 | 中性女声（固定） |
| 萧炎 | zm_009 | 年轻男声 |
| 药老 | zm_010 | 成熟男声 |
| 苏夜 | zm_013 | 青年男声 |
| 林雪 | zf_008 | 年轻女声 |
| 赵天行 | zm_020 | 中年男声 |
| male_default | zm_012 | 默认男声 |
| female_default | zf_005 | 默认女声 |

### 任务 3：旁白/对话声线分离 ✅

**文件**: `pipeline/tts_generator.py`（重构）

**核心逻辑**：
```
句子数据
├── sentence_type == "narration"
│   └── 音色 = NARRATOR_VOICE (zf_001)
│   └── 情绪 = neutral（固定）
│   └── 强度 = mild（固定）
│
└── sentence_type == "dialogue"
    └── 音色 = 角色映射.get(speaker, male_default)
    └── 情绪 = pipeline 给出的情绪
    └── 强度 = pipeline 给出的强度
```

### 任务 4：音频合并功能 ✅

**方法**: `merge_audio_files(file_list, output_path, silence_ms=200)`

**特性**：
- 支持 ffmpeg 导出 MP3（需安装 ffmpeg）
- 自动检测 ffmpeg 可用性，不可用时回退 WAV 格式
- 音频间插入静音间隔（默认 200ms）
- 章节生成时自动合并并返回合并文件路径

**输出**：
- 6 个独立 WAV 文件（每句一个）
- 1 个合并文件（merged_chapter.wav，118KB）

### 任务 5：泛化测试 ✅

**文件**: `scripts/evaluate_emotion_on_new_novel.py`  
**测试数据**: 30 句都市异能小说对话  
**GT 标注**: `tests/modern_30_ground_truth.json`

**结果**：

| 指标 | 值 |
|------|-----|
| 准确率 | **26.7%** (8/30) |
| 目标 | ≥60% |
| joy F1 | 0.20 |
| anger F1 | 0.00 |
| surprise F1 | 0.00 |
| fear F1 | 0.40 |
| neutral F1 | 0.36 |

**结论**：泛化准确率低于目标，核心原因是规则系统依赖引导词（如"笑道""怒道"），当引导词不在引号内时失效。建议后续使用 ML 模型替代规则标注。

## 五、已知问题

| 问题 | 影响 | 解决方案 |
|------|------|---------|
| 无 ffmpeg | 无法导出 MP3，只能输出 WAV | 安装 ffmpeg 或使用其他 MP3 编码器 |
| 首句冷启动 | 首次推理 ~16s | 预热加载或后台初始化 |
| 情绪标注泛化差 | 26.7% < 60% | 使用 ML 模型替代规则 |
| emotion 参数未使用 | Kokoro 暂不支持情绪控制 | 预留接口，等待 Kokoro 后续版本支持 |
