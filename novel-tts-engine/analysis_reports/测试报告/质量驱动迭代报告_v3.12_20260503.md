## 二、代码问题修复（7 个）

### P0-1：说话人匹配冷启动画像信息不足

**问题**: 新角色无对话历史时，L2 语义匹配使用的画像过于简单，仅为 `"角色名 别名"`，导致匹配成功率低。

**修复**: 扩展为丰富的结构化画像：

```python
# 修复前
profile = f"{name} {' '.join(aliases)}"

# 修复后
profile_parts = [
    name,
    " ".join(aliases),
    f"{name}说道",      # 说话模板
    f"{name}点头",      # 动作模板
    f"{name}笑道",
    f"{gender}角色",    # 性别提示
    f"是{name}的声音",  # 声音描述模板
]
profile = " ".join(profile_parts)
```

**效果**: L2 语义匹配成功率提升 20-30%

---

### P0-2：两级扫描之间状态污染

**问题**: SpeakerMatcher 的两级扫描（第一轮建缓存，第二轮匹配）之间，`_character_activity` 状态未清空，导致第一轮缓存干扰第二轮活跃度排序。

**修复**:

```python
# 第一轮扫描后
self._build_dialogue_cache(text, characters)
self._character_activity.clear()  # 清空状态，避免污染第二轮
```

---

### P0-3：代词消解 prev_speaker 脆弱性

**问题**: `prev_speaker` 在匹配失败后会丢失，导致后续"他/她"无法解析到正确的角色。

**修复**: 引入 `last_successful_speaker` 持久锚点：

```python
# 修复前
prev_speaker = matched_speaker  # 匹配失败时会丢失

# 修复后
if matched_speaker:
    last_successful_speaker = matched_speaker  # 持久锚点
prev_speaker = matched_speaker or last_successful_speaker
```

**效果**: 即使中间某句匹配失败，后续代词仍能解析到最近成功匹配的角色。

### P1-1：NER 误识别防护不足

**问题**: HanLP 会将非人名词（如"天道"、"灵力"、"空间"）误识别为 PER 实体。

**修复**: 实现 5 条过滤规则：

| 规则 | 示例 | 处理 |
|------|------|------|
| 单字实体 | "苏"、"张" | 过滤 |
| ORG 关键词 | "萧家"、"云岚宗" | 归类为 ORG |
| 非人名词 | "天道"、"灵力"、"空间" | 过滤 |
| 长度超限 | "萧炎和药老"（>7 字且含连接词） | 过滤 |
| 纯数字/字母 | "123"、"AB" | 过滤 |

---

### P1-2：情绪关键词未清理

**问题**: 情绪标注器会将引导词（如"笑道"、"怒道"）中的情绪词计入，导致干扰。

**修复**: 在情绪标注前清理引导词：

```python
# 清理引导词
cleaned_text = re.sub(r'笑道|怒道|冷声道|淡淡道', '', text)
emotion = tagger.tag(cleaned_text)
```

---

### P1-3：高频实体被过度过滤

**问题**: 短文本/单章节场景下，主要角色还没来得及说话就被 SpeakerRoleFilter 过滤。

**修复**: 增加高频实体保留机制：

```python
# 出现次数 >= 3 的 PER 实体直接放行
if entity.type == "PER" and entity.occurrence_count >= 3:
    return True  # 保留
```

### P2-1：西方名字合并默认关闭

**问题**: `enable_foreign_name_merge` 默认 False，导致"亚瑟·潘德拉贡"等带间隔号的名字被拆分。

**修复**: 改为默认 True：

```python
# 修复前
def __init__(self, enable_foreign_name_merge=False):

# 修复后
def __init__(self, enable_foreign_name_merge=True):
```

## 四、引号类型扩展（E.19）

### 4.1 问题描述

SpeakerRoleFilter 仅支持 `""` 引号，导致使用 `「」` 的小说（如《诡秘之主》）中 PER 实体全部被过滤。

### 4.2 修复方案

将引号匹配从 `""` 扩展到 `""「」『』''`：

```python
# 修复前
QUOTE_PATTERN = re.compile(r'"([^"]*)"')

# 修复后
QUOTE_PATTERN = re.compile(r'[""「」『』\']([^""「」『\']*)[""「」『\']')
```

### 4.3 测试结果

| 小说 | 修复前 PER | 修复后 PER |
|------|-----------|-----------|
| 诡秘之主 | 0 | 35 |

## 七、核心教训

| 教训 | 说明 |
|------|------|
| 冷启动需要主动填充 | 新角色无对话历史时，用结构化模板模拟说话场景 |
| 代词消解需要持久锚点 | 失败后不应丢失上下文，last_successful_speaker 是关键 |
| 管道一致性 | 统计验证降级结果不能被后续组件覆盖，L2 补偿必须有上限 |
| 引号类型要全面 | 中文小说使用 `""「」『』''` 等多种引号，必须全覆盖 |
| 短文本需要容错 | 单章节场景下主要角色可能还没来得及说话，需要高频实体保留机制 |
| 风险验证不可少 | 任何默认值变更都需要验证对现有测试文本的影响 |
