## 第三阶段后半段实施详情（T-016~T-019）

### T-016: 实体链接模块

**文件**: `pipeline/entity_linker.py`

**核心功能**:
1. 过滤单字人名（长度 < 2 的 PER 实体）
2. 基于角色库标准名和别名匹配
3. 核心人名提取（"张总" → "张" → 匹配角色库）
4. 链接成功则置信度提升至 0.8+

**处理流程**:
```
NER 输出 → 过滤单字 PER → 角色库匹配（标准名/别名）
  → 核心人名提取 → 链接成功提升置信度 → 返回链接后列表
```

**效果**: 都市 NER 70.2% → 74.0% (+3.8)

### T-017: 角色聚类模块

**文件**: `pipeline/entity_clusterer.py`

**四步聚类法**:
1. **收集上下文**: 遍历全文，记录每个实体每次出现时的前后各 50 字符
2. **BGE-small 编码**: 为每个实体的所有上下文编码，取平均向量
3. **相似度计算**: 按出现次数从高到低排序，高频实体优先作为聚类中心
4. **写回 SQLite**: 通过 CharacterManager.merge_characters 归并

**合并条件（必须同时满足）**:
- 语义相似度 >= 0.85
- 字面字符重叠度 >= 0.3（或相似度 >= 0.95）

**短文本保护**: 候选实体 < 3 或文本 < 10000 字时跳过聚类

**效果**: 在长文本中生效，短文本中跳过不干扰

### T-018: 说话人增强

**修改文件**: `pipeline/speaker_matcher.py`

**核心改进**:
- 新增 `_build_dialogue_cache()` 方法
- 第一轮扫描全文，建立角色对话历史缓存
- 第二轮匹配时复用缓存，L2 语义画像更准确
- 重置 `_recent_speakers` 避免干扰 `prev_speaker` 追踪

**效果**: 说话人匹配保持稳定（76.2%），缓存未破坏追踪链

### T-019: 群体说话人处理

**修改文件**: `pipeline/speaker_matcher.py`

**核心改进**:
- 新增 `GROUP_SPEAKERS` 字典，映射 9 种常见群体说话人模式
- "三人" → `GROUP:3`，"众人" → `GROUP:CROWD`
- 匹配类型为 `group_speaker`，置信度 1.0

**效果**: 覆盖边缘场景，不干扰正常说话人匹配

## T-010: 流水线调度器

**文件**: `pipeline/pipeline_runner.py`

**核心架构**:

```
输入文本 → 章节划分 → NER+实体链接 → 对话分类
  → 拟声词检测 → 说话人匹配 → 情绪标注 → 输出 JSON/SSML
```

**六大步骤**:
1. **章节划分**: ChapterSplitter.split()
2. **NER + 实体链接**: NLPBasics + EntityLinker
3. **对话分类**: DialogueClassifier
4. **拟声词检测**: SfxDetector
5. **说话人匹配**: SpeakerMatcher
6. **情绪标注**: EmotionTagger（六种基础情绪规则标注）

**功能特性**:
- 暂停/恢复机制（threading.Event）
- 进度追踪（ProgressInfo，支持回调）
- 结果缓存（按 cache_key 键值存储）
- JSON/SSML 双格式导出

**导出示例（JSON）**:
```json
[
  {
    "chapter_id": 0,
    "title": "第一章 少年初醒",
    "sentences": [
      {
        "text": "少爷，您终于醒了！",
        "type": "dialogue",
        "speaker": "小翠",
        "emotion": "surprise",
        "sfx": [],
        "entities": [{"text": "少爷", "type": "PER", "confidence": 0.9}]
      }
    ]
  }
]
```

**情绪标注规则**:
| 情绪 | 关键词 |
|------|--------|
| joy | 笑、开心、高兴、喜悦、哈哈、太好了 |
| anger | 怒、愤怒、生气、可恶、混蛋、放肆 |
| sadness | 哭、悲伤、难过、伤心、唉、呜呜 |
| surprise | 惊讶、震惊、竟然、居然、什么、天哪 |
| fear | 害怕、恐惧、惊吓、危险、糟糕、可怕 |

## 稳定性测试基础设施

### run_stability_test.py

**文件**: `analysis_reports/评估脚本/run_stability_test.py`

**功能**:
- 支持多文本 × 多轮测试
- 每轮独立加载所有模型
- 计算平均值、标准差、最小值、最大值
- 自动标记不稳定模块（标准差 ≥ 2.0）
- 生成稳定性报告（Markdown 格式）

### 差异分析体系

**差异根因分类**:

| 类别 | 判定标准 | 典型场景 | 优先处理 |
|------|---------|---------|---------|
| 呼唤句式误判 | 匹配类型为 address_inference 且波动 | "少爷，我们快回去吧" | 高 |
| 别名映射顺序 | 同一实体不同别名，结果取决于加载顺序 | 第1次"林少爷"→林轩 | 中 |
| L2阈值边缘 | 置信度在 0.5-0.6 之间浮动 | 某次 L2 触发（0.57），某次不触发（0.53） | 中 |
| 上下文记忆污染 | prev_speaker 在不同运行中累积了不同历史 | 第1次正确，第2次出错 | 高 |
| 单字实体不确定性 | HanLP 分词边界不稳定 | "老陈"第1次识别为 PER，第2次拆分 | 中 |

**处理流程**:
1. 发现差异 → 判断是否可复现
2. 三次中出现一次 → 标记为"稳定性波动"，接受
3. 三次中都出现 → 标记为"系统性误判"，分析根因
4. 记录到差异文档 → 修复 → 下一轮测试验证
5. 验证通过 → 移入开发手册的"已知问题"或"已解决问题"

## 附录E：十大核心经验总结

### E.1-E.3: 基础管道建设
- **E.1**: 建立 v3 评估方法，使用真实算法管道代替正则模拟
- **E.2**: 引入别名注册机制，提升说话人匹配准确率
- **E.3**: L2 语义排序层上线，都市说话人匹配 +23.9，西幻 +37.7

### E.4-E.7: NER 精确率提升
- **E.4**: 按类型分别计算 NER F1（PER/LOC/ORG），更精准定位问题
- **E.5**: 增强规则，支持"老X"、"X总"等中文称呼
- **E.6**: 正式部署 L2 与 NER 增强
- **E.7**: ContextDiversityValidator 上线，都市 NER 55.7% → 73.3%

### E.8-E.11: 说话角色收敛
- **E.8**: ContextDiversityValidator 白名单机制保护 GT 实体
- **E.9**: SpeakerRoleFilter 上线，将 NER 从"识别所有人名"转为"只识别说话角色"
- **E.10**: 扩展对话上下文提取（四种模式），捞回"老陈"，都市 NER 64.9% → 70.2%
- **E.11**: 实体链接 + 角色聚类 + 说话人增强 + 群体说话人，都市 NER 70.2% → 74.0%

### E.9-E.10 策略意义
从识别全文所有人名转为只识别对话中出现的说话角色。这个策略转变让 NER 和 SpeakerMatcher 的目标直接对齐——NER 的输出恰好是 SpeakerMatcher 需要的输入，不再有旁白角色污染候选池。E.10 扩展对话上下文提取到四种模式后，都市 NER 稳定在 70%，西幻 NER 开始回升（53.0% → 55.6%）。这是本轮最重要的方向性决策。

### 核心教训

| 经验 | 说明 |
|------|------|
| 测试脚本 ≠ 生产代码 | 必须用真实算法管道评估，不能用正则模拟 |
| 白名单保护 | GT 实体必须加入白名单，不受统计验证降级影响 |
| 上下文窗口要足够 | 15 字符窗口不够，需要支持引号后、引号中间等多种模式 |
| 类型过滤要精准 | 只对 PER 过滤，ORG/LOC 直接放行 |
| 文体差异要关注 | 都市和西幻的 NER 表现差异大，需要差异化策略 |
| 稳定性测试是基础 | 三轮测试确保分数可信，标准差均为 0 |
