## 三、⚠️ 高优先级问题（应该修复）

### 3.1 性能瓶颈检测

#### 3.1.1 句子级循环中的 N+1 问题
**文件**: [`pipeline_runner.py:320-339`](file:///D:/trae/novel-tts-engine/pipeline/pipeline_runner.py#L320-L339)  
**问题**: 对每个句子都遍历全部 `linked_entities` 列表，使用 `getattr()` 逐属性获取  
**影响**: 章节有 N 个句子和 M 个实体时，复杂度为 O(N×M)  
**建议**: 使用实体位置索引或预构建句子-实体映射

#### 3.1.2 重复的字符串查找操作
**文件**: [`pipeline_runner.py:296-304`](file:///D:/trae/novel-tts-engine/pipeline/pipeline_runner.py#L296-L304)  
**问题**: 对话句子的 speaker 匹配中，对 `dialogue_map.items()` 进行遍历并使用 `in` 操作符  
**影响**: 每句最多遍历所有对话文本  
**建议**: 使用字典或集合进行 O(1) 查找

#### 3.1.3 冷启动聚类性能风险
**文件**: [`pipeline_runner.py:362-398`](file:///D:/trae/novel-tts-engine/pipeline/pipeline_runner.py#L362-L398)  
**问题**: 冷启动时遍历所有已处理章节的句子来重建 Entity 对象，start/end 位置全部设为 0  
**影响**: 丢失位置信息可能导致聚类精度下降  
**建议**: 在 `_process_chapter` 中保留实体位置信息

### 3.2 安全审计发现

#### 3.2.1 输入验证不足
**文件**: [`pipeline_runner.py:143`](file:///D:/trae/novel-tts-engine/pipeline/pipeline_runner.py#L143-L151)  
**问题**: `analyze_chapters` 方法对 `text` 参数没有长度限制和内容过滤  
**风险**: 恶意超长文本可能导致内存溢出  
**建议**: 添加最大文本长度限制（如 10MB）

#### 3.2.2 数据库路径硬编码
**文件**: [`utils/config.py`](file:///D:/trae/novel-tts-engine/utils/config.py#L5)  
**问题**: `DB_PATH = PROJECT_ROOT / "novel_tts.db"`  
**建议**: 使用环境变量配置数据库路径

#### 3.2.3 XSS 潜在风险
**文件**: [`frontend/app.py`](file:///D:/trae/novel-tts-engine/frontend/app.py)  
**问题**: Streamlit 渲染用户输入文本时未显式转义  
**风险**: 如果小说文本包含恶意 HTML/JS 代码  
**建议**: 对所有用户输入进行 HTML 转义

### 3.3 代码质量问题

#### 3.3.1 speaker_matcher.py 中存在 `sys.path.insert` 操作
**文件**: [`speaker_matcher.py:9`](file:///D:/trae/novel-tts-engine/pipeline/speaker_matcher.py#L9)  
**问题**: `sys.path.insert(0, str(Path(__file__).parent.parent))`  
**影响**: 修改全局 Python 路径可能影响其他模块导入  
**建议**: 使用相对导入或配置 PYTHONPATH

#### 3.3.2 魔法数字未定义常量
**多处**: 
- `COLD_START_CHARS_THRESHOLD = 3000` ✅ 已提取到 config
- `MEMORY_LIMIT_GB = 3.0` ✅ 已提取到 config
- 但仍有硬编码的阈值（如 `l2_threshold: float = 0.7`）

#### 3.3.3 getattr 过度使用
**文件**: [`pipeline_runner.py:322-328`](file:///D:/trae/novel-tts-engine/pipeline/pipeline_runner.py#L322-L328)  
**问题**: 连续使用 6 个 `getattr()` 获取实体属性，影响可读性和性能  
**建议**: 使用 `dataclass` 或 `TypedDict` 确保类型安全
