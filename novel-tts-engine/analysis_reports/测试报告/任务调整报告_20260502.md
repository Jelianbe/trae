## 二、测试速度优化计划

### 2.1 当前测试流程耗时分析

基于对 `run_stability_test.py` 和 `evaluate_generalization_v3.py` 的代码逐行分析：

#### 测试流程结构

```
稳定性测试 (3文本 x 3轮)
├── 文本1: 都市异能 (3614字, 287行)
│   ├── 第1轮: evaluate_novel()
│   ├── 第2轮: evaluate_novel()
│   └── 第3轮: evaluate_novel()
├── 文本2: 西幻 (~8000字, 614行)
│   ├── 第1轮: evaluate_novel()
│   ├── 第2轮: evaluate_novel()
│   └── 第3轮: evaluate_novel()
└── 文本3: 修仙 (~4000字, 约350行)
    ├── 第1轮: evaluate_novel()
    ├── 第2轮: evaluate_novel()
    └── 第3轮: evaluate_novel()
```

**总计**: 3个文本 × 3轮 = **9次 evaluate_novel() 调用**

#### 单次 evaluate_novel() 内部操作链

```
evaluate_novel()
├── load_ground_truth() - 加载GT JSON
├── CharacterManager() - 初始化 + 注册角色
├── evaluate_chapter_splitter() - 章节划分
├── evaluate_dialogue_classifier() - 对话分类
├── evaluate_sfx_detector() - 拟声词检测
├── evaluate_ner() ────────────────────────── 最耗时
│   ├── get_nlp() - HanLP模型加载（首次加载慢，全局单例）
│   ├── nlp.analyze() - NER推理
│   ├── ContextDiversityValidator.validate() - 右邻字统计
│   ├── SpeakerRoleFilter.filter() - 四种模式上下文提取
│   ├── SemanticRanker.load_model() - BGE模型加载
│   ├── EntityClusterer.cluster() - BGE编码+聚类
│   ├── EntityLinker.link() - 角色库链接
│   └── 计算F1分数
├── evaluate_speaker_matcher() ───────────── 耗时
│   ├── SemanticRanker.load_model() - BGE模型加载
│   ├── 第一遍：全文扫描建图（建对话历史缓存）
│   └── 第二遍：逐句匹配评估
└── evaluate_end_to_end() ────────────────── 耗时
    ├── SemanticRanker.load_model() - BGE模型加载
    ├── 第一遍：全文扫描建图（重复建图！）
    └── 第二遍：逐句匹配（重复评估！）
```

#### 各操作耗时估算（基于实际代码路径）

| 操作 | 都市(3.6K字) | 西幻(8K字) | 修仙(4K字) | 说明 |
|------|-------------|-----------|-----------|------|
| HanLP 模型加载 | 3-5s (首次) / <0.1s (缓存) | 同左 | 同左 | 全局单例 `get_nlp()` |
| BGE 模型加载 | 5-10s (首次) / <0.1s (缓存) | 同左 | 同左 | `SemanticRanker.load_model()` |
| NER 推理 (HanLP) | 1-2s | 2-4s | 1-2s | `nlp.analyze()` |
| ContextDiversityValidator | 1-2s | 2-4s | 1-2s | 右邻字统计，文本越大越慢 |
| SpeakerRoleFilter | 1-2s | 2-3s | 1-2s | 四种模式上下文提取 |
| EntityClusterer (BGE编码+聚类) | 2-4s | 4-8s | 2-4s | **最耗时步骤**，BGE编码所有实体上下文 |
| EntityLinker | 0.3-0.5s | 0.5-1s | 0.3-0.5s | 角色库链接 |
| SpeakerMatcher 两遍扫描 | 2-3s | 4-6s | 2-3s | 全文扫描 + 逐句匹配 |
| evaluate_end_to_end 两遍扫描 | 2-3s | 4-6s | 2-3s | **重复扫描**，与 SpeakerMatcher 逻辑重叠 |
| **单次评估总计(首次)** | **~20-35s** | **~30-55s** | **~20-35s** | 含所有模型加载 |
| **单次评估(模型已加载)** | **~10-20s** | **~15-30s** | **~10-20s** | 模型缓存后 |

#### 稳定性测试总耗时估算

| 场景 | 耗时估算 |
|------|---------|
| 首次运行（含所有模型加载） | **4-8分钟** |
| 后续运行（模型已缓存） | **2.5-5分钟** |
| 最慢情况（西幻文本触发大量BGE编码） | **10-12分钟** |

#### 关键耗时瓶颈识别

1. **重复全文扫描**: `evaluate_speaker_matcher()` 和 `evaluate_end_to_end()` 各执行两遍全文扫描，逻辑高度重叠。**浪费约 4-12秒/轮**
2. **BGE 模型重复加载**: 虽然使用全局单例，但 `evaluate_ner()` 和 `evaluate_speaker_matcher()` 和 `evaluate_end_to_end()` 各调用一次 `load_model()`，虽然后续调用会快速返回（`self._is_loaded` 检查），但仍需经过函数调用路径。
3. **EntityClusterer BGE编码**: 每次评估都完整执行，但输入文本和GT完全相同，结果也相同。**浪费约 18-54秒（9轮累计）**
4. **无快速模式**: 无法跳过昂贵操作进行快速验证
5. **无单文本模式**: 必须运行全部3个文本
6. **固定3轮**: 无法减少轮数进行快速迭代

#### SP-06: EntityClusterer 结果缓存

**问题**: 9轮稳定性测试中，每轮都完整执行 EntityClusterer，但输入文本和GT相同。

**实施方案**:

```python
_cluster_cache = {}

def evaluate_ner(text, ground_truth, semantic_ranker=None, use_cache=True):
    cache_key = hash(text + json.dumps(ground_truth, sort_keys=True))
    if use_cache and cache_key in _cluster_cache:
        return _cluster_cache[cache_key]
    result = _evaluate_ner_internal(text, ground_truth, semantic_ranker)
    if use_cache:
        _cluster_cache[cache_key] = result
    return result
```

**预期效果**: 第一轮完整执行，后续8轮直接返回缓存，节省 18-54秒（总计）。
