# LIKE查询性能与安全优化报告

## 问题描述

### Issue: SQL注入安全修复 - LIKE查询优化

**问题位置**: `pipeline/character_manager.py#L214-216`

**原始问题**: 使用 `f'%{alias}%'` 将用户输入直接与通配符拼接

**安全风险**:
1. 用户输入可能包含SQL特殊字符（`%`, `_`, `\`）
2. 这些字符在LIKE查询中会被解释为通配符
3. 可能导致意外匹配行为

## 修复方案

### 1. 添加特殊字符转义处理

```python
def _escape_like_pattern(self, pattern: str) -> str:
    """
    转义 LIKE 查询中的特殊字符
    
    SQLite LIKE 查询中，% 和 _ 是通配符，需要转义
    """
    return pattern.replace('%', r'\%').replace('_', r'\_').replace('\\', r'\\')
```

### 2. 使用 ESCAPE 子句

```python
escaped_alias = self._escape_like_pattern(alias)
cursor.execute(
    "SELECT id, name, aliases, gender, first_appearance FROM characters WHERE aliases LIKE '%' || ? || '%' ESCAPE '\\'",
    (escaped_alias,)
)
```

### 3. 查询优化策略

**精确匹配优先**:
```python
# 首先尝试精确匹配 name（使用索引）
cursor.execute(
    "SELECT ... WHERE name = ?",
    (alias,)
)

# 如果未找到，再进行模糊匹配（全表扫描）
cursor.execute(
    "SELECT ... WHERE aliases LIKE '%' || ? || '%' ESCAPE '\\'",
    (escaped_alias,)
)
```

## 性能对比

### 查询策略

| 查询方式 | 索引使用 | 性能 | 说明 |
|---------|---------|------|------|
| `WHERE name = ?` | ✅ 使用索引 | 快 | O(log n) |
| `WHERE aliases LIKE ?` | ❌ 全表扫描 | 慢 | O(n) |
| `WHERE aliases LIKE '%' \|\| ? \|\| '%'` | ❌ 全表扫描 | 慢 | O(n) |

### 优化策略

```
查询流程:
1. 精确匹配 name (使用索引，快速)
   ↓ 未找到
2. 模糊匹配 aliases (全表扫描，转义处理)
   ↓ 找到
3. 验证 alias 是否在 aliases JSON 数组中
```

## 安全性验证

### 特殊字符转义

| 输入字符 | 转义后 | 说明 |
|---------|--------|------|
| `%` | `\%` | 转义百分号通配符 |
| `_` | `\_` | 转义下划线通配符 |
| `\` | `\\` | 转义反斜杠本身 |

### 测试用例

```python
# 正常别名
alias = "张三"
# LIKE '%张三%' - 正常匹配

# 包含特殊字符的别名
alias = "100%"
# 转义后: 100\%
# LIKE '%100\%%' ESCAPE '\' - 正确匹配字面量 %

alias = "test_case"
# 转义后: test\_case
# LIKE '%test\_case%' ESCAPE '\' - 正确匹配字面量 _
```

- ✅ 使用 `||` 运算符分离通配符和参数
