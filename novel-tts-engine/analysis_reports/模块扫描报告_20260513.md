## 任务5：后端路由与管道调用关系

### 5.1 API 端点与管道模块调用关系

| API 端点 | HTTP 方法 | 调用的 pipeline 模块 | 功能说明 |
|----------|-----------|---------------------|----------|
| `/api/v1/health` | GET | `pipeline_runner`, `tts_generator` | 健康检查 |
| `/api/v1/projects/upload` | POST | `chapter_splitter` | 上传分章 |
| `/api/v1/projects/create` | POST | `chapter_splitter` | 创建项目 |
| `/api/v1/projects/{project_id}/chapters/{chapter_index}` | GET | `pipeline_runner` | 章节分析 |
| `/api/v1/projects/{project_id}/characters` | GET | `character_manager` | 获取角色列表 |
| `/api/v1/projects/{project_id}/characters/{char_id}/lock` | POST | `character_manager` | 锁定角色 |
| `/api/v1/projects/{project_id}/characters/{char_id}/unlock` | POST | `character_manager` | 解锁角色 |
| `/api/v1/tts/generate` | POST | `tts_generator` | TTS 生成 |
| `/api/v1/tts/chapter` | POST | `tts_generator` | 章节合成 |

### 5.2 管道模块调用层次

```
backend/main.py
├── ChapterSplitter (章节分割)
│   └── pipeline/chapter_splitter.py
├── PipelineRunner (管道分析)
│   ├── entity_linker.py
│   ├── speaker_matcher.py
│   ├── emotion_extractor.py
│   └── ... (其他分析模块)
├── CharacterManager (角色管理)
│   └── pipeline/character_manager.py
└── TTSGenerator (语音合成)
    ├── pipeline/tts_generator.py
    ├── pipeline/tts_kokoro.py
    └── pipeline/tts_indextts.py
```

### 5.3 直接调用检查

| 检查项 | 结果 | 说明 |

## 发现与建议

### 发现

1. **实体处理逻辑分散**：PER 实体处理逻辑分散在 `speaker_matcher.py` 和 `lp_basics.py` 两个核心文件中
2. **角色管理器封装完整**：所有数据库操作均通过 `character_manager.py`，未发现绕过现象
3. **单字姓氏多处定义**：`SINGLE_CHAR_SURNAMES` 在 `lp_basics.py` 和 `character_name_validator.py` 中重复定义
4. **后端路由结构清晰**：API 端点与管道模块的调用关系明确，层次分明

### 潜在问题

1. **代码重复**：`SINGLE_CHAR_SURNAMES` 集合在多个文件中重复定义，建议抽取到公共模块
2. **备份文件存在**：发现 `speaker_matcher.py.backup_before_rollback` 和 `speaker_matcher_v4_backup.py` 备份文件，建议清理或归档
3. **实体扩展/修剪逻辑**：仅在 `speaker_matcher.py` 中实现，可考虑抽取为独立服务
