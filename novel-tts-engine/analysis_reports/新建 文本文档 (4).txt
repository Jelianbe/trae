## 角色自动发现与注册模块 - 设计草案 v0.1

### 一、设计目标

在不破坏现有 `speaker_matcher`（有预注册场景）的前提下，增加一个**独立的、可选的**角色发现与注册管道，解决无预注册或预注册不全时的冷启动问题。

**核心原则**：
- **单一职责**：发现模块只负责“从文本中提取可能的角色名并临时注册”，不参与说话人匹配逻辑。
- **可插拔**：可以通过配置开关启用/禁用，可以替换不同的提取策略（NER、规则、SRL、LLM）。
- **渐进增强**：先简单后复杂，逐步提升召回率，同时保持精度。
- **无侵入**：与现有 `character_manager` 通过明确定义的接口交互，不修改现有 `speaker_matcher` 核心流程（只在 fallback 处调用）。

### 三、关键接口定义

#### 3.1 `CandidateExtractor` 抽象基类

```python
from abc import ABC, abstractmethod
from typing import List, Dict, Any

class CandidateExtractor(ABC):
    @abstractmethod
    def extract(self, text: str, context: Dict[str, Any] = None) -> List[Dict[str, Any]]:
        """
        从文本中提取候选角色名
        返回: [{"name": "赵总监", "source": "pattern_surname_title", "confidence": 0.7, "span": (start, end)}]
        """
        pass
```

#### 3.2 `CharacterDiscoveryEngine`

```python
class CharacterDiscoveryEngine:
    def __init__(self, extractors: List[CandidateExtractor], 
                 filter_normalizer: 'CandidateFilterNormalizer',
                 registry: 'TemporaryCharacterRegistry'):
        self.extractors = extractors
        self.filter_normalizer = filter_normalizer
        self.registry = registry
    
    def discover_from_chapter(self, chapter_text: str, chapter_id: int, project_id: str):
        """对整个章节进行角色发现并注册临时角色"""
        all_candidates = []
        for ext in self.extractors:
            candidates = ext.extract(chapter_text)
            all_candidates.extend(candidates)
        
        # 过滤+归一化
        normalized = self.filter_normalizer.process(all_candidates)
        
        # 注册到角色库（临时）
        self.registry.register(normalized, chapter_id, project_id)
```

#### 3.3 `TemporaryCharacterRegistry`

```python
class TemporaryCharacterRegistry:
    def __init__(self, char_manager: CharacterManager):
        self.char_manager = char_manager
        self._cache = {}  # 避免重复注册
    
    def register(self, candidates: List[Dict], chapter_id: int, project_id: str):
        for cand in candidates:
            name = cand['normalized_name']
            if name in self._cache.get(project_id, set()):
                continue
            # 调用 char_manager 添加临时角色
            self.char_manager.add_character(
                name=name,
                project_id=project_id,
                aliases=set(cand.get('aliases', [])),
                gender='unknown',
                first_appearance=chapter_id,
                is_temp=True,
                metadata={'source': cand['source'], 'confidence': cand['confidence']}
            )
            self._cache.setdefault(project_id, set()).add(name)
```

### 四、集成到现有 `speaker_matcher`

**不改动现有匹配逻辑**，只在 `analyze_dialogue` 的 **最终 fallback 处**（即所有策略都返回“未知”）调用发现模块的**即时发现**（可选），或者完全依赖独立的预处理阶段。

推荐做法：
- **预处理模式**：在 `PipelineRunner` 处理章节前，先调用 `CharacterDiscoveryEngine.discover_from_chapter` 对整个章节进行一轮发现，把所有潜在角色预注册为临时角色。这样 `speaker_matcher` 就能匹配到它们（尽管置信度低）。
- **即时模式**：在 `analyze_dialogue` 无法匹配时，调用一个轻量级的 `_quick_discover` 方法，只分析当前句子附近的文本，注册新角色并返回。

**建议先实现预处理模式**，因为它更干净、不影响实时性能，且能一次性注册整章的所有角色。

- 可选，根据需求

### 六、风险评估与缓解

| 风险 | 缓解措施 |
|------|----------|
| 临时角色过多，干扰匹配 | 降低临时角色置信度因子（如0.6），正式角色优先 |
| 错误注册（如“办公室”） | 强过滤规则 + 仅当出现次数≥2或出现在对话上下文才注册 |
| 性能下降（整章提取） | 仅对旁白文本提取，且可限制长度；提取器可缓存 |
| 与现有角色库冲突（如别名） | 注册前检查是否已存在（大小写归一化），存在则跳过或合并 |
