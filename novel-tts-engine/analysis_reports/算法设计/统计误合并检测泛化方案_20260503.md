## 一、当前问题

### 1.1 硬编码集合的局限性

当前`_detect_mis_merged_entities`使用硬编码的`SINGLE_CHAR_VERBS`集合：

```python
SINGLE_CHAR_VERBS = {
    '冷', '笑', '怒', '喜', '愁', '悲', '愤', '急', '惊', '疑',
    '呆', '愣', '痴', '醉', '困', '累', '饿', '渴', '痛', '痒',
    '羞', '恼', '恨', '怨', '叹', '泣', '吼', '喊', '叫', '骂',
}
```

**问题**：
1. 无法覆盖所有可能的动词后缀（如"承"、"喏"、"应"等）
2. 需要人工维护，容易遗漏
3. 不同作品可能有不同的常用动词后缀
4. 无法适应新的文学风格

### 1.2 真实案例

- "萧炎承喏道" → "萧炎承"(PERSON) + "喏道" - "承"不在SINGLE_CHAR_VERBS中
- "陈承喏" → 真实人名，但"承"和"喏"都在动词集合中 - 会误杀

---

## 二、设计目标

1. **自动化发现**：从文本中自动发现高频动词后缀
2. **作品自适应**：不同作品有不同的动词使用习惯
3. **避免误杀**：不将真实人名的组成部分误判为动词
4. **可解释性**：能够解释为什么某个字符被判定为动词后缀

---

## 三、方案设计

### 3.1 统计学习方法：基于右邻字多样性

**核心思想**：
- 真实人名后面的字符应该具有**高多样性**（可以跟"的"、"说"、"问"、"是"等）
- 动词后缀后面的字符应该具有**低多样性**（通常只跟"道"、"说"、"问"等对话引导词）

**算法**：

```python
def discover_verb_suffixes_statistically(text: str, known_persons: set) -> set:
    """
    从文本中统计发现高频动词后缀
    
    原理：
    1. 收集所有"字符X + 道/说/问"的模式
    2. 如果字符X经常出现在"道/说/问"前面，且右邻字多样性低
    3. 则字符X很可能是动词后缀
    
    参数：
    - text: 完整文本
    - known_persons: 已确认的高频角色名集合
    
    返回：
    - 动词后缀字符集合
    """
    import re
    from collections import Counter, defaultdict
    
    # 步骤1：找到所有"X道"、"X说"、"X问"模式
    dialogue_patterns = re.findall(r'(.{1,2})(?:道|说|问|喊|叫)', text)
    
    # 步骤2：统计每个字符X后面跟着的字符
    suffix_neighbors = defaultdict(set)
    suffix_counts = Counter()
    
    for match in dialogue_patterns:
        suffix_char = match[-1]  # 取最后一个字符
        suffix_counts[suffix_char] += 1
        
        # 记录该字符后面的字符（右邻字）
        # 在"X笑道"中，"笑"后面通常只跟"道"
        # 在"萧炎说道"中，"炎"后面可以跟很多不同的字符
    
    # 步骤3：计算右邻字多样性
    # 对于真实人名的最后一个字，右邻字应该很多样
    # 对于动词后缀，右邻字应该很单一（通常只有"道"、"说"等）
    
    verb_suffixes = set()
    for suffix_char, count in suffix_counts.items():
        # 出现次数足够多（>=5次）
        if count < 5:
            continue
        
        # 计算右邻字多样性（需要扫描全文）
        right_neighbors = get_right_neighbors(suffix_char, text)
        
        # 如果右邻字种类很少（<=3种），说明是动词后缀
        if len(right_neighbors) <= 3:
            # 进一步验证：这些右邻字是否主要是对话引导词
            dialogue_words = {'道', '说', '问', '喊', '叫', '答', '应'}
            dialogue_ratio = len(right_neighbors & dialogue_words) / len(right_neighbors)
            
            if dialogue_ratio >= 0.5:
                verb_suffixes.add(suffix_char)
    
    return verb_suffixes
```

### 3.2 避免误杀：人名结构特征验证

**问题**：如何区分"陈承喏"（真实人名）和"萧炎冷"（误合并）？

**解决方案**：

1. **已知角色名保护**：
   - 如果"陈承喏"在文本中出现≥5次，且右邻字多样
   - 则"陈承喏"应该被加入known_persons
   - 误合并检测会跳过known_persons中的实体

2. **字符紧密度分析**：
   ```python
   def is_likely_mis_merged(entity_text: str, known_persons: set, text: str) -> bool:
       """
       判断实体是否可能是误合并
       
       逻辑：
       1. 实体长度>=3
       2. 末端字符是统计发现的动词后缀
       3. 去除末端后，剩余部分是known_persons中的高频角色
       4. 实体整体出现次数远低于前缀角色名的出现次数
       """
       if len(entity_text) < 3:
           return False
       
       # 尝试去除末端1-2字
       for suffix_len in [1, 2]:
           prefix = entity_text[:-suffix_len]
           suffix = entity_text[-suffix_len:]
           
           # 如果前缀是已知高频角色
           if prefix in known_persons:
               # 检查后缀是否是统计发现的动词后缀
               if suffix in discovered_verb_suffixes:
                   # 进一步验证：实体出现次数是否远少于前缀
                   entity_count = count_occurrences(entity_text, text)
                   prefix_count = count_occurrences(prefix, text)
                   
                   # 如果实体出现次数 < 前缀的10%，说明很可能是误合并
                   if entity_count < prefix_count * 0.1:
                       return True
       
       return False
   ```

## 四、验证方案

### 4.1 测试用例

```python
def test_statistical_verb_suffix_discovery():
    """测试统计动词后缀发现"""
    text = """
    萧炎冷笑道："..."
    萧炎怒道："..."
    萧炎叹道："..."
    萧炎问道："..."
    陈承喏说道："..."  # 真实人名，不应被误判
    陈承喏来了。
    陈承喏的书。
    陈承喏今天。
    """
    
    discovered = discover_verb_suffixes_statistically(text, known_persons={'陈承喏'})
    
    # 应该发现：冷、怒、叹、问
    assert '冷' in discovered
    assert '怒' in discovered
    assert '叹' in discovered
    
    # 不应该发现：喏（因为"陈承喏"是known_persons，右邻字多样）
    assert '喏' not in discovered
```
