## 3. P0：角色库未覆盖身份词修复

### 3.1 问题描述

测试中有 4 个案例的说话人是"身份词"（如掌柜、首领、联盟成员），而非标准人名。这些身份词在角色库中不存在，导致系统无法匹配。

| 案例 | 旁白 | 预期 | 实际 |
|-----|------|------|------|
| P1 | `"林轩推开客栈的门，对着掌柜说道："` | 掌柜 | 未知 |
| P21 | `"联盟成员怒吼着冲上前。博士冷笑："` | 联盟成员 | 博士 |
| P29 | `"门开了，一个清脆的声音回答："` | 小翠 | 赵天行 |
| P34 | `"首领挥剑指向敌方。"` | 首领 | 未知 |

### 3.2 修复方案

**方案 A：身份词自动注册为临时角色**

在 `_extract_context_speakers` 和 `get_speaker_for_sentence` 中，当 NER 未提取到 PER 实体但正则匹配到身份词时，自动创建临时角色并加入候选列表。

**修改文件**: `pipeline/speaker_matcher.py`

**新增方法**:

```python
def _extract_identity_words(self, text: str) -> List[str]:
    """从文本中提取身份词候选。
    
    身份词是指表示身份/职业/关系的词，如"掌柜"、"首领"、"联盟成员"等。
    这些词在上下文中可能作为说话人出现，但不会被 NER 识别为 PER 实体。
    
    识别规则：
    1. "对着/对/向/跟" + 名词 + "说/道/问/喊/叫/呼唤"
    2. 名词 + "怒吼/冷笑/怒视/喝道/怒道"
    3. 名词 + 动词 + 逗号/冒号 + 对话
    
    来源：基于错误案例分析（P1、P21、P34 等身份词未被识别案例）
    边界：仅匹配 2-4 字的身份词，避免匹配长描述
    更新日期：2026-05-10
    维护者：P0 身份词修复方案
    """
    import re
    candidates = []
    
    # 规则1：对着/对/向/跟 + 名词 + 说话动词
    pattern1 = r'[对着向跟]([\u4e00-\u9fa5]{2,4})[说道问喊叫呼唤]'
    for match in re.finditer(pattern1, text):
        word = match.group(1)
        if word not in ('什么', '哪里', '怎么', '为什么'):
            candidates.append(word)
    
    # 规则2：名词 + 情绪动词
    pattern2 = r'([\u4e00-\u9fa5]{2,4})(?:怒吼|冷笑|怒视|喝道|怒道|吼道|嚷道)'
    for match in re.finditer(pattern2, text):
        word = match.group(1)
        if len(word) >= 2:
            candidates.append(word)
    
    return candidates
```

**集成到 `_extract_context_speakers`**：

在 NER 提取后、描述性角色提取前，增加身份词提取步骤：

## 4. P1：复姓 NER 截断修复

### 4.1 问题描述

HanLP NER 对复姓（纳兰、慕容、欧阳等）只提取姓氏部分，而非完整姓名。

| 案例 | 旁白 | 预期 | 实际 |
|-----|------|------|------|
| P2 | `"纳兰嫣然放下书卷，头也不抬地问："` | 纳兰嫣然 | 纳兰 |
| P16 | `"纳兰嫣然推门而入。她冷冷说道："` | 纳兰嫣然 | 纳兰 |
| P19 | `"纳兰嫣然笑道："` | 纳兰嫣然 | 纳兰 |

### 4.2 修复方案

**方案**：在 `_extract_context_speakers` 中，NER 提取后增加复姓扩展逻辑。

**修改文件**: `pipeline/speaker_matcher.py`

**新增方法**:

```python
def _expand_surname_entities(self, text: str, entities: List[Tuple[str, str]]) -> List[Tuple[str, str]]:
    """扩展复姓 NER 实体。
    
    HanLP 对复姓（纳兰、慕容、欧阳等）可能只提取姓氏部分。
    本方法通过正则匹配，从原文中提取完整的复姓+名字。
    
    复姓列表来源：《中国姓氏大辞典》，收录常见复姓 60+ 个
    边界：仅处理常见复姓，不尝试处理罕见复姓
    更新日期：2026-05-10
    维护者：P1 复姓修复方案
    """
    import re
    
    # 常见复姓列表
    compound_surnames = [
        '纳兰', '慕容', '欧阳', '上官', '司马', '诸葛', '夏侯',
        '皇甫', '尉迟', '公孙', '轩辕', '令狐', '东方', '司徒',
        '鲜于', '端木', '澹台', '公冶', '宗政', '濮阳', '淳于',
        '单于', '太叔', '申屠', '仲孙', '钟离', '长孙', '宇文'
    ]
    
    expanded = list(entities)
    
    for surname in compound_surnames:
        # 匹配复姓+2-3字名字（如纳兰嫣然、慕容复、欧阳明日）
        pattern = rf'{surname}[\u4e00-\u9fa5]{{2,3}}'
        for match in re.finditer(pattern, text):
            full_name = match.group()
            # 检查是否已有截断版本
            for i, (entity, entity_type) in enumerate(expanded):
                if entity == surname:
                    expanded[i] = (full_name, entity_type)
                    break
            else:
                expanded.append((full_name, 'PER'))
    
    return expanded
```

```python
def _extract_descriptive_characters(self, text: str) -> List[str]:
    """从文本中提取描述性角色指称。
    
    当 NER 未识别到 PER 实体时，使用正则匹配常见的描述性角色模式。
    这些模式包括：
    - 颜色 + 服饰/物品（如"黑衣人"、"白袍老者"）
    - 形容词 + 身份（如"高大身影"、"神秘人物"）
    
    来源：基于错误案例分析（P4、P13 等描述性角色未被识别案例）
    边界：仅匹配 2-5 字的描述性短语，避免匹配过长描述
    更新日期：2026-05-10
    维护者：P2 描述性角色修复方案
    """
    import re
    candidates = []
    
    # 模式1：颜色 + 服饰 + 身份
    pattern1 = r'[黑白红蓝青紫黄灰银金][\u4e00-\u9fa5]{1,3}(?:人|者|客|僧|道|尼|侠|剑)'
    for match in re.finditer(pattern1, text):

    # 模式2：形容词 + 身份/人物
    pattern2 = r'(?:高大|矮小|瘦弱|肥胖|年轻|年老|神秘|熟悉|陌生)(?:的)?(?:身影|人物|声音|男子|女子|老者|少年)'
    for match in re.finditer(pattern2, text):
        candidates.append(match.group())
    
    return candidates
```

## 6. P3：代词消解就近原则修复

### 6.1 问题描述

| 案例 | 旁白 | 预期 | 实际 |
|-----|------|------|------|
| P7 | `"药老从戒指中飘出。他看了一眼萧炎，缓缓道："` | 药老 | 萧炎 |
| P28 | `"你输了。"苏夜收起剑。黑衣人跪在地上："` | 黑衣人 | 苏夜 |

### 6.2 修复方案

**方案**：在 `pronoun_resolver.py` 的 `resolve_in_local_window` 中，增加主语位置加权。

**修改文件**: `pipeline/pronoun_resolver.py`

**新增辅助方法**:

```python
def _is_subject_position(self, name: str, context: str) -> bool:
    """判断实体是否位于主语位置。
    
    启发式规则：
    1. 显式提示动词前最近的名词（正则匹配 {实体}.*[说道问喊叫]）
    2. 句首实体（句号或开头后的第一个名词性实体）
    3. 主语标记：实体后紧跟动词（非介词宾语）
    
    来源：基于错误案例分析（P7、P28 等代词消解错误案例）
    边界：仅判断主语/宾语位置，不处理复杂句法
    更新日期：2026-05-10
    维护者：P3 代词消解修复方案
    """
    import re
    
    # 规则1：提示动词前的实体
    speech_verbs = '道说问喊叫呼唤喝'
    pattern = rf'{re.escape(name)}[^{speech_verbs}]{{0,10}}[{speech_verbs}]'
    if re.search(pattern, context):
        return True
    
    # 规则2：句首实体
    sentences = re.split(r'[。！？\n]', context)
    for sent in sentences:
        sent = sent.strip()
        if sent.startswith(name):
            return True
    
    return False

def _is_object_position(self, name: str, context: str) -> bool:
    """判断实体是否位于宾语位置。
    
    启发式规则：实体紧邻"对/向/给/把/看"等介词/动词后
    """
    import re
    
    # 介词宾语
    prepositions = '对向给把'
    pattern = rf'[{re.escape(prepositions)}]{re.escape(name)}'
    if re.search(pattern, context):
        return True
    
    # 动词宾语（看了 X、打了 X、问了 X）
    verbs = '看打问叫喊'
    pattern = rf'[{re.escape(verbs)}]了{re.escape(name)}'
    if re.search(pattern, context):
        return True
    
    return False
```

### 9.3 R-005：全流程文档化

- 本方案对应需求编号：BR-P0（身份词修复）、BR-P1（复姓修复）、BR-P2（描述性角色修复）、BR-P3（代词消解修复）

- 代码逻辑变更时同步更新 `analysis_reports/综合分析报告_v6.md`
- 测试通过后更新本方案的"实施路线图"章节

### 9.6 R-011：用户主权

- 用户随时可以叫停当前操作
- 检测到"停止"、"错了"、"换方法"等关键词时立即停下
- 切换为咨询模式，等待用户进一步指示

### 9.7 R-012：最小化范围

- **严禁顺手优化式修改**
- 只修复 P0-P3 明确定义的问题
- 不触碰已放弃的任务（群体检测、修饰词归一化、显式提示遮挡）
- 不修改与修复目标无关的逻辑

### 9.8 R-014：假设驱动开发

每个改动前必须提出假设：

| 改动 | 假设 | 验证方式 | 回退条件 |
|-----|------|---------|---------|
| P0 身份词提取 | "提取身份词可修复 4 个角色库未覆盖案例" | 运行 35 段落测试集 | 准确率下降 > 1% |
| P1 复姓扩展 | "复姓扩展可修复 3 个别名截断案例" | P2/P16/P19 案例验证 | 引入新错误 > 2 个 |
| P2 描述性角色提取 | "描述性角色提取可修复 2 个漏识别案例" | P4/P13 案例验证 | 引入新错误 > 2 个 |
| P3 主语加权 | "主语位置加权可修复代词消解错误" | P7/P28 案例验证 | 引入新错误 > 2 个 |

### 9.9 编码规则

- **泛用性优先**：使用通用语言特征（正则、词性），不硬编码词表
- **诚实优于猜测**：证据不足时返回"未知"，不强行匹配
- **禁止新增映射表**：不添加 `if name == '某个名字'` 硬编码
- **所有静态集合需有来源注释**：说明设计依据和适用范围
