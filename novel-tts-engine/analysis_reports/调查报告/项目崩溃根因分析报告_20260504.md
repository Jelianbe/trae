### 2.1 初步假设（已排除）

| 假设 | 验证结果 | 结论 |
|------|---------|------|

### 2.2 根因定位

**问题链路追踪**：

```
测试数据格式
    ↓
评估脚本构造完整文本（用 \n 分隔）
    ↓
Pipeline 句子分割（split_sentences_smart）
    ↓
【关键问题】不识别 \n 为句子分隔符
    ↓
多行文本被合并成一个"句子"
    ↓
find_target_sentence 找不到目标句子
    ↓
返回空字符串
```

## 3. 根本原因

### 3.1 直接原因

**评估脚本 `find_target_sentence` 函数无法找到目标句子**

```python
def find_target_sentence(sentences, target_text: str):
    target_text = target_text.strip()  # "「你给我滚出去！」"
    for s in sentences:
        if s.text.strip() == target_text:  # 永远不匹配！
            return s
    return None  # ← 所有样本都返回 None
```

### 3.2 深层原因

**`split_sentences_smart` 函数不将换行符视为句子分隔符**

```python
# utils/text_utils.py 第 12 行
_SENTENCE_END_PATTERN = re.compile(r'([。！？；])')
# 只匹配标点符号，不匹配换行符！
```

**实际效果**：

| 输入文本 | 预期分割结果 | 实际分割结果 |
|---------|-------------|-------------|
| `"苏夜站在门口。\n「滚出去！」\n林雪愣住了。"` | 3 个句子 | **1 个句子**（三行合并） |

### 3.3 设计原因

**测试数据格式与 Pipeline 预期不匹配**

测试数据 `role_emotion_gt_50.json` 使用 `\n` 分隔上下文：
```json
{
  "text": "「你给我滚出去！」",
  "context_before": "苏夜站在门口，脸色铁青。",
  "context_after": "林雪愣住了，她从没见过苏夜这样。"
}
```

评估脚本构造：
```python
full_text = f"{context_before}\n{text}\n{context_after}"
```

但 Pipeline 的句子分割器不识别 `\n` 为分隔符。

## 6. 修复方案

### 方案 A：修改句子分割逻辑（推荐）

修改 `utils/text_utils.py`，将换行符视为句子分隔符：

```python
_SENTENCE_END_PATTERN = re.compile(r'([。！？；\n])')
```

**优点**：一劳永逸，支持更多文本格式  
**风险**：可能影响现有功能，需要回归测试

### 方案 B：修改评估脚本

修改 `find_target_sentence` 使用包含匹配：

```python
def find_target_sentence(sentences, target_text: str):
    target_text = target_text.strip()
    for s in sentences:
        if target_text in s.text:  # 包含匹配
            return s
    return None
```

**优点**：改动最小，不影响 Pipeline  
**缺点**：可能匹配到错误句子

### 方案 C：修改测试数据格式

不使用换行符分隔，直接拼接：

```python
full_text = f"{context_before}{text}{context_after}"
```

**优点**：最简单  
**缺点**：丢失上下文边界信息

## 7. 附加发现

### 7.1 `set()` 无序问题

`speaker_matcher.py` 第 200 行：

```python
return list(set(persons))  # 无序！
```

**影响**：可能导致角色匹配结果不稳定  
**建议**：改为保持原始顺序的去重

```python
seen = set()
unique = []
for p in persons:
    if p not in seen:
        seen.add(p)
        unique.append(p)
return unique
```

### 7.2 日期错误问题

项目中发现 10 个文件包含错误日期 `2026-05-06`，实际应为 `2026-05-04`。

## 8. 结论

### 8.1 核心结论

> **项目并没有"崩溃"，角色识别算法本身没有问题。问题是新创建的测试数据格式与 Pipeline 的句子分割逻辑不匹配，导致评估脚本无法找到目标句子。**

### 8.2 影响评估

| 维度 | 评估 |
|------|------|
| 代码质量 | ✅ 正常，无严重 Bug |
| 算法正确性 | ✅ 正常，逻辑正确 |
| 测试框架 | ⚠️ 存在设计缺陷 |
| 文档一致性 | ⚠️ 日期错误需修正 |

### 8.3 下一步建议

1. **立即修复**：修正日期错误
2. **短期修复**：采用方案 B 修改评估脚本
3. **中期优化**：采用方案 A 优化句子分割逻辑
4. **长期改进**：建立测试数据格式规范
