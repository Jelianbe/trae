## 一、项目状态与背景概述

### 1.1 项目目标

将非结构化的小说文本自动转换为**带说话角色标注、情绪标注、音效标记的结构化数据**，供下游 TTS 引擎（Kokoro / Index-TTS）生成多角色、多情绪的有声书音频。

### 1.2 已完成的核心功能

| 模块 | 状态 | 说明 |
|------|------|------|
| 章节划分 | ✅ | `chapter_splitter.py` — Step 1 |
| NLP 基础 | ✅ | `nlp_basics.py` — 分词、词性标注、NER (HanLP) |
| 实体链接 | ✅ | `entity_linker.py` — 别名归一化 |
| 角色管理 | ✅ | `character_manager.py` — SQLite 持久化，project_id 隔离 |
| 说话人匹配 | ✅ | `speaker_matcher.py` — 6 策略级联 |
| 情绪提取 | ✅ | `emotion_extractor.py` — 方案 B 双管道 |
| TTS 生成 | ✅ | `tts_generator.py` — Kokoro + Index-TTS 统一入口 |
| Web API | ✅ | `backend/main.py` — FastAPI，16+ 端点 |
| 前端 SPA | ✅ | `frontend/index.html` — 原生 JS v3 |
| 测试框架 | ✅ | `tests/conftest.py` — pytest 隔离数据库（R-022 重构） |

### 1.3 当前基线

| 测试集 | 准确率 | 说明 |
|--------|--------|------|
| **城市职场长文本** | **81.2%** (69/85) | 使用隔离临时数据库 |
| **西幻长文本** | **53.8%** (21/39) | 使用隔离临时数据库 |
| 综合平均分 | 72.0% | 都市76.0 / 西幻66.4 / 修仙73.7 |

### 1.4 当前面临的主要挑战

1. **西幻文体准确率低**（53.8% vs 城市 81.2%）：音译名识别、描述性角色误匹配
2. **连续对话识别**：纯对话行（无旁白）说话人推断，城市职场剩余 16 条错误多集中于此
3. **TTS 性能**：当前串行生成，耗时长
4. **内存占用**：HanLP/BGE 模型常驻内存，空闲时不释放

### 1.5 关键架构决策

| 决策 | 内容 | 理由 |
|------|------|------|
| project_id 隔离 | 单数据库 + 字段过滤 | 管理简单，够用 |
| 测试隔离 | 独立临时数据库（conftest.py） | 完全隔离，避免污染 |
| 空 project_id 禁止 | `add_character` / `find_or_create` 校验非空 | 防止静默数据污染 |
| 说话人匹配 6 策略 | 上下文推理 → 提示词 → 代词 → 角色库 → 语义 → 触发词 | 分级级联，快速失败 |
| 多特征评分重排 | **已拒绝**（H-20260515-09） | 场景参与度形成正反馈循环 |

## 七、常见问题 FAQ

**Q: 为什么西幻准确率比城市职场低这么多？**
A: 根因已定位：音译名（亚瑟、艾琳）不被 NER 识别为人名，描述性角色提取器误提取"骑士"、"法师"等为角色名。此外连续对话逻辑在交替场景中表现不佳。

**Q: 测试数据会不会污染生产库？**
A: 已修复。pytest 测试使用 `conftest.py` 提供的临时数据库，测试结束后自动删除。只有 `python tests/xxx.py` 独立运行才会使用生产库。

**Q: 多特征评分重排为什么被拒绝？**
A: H-20260515-09 实验发现场景参与度形成正反馈循环，频繁出现的角色持续获得高分，导致误判率上升。此方向不宜继续迭代。

**Q: 如何添加新的测试集？**
A: 1) 在 `tests/` 下创建 `{name}_test.txt` 和 `{name}_answer_key.json`；2) 创建 `test_{name}.py` 测试脚本；3) 在 `conftest.py` 中添加对应 fixture（如需要）。
