## 第一阶段：结构优化（预期 +1.9%）

### 改动 1：移除 NER 的 context_per 路径

**文件**: [speaker_matcher.py](file:///d:/trae/novel-tts-engine/pipeline/speaker_matcher.py)

**目标**: 关闭 NER 从上下文中提取 PER 作为候选人的路径（保留 NER 用于检测新角色）

**为什么**: 消融实验显示关闭 NER 后准确率从 41.2% → 43.1%。NER 提取的"上下文被提及角色"（如"族长""骑士""将军"）只是旁白叙述中提到的角色，并非说话人，引入噪声多于正确信息。

**修改方法**:

在 `_extract_context_speakers()` 方法中，删除或注释掉以下两部分代码：

1. **"步骤2：NER 提取 PER 实体（context_before）"** 整个代码块
   - 定位：在 `_extract_context_speakers()` 中，`# 步骤1：代词消解` 之后
   - 范围：从 `# 步骤2：NER 提取 PER 实体（过滤带修饰词的实体）` 到下一个 `# 步骤` 注释前
   - 删除后：保留 `# 步骤1：代词消解` 不变，步骤3的描述性角色提取不变

2. **"步骤3：NER 提取 PER（context_after）"** 整个代码块
   - 定位：在 context_after 部分的描述性角色提取之后
   - 范围：从 `if context_after:` 下的 NER 提取代码块到后一个 `# 兜底步骤` 前

**保留**: `_extract_from_ner()` 方法本身不动（用于检测新角色 + 自动入库）

**验证**:
- `python .\tests\baseline_rules_speaker.py` → 准确率从 ~45% → ~47%（期望）
- 自动角色创建不受影响（NER 仍可从句子内检测新角色）

## 第二阶段：规则修复（预期 +10%~15%）

### 改动 3：修复截断类错误（7 条）

**问题**: 规则匹配 `role_core_words` 中的通用身份词时截断了完整角色名。

| ID | GT | 规则预测 | conf |
|:---|:---|:---------|:----:|
| re_003 | 韩将军 | 将军 | 0.80 |
| re_006 | 黑甲骑士 | 黑甲 | 0.85 |
| re_021 | 部门经理 | 经理 | 0.85 |
| re_026 | 老剑客 | 剑客 | 0.85 |
| re_045 | 老兵 | 年轻士兵 | 0.75 |
| re_058 | 巡逻队长 | 队长 | 0.85 |
| re_064 | 亚历山大·安德森 | 骑士 | 0.80 |

**根因**: `match_speaker()` 中的 `trigger_result = self.match_by_trigger_words(...)` 直接返回 `role_core_words` 中的匹配项（如"将军"），然后作为 `match_speaker()` 的最终结果返回，没有检查上下文是否存在更完整的角色名。

**修改方法**:

在 [speaker_matcher.py](file:///d:/trae/novel-tts-engine/pipeline/speaker_matcher.py) 的 `match_speaker()` 方法中，在收到 `trigger_result`（角色核心词匹配结果）后，添加截断检查：

```python
# 伪代码——在 match_speaker() 中 trigger_result 返回后：
if trigger_result and trigger_result.match_type == 'role_core_words':
    # 检查语境中是否存在 "修饰词 + 匹配词" 的完整形式
    matched_name = trigger_result.character.name  # 如 "将军"
    context_text = f"{context.context_before} {context.context_after}"
    
    # 规则1：检查 context_before 中是否包含 "X + matched_name"（如 "韩将军"）
    prefix_pattern = re.compile(
        rf'([\u4e00-\u9fa5]){re.escape(matched_name)}'
    )
    prefix_matches = prefix_pattern.findall(context_text)
    
    # 规则2：检查 context_after 中是否有完整角色名（如"队长"出现在旁白时，检查"巡逻队长"）
    # 规则3：如果以上匹配到，且该完整名称在角色库中存在，优先返回完整名称
    
    # 示例逻辑：
    for char in self.char_manager.get_all_characters(self._current_project_id):
        if matched_name in char.name and char.name != matched_name:
            if char.name in context_text:
                # 完整角色名在上下文中出现，优先使用
                return MatchResult(
                    character=char,
                    confidence=0.85,
                    match_type=f'context_reasoning:角色名扩展({char.name})'
                )
```

**注意**: 这个逻辑不能做成硬编码的"A→B 映射表"（违反 R-016）。必须基于**上下文文本中真实出现**的证据来推断。

### 改动 4：修复错选类错误（9 条）

**问题**: `context_reasoning` 路径按活跃度排序，从角色库中选了最活跃的角色，但活跃不等于说话人。

| ID | GT | 规则预测 | conf | 场景 |
|:---|:---|:---------|:----:|------|
| re_024 | 林雪 | 苏夜 | 0.85 | 林雪说话，但苏夜更活跃 |
| re_037 | 药老 | 萧炎 | 0.85 | 师徒对话，萧炎更活跃 |
| re_029 | 年轻将领 | 元帅 | 0.80 | 旁白提元帅，但不是说话人 |
| re_032 | 年轻人 | 族长 | 0.80 | 同上 |
| re_034 | 年轻人 | 老铁匠 | 0.80 | 同上 |
| re_042 | 女修 | 少年 | 0.80 | 旁白提少年，但说话人是女修 |
| re_048 | 黑衣男子 | 男子 | 0.80 | 身份词截断 |
| re_068 | 黑袍法师 | 法师 | 0.80 | 同上 |
| re_092 | 萧炎 | 药老 | 0.75 | 师徒对话反向 |

**根因**: `_extract_context_speakers()` 中候选人排序时，全局活跃度权重过高，近因权重过低。

**修改方法**:

在 [speaker_matcher.py](file:///d:/trae/novel-tts-engine/pipeline/speaker_matcher.py) 的 `_extract_context_speakers()` 返回 `candidates` 列表前，增加基于**近因优先**的排序维度：

```python
# 伪代码——在 return candidates 之前，增加近因加权

# 引入近因权重：上下文末尾出现的角色权重更高
if context_before:
    last_50_chars = context_before[-50:]  # 末尾 50 字
    reweighted = []
    for name, reason, confidence in candidates:
        # 如果在 context_before 末尾出现，增加权重
        if name in last_50_chars:
            confidence = min(confidence + 0.10, 0.95)
            reason = f'{reason}(近因)'
        
        # 如果能从旁白中直接找到这个人的说话动词
        # （如"林雪冷喝"→林雪在旁白末尾出现且有说话动词）
        if re.search(rf'{re.escape(name)}(?:说道|道|说|问|答|冷喝|喝道|冷笑)', 
                     context_before[-80:]):
            confidence = min(confidence + 0.08, 0.95)
            reason = f'{reason}(近因+话动)'
        
        reweighted.append((name, reason, confidence))
    
    # 按 confidence 降序重排
    reweighted.sort(key=lambda x: -x[2])
    return reweighted
```

**关键原则**:
- 近因权重只增加，不降低已有结果（避免修复 A 破坏 B）
- 近因窗口不超过 80 字
- "话动特征"（名字 + 说话动词）作为近因的额外证据，不加也不减
