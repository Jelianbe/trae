## 改动 1：句子拆分 + 竞争修复

### 目标
- 打开项目后只自动分析第1章并渲染句子拆分
- 其他章节点击后显示原文，不触发分析
- 点击"句子拆分"按钮才触发分析 + fragment 渲染
- 切换回已拆分的章节时保持拆分状态
- 修复异步竞争条件

### 涉及文件

| 文件 | 改动 |
|------|------|
| `frontend/js/store.js` | 新增 `splitChapters: {}` 状态 |
| `frontend/js/app.js` | 重写 `selectChapter`，新增 `_triggerSentenceSplit`，加 `_analysisGen` 计数器 |
| `frontend/js/views.js` | `renderSegments` 新增 `splitMode` 参数控制 fragment/原文渲染 |
| `frontend/index.html` | 改按钮文案，删除无用按钮 |
| `frontend/css/style.css` | 无改动 |

### 验收标准
- [x] 打开项目 → 只显示第1章内容，不自动分析
- [ ] 点击第1章 → 显示执行"句子拆分"提示
- [x] 对第1章点击"句子拆分"按钮 → 触发分析，完成后显示堆叠色条 + 悬停方框
- [x] 点击第2章 → 显示执行"句子拆分"提示，无分析等待
- [x] 对第2章点击"句子拆分"按钮 → 触发分析，完成后显示 fragment
- [x] 切回第1章 → 仍然显示 fragment（已拆分状态保持）
- [x] 快速连续点击第2章和第3章 → 不报"项目不存在"错误

## 改动 4：音频生成 — 卡片试听

### 目标
- 底部进度条显示整章音频生成进度（段覆盖率）
- 每张卡片显示生成状态（✓ 已生成 / □ 未生成）
- 点击卡片试听按钮 → 未生成的调 TTS 生成后播放，已生成的直接播放缓存
- 点击"生成音频"→ 按顺序遍历所有卡片，已生成的跳过，未生成的逐段生成
- 卡片上的标记在切章节后保留不丢失

### 涉及文件

| 文件 | 改动 |
|------|------|
| `frontend/js/store.js` | 新增 `ttsCache: {}`（`{segIndex: audioUrl}`），`ttsProgress: {done, total}` |
| `frontend/js/app.js` | 新增 `_ttsGenerateOne(segIndex)`，`_ttsPlayOne(segIndex)`，`_ttsGenerateAll()` |
| `frontend/js/views.js` | `renderSegments` 每张卡片底部加试听按钮 + 状态标记 |
| `frontend/index.html` | 音频列表区域删除，底部进度条改为覆盖率显示 |

### 验收标准
- [x] 点击卡片试听 → 未生成则调 TTS → 播放 → 卡片变为"试听"
- [x] 再次点击同一卡片试听 → 直接播放（不重复生成）
- [x] 点击"生成音频"→ 逐段生成未标记的卡片，已标记的跳过
- [x] 底部进度条显示 `生成中 12/85`
- [ ] 切章节后重新进入 → 已生成的卡片标记仍在（命中 TTS 缓存）

- 分析进度圆环不做句内粒度
