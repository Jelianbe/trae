## 一、错误类型分类体系

### 1.1 错误分级标准

| 等级 | 代码 | 说明 | 处理方式 |
|------|------|------|---------|
| **P0-严重** | `CRITICAL` | 流水线崩溃、数据丢失、服务不可用 | 立即终止，人工介入 |
| **P1-高** | `ERROR` | 单个模块失败、角色匹配错误 | 降级处理，记录日志 |
| **P2-中** | `WARNING` | 置信度不足、边界模糊 | 返回"未知"，继续流程 |
| **P3-低** | `INFO` | 调试信息、统计日志 | 仅记录，不影响流程 |

### 1.2 错误类型矩阵

```
按来源分类:
├── 输入错误 (InputError)
│   ├── 空文本
│   ├── 超长文本 (>100K 字符)
│   ├── 格式错误 (非 UTF-8)
│   └── 编码异常
│
├── 服务错误 (ServiceError)
│   ├── HanLP 连接失败
│   ├── TTS 服务超时
│   └── 数据库锁定
│
├── 业务错误 (BusinessError)
│   ├── 说话人匹配失败 → "未知"
│   ├── 情绪置信度不足 → 降级
│   ├── 角色合并冲突
│   └── 实体链接失败
│
├── 管道错误 (PipelineError)
│   ├── 模块级联失败
│   ├── 冷启动失败
│   └── 缓存溢出
│
└── 配置错误 (ConfigError)
    ├── 环境变量缺失
    ├── 参数越界
    └── 路径不存在
```

## 二、错误信息标准格式

### 2.1 日志格式规范

所有日志消息必须遵循以下格式：

```
[模块名] [级别] [操作描述] | 关键参数: 值 | 结果: 成功/失败 | 详情: 具体信息
```

**示例**:
```
[PipelineRunner] [INFO] 开始处理章节 | 章节ID: chapter_001 | 字数: 3245
[SpeakerMatcher] [WARNING] 说话人匹配失败 | 文本: "他冷冷地说道" | 降级: 未知
[EmotionExtractor] [INFO] 情绪提取完成 | 标签: anger | 置信度: 0.65 | 向量: [0.1,0.7,...]
[CharacterManager] [ERROR] 角色创建失败 | 名称: "张三" | 原因: IntegrityError
```

### 2.2 错误码定义

| 错误码 | 类型 | 消息模板 | 示例 |
|--------|------|---------|------|
| E-001 | 输入错误 | `输入文本为空` | `ValueError: 输入文本为空` |
| E-002 | 输入错误 | `输入文本超长 ({actual} > {limit} 字符)` | `ValueError: 输入文本超长 (150000 > 100000 字符)` |
| E-003 | 服务错误 | `HanLP 服务不可用: {url}` | `ConnectionError: HanLP 服务不可用: http://localhost:8080` |
| E-004 | 服务错误 | `TTS 请求超时 ({timeout}s)` | `Timeout: TTS 请求超时 (120s)` |
| E-005 | 服务错误 | `TTS 服务返回错误: {status} - {detail}` | `RuntimeError: TTS 服务返回错误: 500 - Internal Server Error` |
| E-006 | 业务错误 | `说话人匹配失败，返回"未知"` | `WARNING: 说话人匹配失败，文本="{text[:20]}..." → 未知` |
| E-007 | 业务错误 | `情绪置信度不足 ({score} < {threshold})` | `INFO: 情绪置信度不足 (0.15 < 0.25) → neutral` |
| E-008 | 业务错误 | `角色合并冲突: {primary} vs {secondary}` | `ValueError: 角色合并冲突: 张三 vs 张老三` |
| E-009 | 管道错误 | `冷启动失败: {reason}` | `ERROR: 冷启动失败: 角色画像构建超时` |
| E-010 | 配置错误 | `环境变量 {name} 未设置` | `KeyError: 环境变量 HANLP_SERVLET_URL 未设置` |

## 三、错误处理流程

### 3.1 流水线错误处理总流程

```
错误发生
    │
    ▼
┌─ 捕获异常 ─────────────┐
│ try/except 块捕获        │
│ 记录错误日志             │
└───────────┬────────────┘
            │
            ▼
┌─ 错误分级 ─────────────┐
│ P0 → 终止流水线          │
│   ├─ 状态设为 ERROR      │
│   ├─ 记录完整堆栈        │
│   └─ 重新抛出异常        │
│                          │
│ P1 → 降级处理            │
│   ├─ 标记模块失败         │
│   ├─ 使用默认值/未知      │
│   └─ 继续后续步骤        │
│                          │
│ P2 → 返回低置信度        │
│   ├─ 置信度降级           │
│   └─ 继续流程            │
│                          │
│ P3 → 仅记录             │
│   └─ 不影响流程          │
└───────────┬────────────┘
            │
            ▼
┌─ 恢复/回退 ─────────────┐
│ 成功恢复 → 记录恢复日志   │
│ 无法恢复 → 返回部分结果   │
└────────────────────────┘
```

### 3.2 各模块错误处理策略

| 模块 | 错误类型 | 处理策略 | 降级方案 |
|------|---------|---------|---------|
| **PipelineRunner** | 任意异常 | try/except/finally | 状态=ERROR，重抛异常 |
| **SpeakerMatcher** | NER 失败 | try/except | 降级到关键词匹配 |
| **SpeakerMatcher** | 临时角色注册失败 | try/except + warning | 跳过该角色，返回 None |
| **SpeakerMatcher** | 无匹配候选 | 返回 None | 返回"未知"标识符 |
| **DialogueBoundaryDetector** | 空文本/空引号 | 直接返回 | 非对话 (confidence=1.0) |
| **EmotionExtractor** | 无情绪信号 | 无异常 | 返回 neutral (confidence=0.0) |
| **CharacterManager** | DB IntegrityError | 捕获 + 回查 | 返回已存在角色 |
| **CharacterManager** | DB OperationalError | 捕获 + ALTER TABLE | 自动迁移表结构 |
| **EntityLinker** | 无匹配角色 | 无异常 | is_linked=False |
| **EntityCleaner** | 实体为空 | 无异常 | 返回空列表 |

#### E-CASE-001: 输入文本为空

- **严重程度**: P0-严重
- **触发条件**: 调用 `pipeline_runner.analyze_chapters("")` 或 `None`
- **错误信息**:
  ```
  ValueError: 输入文本为空
  ```
- **堆栈跟踪**:
  ```python
  File "pipeline/pipeline_runner.py", line 187, in analyze_chapters
      if not text:
          raise ValueError("输入文本为空")
  ```
- **根因分析**: 调用方未验证输入直接传入空字符串
- **处理流程**:
  ```
  analyze_chapters("")
      → if not text: raise ValueError
      → finally: self._state = PipelineState.ERROR
      → 异常传播到调用方
  ```
- **修复方案**: 调用方在调用前验证输入非空
- **复现步骤**:
  ```python
  from pipeline.pipeline_runner import get_pipeline_runner
  runner = get_pipeline_runner()
  runner.analyze_chapters("")  # 触发 ValueError
  ```
- **影响范围**: 流水线完全无法执行

---

#### E-CASE-002: HanLP 服务不可用

- **严重程度**: P1-高
- **触发条件**: HanLP 服务未启动或网络不可达
- **错误信息**:
  ```
  ConnectionError: 无法连接到 HanLP 服务: http://localhost:8080
  ```
- **处理流程**:
  ```
  analyze_with_hanlp(text)
      → requests.post(HANLP_SERVLET_URL, ...)
      → ConnectionError
      → logger.error("HanLP 服务不可用")
      → return None, "HanLP 服务不可用"
      → 调用方降级到规则匹配
  ```
- **降级方案**: SpeakerMatcher 使用关键词匹配替代 NER
- **修复方案**:
  1. 启动 HanLP 服务: `java -jar hanlp-servlet.jar`
  2. 检查服务地址: `echo $HANLP_SERVLET_URL`
  3. 测试连通性: `curl http://localhost:8080`
- **影响范围**: NER 分析完全失效，说话人识别降级到规则匹配

---

#### E-CASE-003: 说话人匹配失败（返回"未知"）

- **严重程度**: P2-中
- **触发条件**: 所有匹配策略均无候选
- **日志信息**:
  ```
  [SpeakerMatcher] [WARNING] 说话人匹配失败，无候选角色 | 文本: "......"
  ```
- **处理流程**:
  ```
  match_speaker(context)
      → 上下文推理: 无候选
      → 说话人提示词: 无匹配
      → 代词消解: 无代词
      → 角色库匹配: 无匹配
      → 语义排序: 已禁用
      → 触发词匹配: 无触发
      → return None
      → 调用方返回 speaker="未知"
  ```
- **后续处理**: 保持"未知"，等待冷启动回填或人工标注
- **影响范围**: 该句说话人为"未知"，TTS 无法分配角色音色

---

#### E-CASE-004: 角色创建冲突

- **严重程度**: P1-高
- **触发条件**: 并发创建同名角色
- **错误信息**:
  ```
  sqlite3.IntegrityError: UNIQUE constraint failed: characters.name, characters.project_id
  ```
- **处理流程**:
  ```
  add_character(name, project_id)
      → INSERT INTO characters (name, project_id, ...)
      → IntegrityError (唯一约束冲突)
      → conn.rollback()
      → 回查已存在角色: SELECT * FROM characters WHERE name=? AND project_id=?
      → return existing_character
  ```
- **修复方案**: 使用 `find_or_create()` 替代 `add_character()`，自动处理冲突
- **影响范围**: 不会导致数据丢失，自动返回已存在角色

---

#### E-CASE-005: TTS 服务超时

- **严重程度**: P0-严重
- **触发条件**: Index-TTS 服务响应超过 120 秒
- **错误信息**:
  ```
  RuntimeError: Index-TTS 请求超时 (120s) - 文本可能过长或服务过载
  ```
- **处理流程**:
  ```
  generate_audio(text, timeout=120)
      → requests.post(..., timeout=120)
      → Timeout
      → raise RuntimeError("Index-TTS 请求超时 (120s) - 文本可能过长或服务过载")
  ```
- **修复方案**:
  1. 检查文本长度，超长文本需分段
  2. 检查 TTS 服务状态: `curl http://localhost:8300/health`
  3. 重启 TTS 服务
  4. 增加超时: `IndexTTSEngine(timeout=300)`
- **影响范围**: 当前音频生成失败，不影响其他句子

---

#### E-CASE-006: 冷启动失败

- **严重程度**: P2-中
- **触发条件**: 冷启动阶段角色画像构建超时或异常
- **日志信息**:
  ```
  [PipelineRunner] [ERROR] 冷启动失败: 角色画像构建超时 | 章节ID: chapter_003
  ```
- **处理流程**:
  ```
  _process_chapter(...)
      → if 累积字数 >= 3000:
      →     try: build_cold_start_portraits()
      →     except TimeoutError:
      →         logger.error("冷启动失败: 角色画像构建超时")
      →         # 不阻塞主流程
      →         pass
      → 继续处理后续章节
  ```
- **影响范围**: 未知说话人无法回填，但不影响后续章节处理

---

#### E-CASE-007: 情绪置信度不足

- **严重程度**: P3-低
- **触发条件**: 所有情绪信号得分 <= UNKNOWN_SCORE_THRESHOLD (0.15)
- **日志信息**:
  ```
  [EmotionExtractor] [INFO] 情绪置信度不足 (0.12 < 0.15) → 返回 unknown
  ```
- **处理流程**:
  ```
  classify(text)
      → 多信号打分: 脏话=0, 副词=0.05, 标点=0.02, ...
      → max_score = 0.12
      → if max_score <= UNKNOWN_SCORE_THRESHOLD:
      →     return EmotionResult(label="unknown", confidence=0.0)
  ```
- **影响范围**: 该句情绪为"unknown"，TTS 使用中性语气

---

#### E-CASE-008: 数据库迁移失败

- **严重程度**: P1-高
- **触发条件**: 升级数据库 schema 时字段已存在
- **错误信息**:
  ```
  sqlite3.OperationalError: duplicate column name: vector
  ```
- **处理流程**:
  ```
  _migrate_database()
      → try: ALTER TABLE characters ADD COLUMN vector BLOB
      → except OperationalError as e:
      →     if "duplicate column" in str(e):
      →         pass  # 已存在，跳过
      →     else:
      →         raise
  ```
- **修复方案**: 自动处理，无需人工介入
- **影响范围**: 无，数据库已处于最新 schema

### 4.3 错误处理最佳实践

| 场景 | 正确做法 | 错误做法 |
|------|---------|---------|
| 模块失败 | try/except + 降级 + 日志 | 让异常传播导致流水线崩溃 |
| 置信度不足 | 返回"未知" + 低置信度 | 猜测一个角色 |
| 服务不可用 | 降级到本地规则 | 无限重试/阻塞等待 |
| 数据冲突 | 回查已有数据 + 合并 | 直接覆盖/报错退出 |
| 配置缺失 | 使用默认值 + WARNING | 崩溃退出 |
| 冷启动失败 | 跳过 + 继续 | 终止整个流水线 |
