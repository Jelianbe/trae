## 一、现状分析

### 1.1 当前架构

```
AI执行工作流_算法迭代标准手册.md
├── 第-1步：优先级裁定（通用）
├── 第0步：快照备份（通用）
├── 第1步：假设模板 + 入口判断（**算法特定**）
├── 第2步：v7.0合规检查（**算法特定**）
├── 第3步：基线锁定（**算法特定**）
├── 第4步：执行改动（通用）
├── 第5步：验证（**算法特定**）
├── 第5.5步：过拟合检查（**算法特定**）
└── 第6步：决策矩阵（通用）
```

### 1.2 问题

| 问题 | 表现 | 后果 |
|------|------|------|
| **类型耦合** | 9 步中 4 步绑定算法迭代 | Bug 修复要填可证伪条件，配置调优要跑基线 |
| **硬编码比例高** | 类型特定步骤 4/4 = 100% | 新增任务类型必须改主文档，不敢加 |
| **单一文档过重** | ~400 行融合 3 个来源 | 读一遍要 10 分钟，AI 容易跳步 |
| **无表单注册** | 所有类型共用同一模板 | 入口判断填的字段对某些类型不适用 |

### 1.3 基线指标

| 指标 | 改前值 | 目标值 |
|------|:------:|:------:|
| 支持任务类型数 | 2（算法迭代 + 批量代码治理） | **5** |
| 通用步骤占比 | 3/9（33%） | **≥ 5/9（55%）** |
| 类型特定步骤 | 4（硬编码） | **≤ 3（表单驱动）** |
| 单篇文档可读时间 | ~10 分钟 | **≤ 5 分钟** |

```
│  docs/优化项表单/                                       │
│  ├── 🧪 算法迭代.md（含假设模板+v7.0检查+基线+过拟合）   │

│  .trae/rules/R-021-AI执行工作流.md                      │
│  └── 入口检查 → 判定优化项类型 → 加载对应表单          │
└────────────────────────────────────────────────────────┘
```

### 2.2 执行路径设计

```
每种优化项类型的执行路径都由两部分组成：

通用骨架步骤（恒走） + 优化项特定的步骤（按类型决定）

算法迭代:   -1,0 → [1,2,3],4,[5,5.5],6    = 9步（不变）
配置调优:   -1,0 → [1],4,[5],6            = 6步（减3步）
Bug修复:    -1,0 → [1],4,[5],6            = 6步（减3步，跳过基线+过拟合）
模块集成:   -1,0 → [1],4,[5],6            = 6步（减3步）
架构重构:   -1,0 → [1,2],4,[5],6          = 7步（跳过基线+过拟合，保留v7.0）

# 方括号[]内的步骤是"类型特定"的，由对应表单定义
```

### 2.3 关键设计决策

| 决策 | 选项 | 选择 | 理由 |
|------|------|:----:|------|
| 表单格式 | Markdown / JSON / YAML | **Markdown** | AI 最擅长读写，人类也可审核 |
| 表单存储 | 嵌入骨架 / 独立文件 | **独立文件** | 新增类型只需加文件，不改骨架 |
| 表单注册方式 | 自动扫描 / 手动注册 | **R-021 规则文件中写死枚举** | 自动扫描不可控，写死更安全 |
| 步骤执行顺序 | AI 自行解读 / 表单明确定义 | **表单明确定义路径** | 避免 AI 跳步或漏步 |

## 三、表单格式定义

### 3.1 通用表单模板

每种优化项表单遵循统一的结构：

```markdown
# 优化项表单：[类型名]

## 基本信息
- **类型标识**: [枚举值，如 algorithm_iteration]
- **执行路径**: [步号列表，如 -1,0,1,2,3,4,5,5.5,6]
- **跳过步骤**: [跳过的步号列表]

## 第1步模板（入口判断）
[该类型对应的填写模板]

## 第2步模板（合规检查，可选）
[该类型的检查清单，没有则填"无"]

## 第3步模板（基线锁定，可选）
[该类型的基线测量方式和示例命令，没有则填"无"]

## 第5步模板（验证，可选）
[该类型的验证方式和示例命令]

## 第5.5步模板（泛化检查，可选）
[该类型的泛化检查方式，没有则填"无"]

## 验收标准
[该类型的 DoD 清单]
```

### 3.2 五种表单设计

#### 表单 A：🧪 算法迭代 `algorithm_iteration`

| 字段 | 值 |
|------|----|
| 执行路径 | -1,0,1,2,3,4,5,5.5,6（9步） |
| 跳过步骤 | 无 |

**第1步模板**: 假设模板 H（含可证伪条件），与当前 v2.0 版完全相同  
**第2步模板**: v7.0 7项原则自查清单  
**第3步模板**: 分布拆解基线命令（含按挑战类型+文体）  
**第5步模板**: 同一基线命令  
**第5.5步模板**: 留出集方向检查（每3轮）  
**验收标准**: 
- 基线 ≥ 阈值 → 接受
- 各题材不降 → 接受
- 留出集方向一致 → 通过

#### 表单 B：⚙️ 配置调优 `config_tuning`

| 字段 | 值 |
|------|----|
| 执行路径 | -1,0,1,4,5,6（6步） |
| 跳过步骤 | 2（合规检查），3（基线锁定），5.5（过拟合检查） |

**第1步模板**: 参数变更表

```markdown

| 参数 | 改前值 | 改后值 | 理由 |
|------|:------:|:------:|------|

## 影响范围

- 回退条件: [什么情况下回退]
```

**第5步模板**: 性能基准对比

```bash
# 改前耗时
python -c "模块调用"  # 记录耗时

python -c "模块调用"  # 记录耗时
```

**验收标准**:
- 功能无退化（已有测试全部通过）
- 性能不降或按预期变化
- 无新硬编码违规

#### 表单 C：🐛 Bug 修复 `bug_fix`
