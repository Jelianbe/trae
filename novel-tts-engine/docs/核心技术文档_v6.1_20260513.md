## 一、项目概述

### 1.1 项目目标

构建一个面向中文网文（修仙/都市/西方奇幻等多文体）的**对话说话人识别引擎**，实现：
- 从非结构化文本中提取对话内容
- 识别每句对话的说话人
- 支持角色库管理、别名匹配、临时角色创建
- 准确率目标：≥74%（预创建角色库场景）

### 1.2 技术栈

| 组件 | 技术选型 |
|------|---------|
| NER/分词 | HanLP (via `nlp_basics.py`) |
| 角色存储 | SQLite (via `character_manager.py`) |
| 语义排序 | Sentence-BERT (via `semantic_ranker.py`) |
| 框架 | 纯 Python，无外部 Web 框架依赖 |
| 测试 | pytest + 自定义评估脚本 |

### 1.3 目录结构

```

  ↓

[4] 上下文多样性验证
  ↓
[5] 说话人候选人生成 (_extract_context_speakers)
  ├── 代词消解
  ├── NER PER 提取 + 被动过滤
  ├── 角色库直接匹配（语言学规则）
  ├── 描述性角色提取
  ├── 自称推断
  └── 旁白兜底匹配
  ↓
[6] 角色匹配 (角色库精确/别名/临时)
  ↓
[7] 情绪提取
  ↓
[8] 输出结果
```

## 三、实体清洗算法 (EntityCleaner)

### 3.1 模块职责

**来源**：从 `speaker_matcher.py` 和 `nlp_basics.py` 抽取的实体清洗逻辑  
**设计原则**：无状态、参数化、独立性  
**输入契约**：原始实体列表 + 原文文本  
**输出契约**：干净实体列表（已扩展、已修剪、已过滤非人实体）

### 3.2 处理流程

```python
def clean(entities, raw_text):
    cleaned = entities
    cleaned = _expand_surname_entities(raw_text, cleaned)    # 1. 复姓扩展
    cleaned = _expand_single_char_entities(raw_text, cleaned) # 2. 单字扩展
    cleaned = _trim_overextended_entities(cleaned)            # 3. 过扩展修剪
    cleaned = [e for e in cleaned if _is_clean_per_entity(e)] # 4. 干净度过滤
    return cleaned
```

### 3.3 子算法详解

#### 3.3.1 复姓扩展 (`_expand_surname_entities`)

**问题**：HanLP 对复姓（纳兰、慕容、欧阳等）可能只提取姓氏部分，如"纳兰嫣然"→"纳兰"。

**算法**：
```
1. 定义 33 个常见复姓（来源：《中国姓氏大辞典》）
2. 对每个复姓，正则匹配：复姓 + 2~3 个中文字
3. 如果匹配到，替换原单姓实体为完整名
4. 排除：最后一个字是动词的情况（如"纳兰走"→"纳兰"）
```

**复姓词表**（33个）：
```
纳兰, 慕容, 欧阳, 上官, 司马, 诸葛, 夏侯, 皇甫, 尉迟, 公孙,
轩辕, 令狐, 东方, 司徒, 鲜于, 端木, 澹台, 公冶, 宗政, 濮阳,
淳于, 单于, 太叔, 申屠, 仲孙, 钟离, 长孙, 宇文, 万俟, 闻人,
赫连, 独孤
```

**边界**：仅处理常见复姓，不尝试处理罕见复姓。

#### 3.3.2 单字扩展 (`_expand_single_char_entities`)

**问题**：HanLP 可能将双字角色名拆成单字，如"药老"→"药"。

**算法**：
```
1. 检测单字 PER 实体（在 SINGLE_CHAR_SURNAMES 集合中）
2. 在 raw_text 中取该单字后一个字符
3. 若后字符是中文字符（\u4e00-\u9fff），则组合为新实体
4. 下游 speaker_matcher 会做角色库匹配验证
```

**注意**：不在这里查角色库（NER 阶段角色库可能未初始化），而是做通用拼接，让下游过滤无效组合。

#### 3.3.3 过扩展修剪 (`_trim_overextended_entities`)

**问题**：HanLP 可能将过长的文本识别为一个 PER 实体，如"郭垣正"（应为"郭垣"）。

**算法**：
```
1. 检测长度 >= 3 的 PER 实体
2. 尝试从左侧截取 2 字、3 字，检查是否在角色库中
3. 若找到匹配，替换为角色库中的标准名
4. 若无匹配，保留原实体
```

**边界**：仅修剪明显过长的实体，不修改正常人名。

#### 3.3.4 干净度过滤 (`_is_clean_per_entity`)

**问题**：NER 可能提取带修饰词的短语作为 PER 实体，如"一个白发老者"。

**过滤规则**：
```python
# 规则1: 数量词开头
^[一二三四五六七八九十百千万两\d]+[个位只名]

# 规则2: 修饰词模式
^[一两].{2,3}[白发黑袍高大年轻古老英俊丑陋]
^.{0,2}身穿.{0,2}[袍衣甲衫]
^.{0,2}高大.{0,2}身影
^.{0,2}年轻.{0,2}

# 规则3: 长度过滤
len(text) > 6 → False

# 规则4: 方位词开头
^(黑暗中|门外|远处|近处|角落里|窗前|床边|桌前)
```

## 四、说话人匹配算法 (SpeakerMatcher)

### 4.1 候选人生成流程 (`_extract_context_speakers`)

**输入**：对话文本 + 上文 + 下文  
**输出**：候选人列表 `[(名字, 来源, 置信度)]`

#### 步骤1：代词消解

```python
# 优先处理代词（他/她/它/你/我），因为代词比描述性短语更可靠
if context_before:
    pronoun_result = _resolve_pronoun_in_context(context_before)
    # 使用局部窗口（最近说话人 + 活跃度）解析代词
```

#### 步骤2：NER 提取 PER 实体 + 被动动作主体过滤

```python
# 被动动作主体过滤：排除"X点头/照做/回应/沉思/喃喃"中的X
# 这些X是被对话方，不是说话人
passive_patterns = [
    r'([\u4e00-\u9fa5]{2,4})点[头首]',
    r'([\u4e00-\u9fa5]{2,4})照做',
    r'([\u4e00-\u9fa5]{2,4})点头',
    r'([\u4e00-\u9fa5]{2,4})回应',
    r'([\u4e00-\u9fa5]{2,4})回答',
    r'([\u4e00-\u9fa5]{2,4})沉思',
    r'([\u4e00-\u9fa5]{2,4})喃喃',
]

# NER 提取 → 实体清洗 → 过滤被动主体 → 角色库匹配
result = nlp.analyze(context_before)
before_pers_cleaned = entity_cleaner.clean(result.entities, raw_text=context_before)
for pe_text in before_pers_cleaned:
    if pe_text in passive_subjects:
        continue  # 跳过被对话方
    char = _match_candidate_to_character(pe_text, context_before)
    candidates.append((char.name, '上下文PER(前)', confidence))
```

#### 步骤3：角色库直接匹配（语言学规则）

**来源**：现代汉语句法结构（主谓宾）+ 网文直接引语引导模式统计  
**影响**：P7/P10/P15/P18等段落，约5.5%准确率

```python
for char in project_chars:  # 按名字长度降序排列
    name = char.name
    for ctx_text, ctx_label in [(context_before, '前'), (context_after, '后')]:
        # 规则1: 声音指示（"XXX的声音/传音/在脑海中响起"）
        if re.search(r'的声音|在脑海|心中|传音', after_name):
            candidates.append((name, '声音指示', 0.90))
            break
        
        # 规则2: 说话动词（"道/说道/问/答道/笑道/沉声道"等）
        if re.search(r'道|说道|问|答道|喊|叫|笑道|沉声道|冷冷道|淡淡道', after_name):
            candidates.append((name, '说话动词', 0.88))
            break
        
        # 规则3: 复合说话（"摇头道/点头道/叹息道"等）
        if re.search(r'(?:摇头|点头|叹息)[道说问]', after_name[:8]):
            candidates.append((name, '复合说话', 0.85))
            break
        
        # 规则4: 冒号主语（"XXX："格式，排除"看向XXX："）
        if re.search(r'[：:]', after_name[:8]) and not re.search(r'看向|看着|望着', before_name):
            candidates.append((name, '冒号主语', 0.85))
            break
        
        # 规则5: 动作暗示（句首或句号后 + 动作描述）
        if pos <= 2 and re.search(r'飘出|走出|走来|站起身|摇了摇头|叹了口气', effective_ctx):
            candidates.append((name, '动作暗示', 0.75))
            break
```

#### 步骤4：描述性角色提取

```python
# 从上下文中提取描述性角色（如"白发老者"、"黑衣骑士"）
descriptive_roles = role_extractor.extract(context_before)
for role in descriptive_roles:
    char = _match_candidate_to_character(role, context_before, skip_speech_check=True)
    candidates.append((char.name, '描述性角色', 0.80))
```

#### 步骤5：自称推断

```python
# 检测自称模式（"我是XX"、"在下XX"等）
self_ref_candidates = self_ref_inferrer.infer(text, context_before)
for name, reason, confidence in self_ref_candidates:
    char = _match_candidate_to_character(name, text)
    candidates.append((char.name, f'自称推断({reason})', 0.80))
```

#### 步骤6：上下文 after 的 NER 提取

```python
# 对下文做相同的 NER → 清洗 → 匹配流程
result = nlp.analyze(context_after)
after_pers_cleaned = entity_cleaner.clean(result.entities, raw_text=context_after)
for pe_text in after_pers_cleaned:
    char = _match_candidate_to_character(pe_text, context_after)
    candidates.append((char.name, '上下文PER(后)', 0.75))
```

#### 步骤7：兜底匹配

```python
# 如果没有任何候选，尝试从旁白中提取
if not candidates:
    narration = _extract_narration(context_before, context_after)
    char_match = _match_from_character_library(narration)
    if char_match:
        candidates.append((char_match.name, '角色库旁白匹配', 0.70))
```

## 五、角色管理器 (CharacterManager)

### 5.1 职责

- 角色 CRUD（增删改查）
- 别名管理（一个角色可有多别名）
- 性别推断（基于名字和上下文）
- 角色锁定（用户确认后不可被自动修改）
- 临时角色（未确认的新角色，标记为 `is_temporary=True`）

### 5.2 数据库 Schema

```sql
-- 角色表
CREATE TABLE characters (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    project_id TEXT DEFAULT '',
    aliases TEXT DEFAULT '[]',
    gender TEXT DEFAULT 'unknown',
    first_appearance INTEGER,
    is_locked INTEGER DEFAULT 0,
    is_temporary INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 索引
CREATE INDEX idx_project ON characters(project_id);
CREATE UNIQUE INDEX idx_name_project ON characters(name, project_id);
```

### 5.3 核心方法

| 方法 | 说明 |
|------|------|
| `add_character(name, project_id, aliases, gender)` | 创建角色 |
| `get_character_by_name(name, project_id)` | 按名查找 |
| `get_character_by_alias(alias, project_id)` | 按别名查找 |
| `find_or_create(name, project_id, context, min_confidence)` | 查找或创建 |
| `merge_characters(primary_id, secondary_id)` | 合并角色 |
| `lock_character(char_id, project_id)` | 锁定角色 |
| `infer_gender(name, context)` | 性别推断 |

### 5.4 单例模式

```python
_character_manager: Optional[CharacterManager] = None
_character_manager_lock = threading.Lock()

def get_character_manager(db_path=None) -> CharacterManager:
    """获取或创建全局角色管理器实例（线程安全，双重检查锁）"""
    global _character_manager
    if _character_manager is None:
        with _character_manager_lock:
            if _character_manager is None:
                _character_manager = CharacterManager(db_path)
    return _character_manager
```

## 六、项目规则体系

### R-001: 原子化与状态管理

**规则**：任务必须是不可再分的原子操作。每个任务只做一件事，完成即标记。

**实践**：
- 每个管道模块只做一种处理（NER/清洗/匹配/过滤）
- `SpeakerMatcher` 的 `_extract_context_speakers` 拆分为 7 个步骤，每步独立

### R-002: 依赖锁定机制

**规则**：启动任务时检查上游依赖。依赖未就绪时阻塞启动。

**实践**：
- `EntityCleaner` 构造函数检查 `CharacterManager` 是否可用
- `PipelineRunner.__init__` 按依赖顺序初始化各模块

### R-003: 里程碑节点管理

**规则**：阶段结束时设置里程碑。记录达成状态、日期、备注。

**实践**：
- 每个版本发布时记录里程碑（如 v4 2026-05-10 准确率76.4%）
- 每个重构完成时更新里程碑

### R-004: 准出标准 (DoD)

**规则**：每个阶段开始前都必须定义完成标准。DoD 必须包含至少 3 条可验证标准。

**DoD 质量标准**（SMART 原则）：
- **S**pecific（具体的）
- **M**easurable（可测量的）
- **A**chievable（可实现的）
- **R**elevant（相关的）
- **T**ime-bound（有时限的）

**示例 DoD**：
1. `pytest tests/` 全部通过
2. `sqlite3 novel_tts.db ".schema"` 输出的表结构与设计文档一致
3. 启动 app.py，上传测试文件后，前端无报错，显示正确的分章数和词性标签
4. 模拟断网环境，重复测试，功能完全正常

### R-005: 全流程文档化 — 逻辑解释

**规则**：关键算法和数据结构必须有注释或决策记录。

**实践**：
- 每个方法都有 docstring 说明来源、边界、维护者
- 每个正则模式都有注释说明语言学依据
- 每次重大改动都有决策记录

### R-006: 全流程文档化 — Bug 调试记录

**规则**：调试超过 15 分钟的 Bug 必须记录。

**Bug 记录模板**：
- 日期、严重程度、影响范围
- Bug 现象
- 定位过程
- 最终原因
- 修复方案
- 预防措施

### R-007: 双向绑定

**规则**：需求文件 requirements.md 和任务文件 TASKS.md 通过编号互相引用。

**编号格式**：`BR-XXX`（需求）、`T-XXX`（任务）

### R-008: 文档同步准则

**规则**：代码逻辑变更时同步更新文档。

**实践**：
- 每次代码修改时检查相关文档是否需要更新
- 算法改动时更新对应算法文档

### R-009: 变更流程管理

**规则**：新增需求必须生成变更提案。

**变更提案模板**：
- 需求描述
- 需求类型
- 插入位置

### R-010: 过程可见

**规则**：复杂操作前说明意图和预期产出。

### R-011: 用户主权

**规则**：用户拥有所有决策的最终否决权。用户说"停止"、"错了"、"换方法"时，AI 必须立刻停止并切换为咨询模式。

### R-012: 最小化范围

**规则**：严禁顺手优化式修改。只做被要求做的事。

### R-013: 记忆强化

**规则**：阶段结束时生成小结。

### R-014: 假设驱动开发

**规则**：算法改动前填写假设模板。

**假设模板**：
- 改动内容（一句话说清）
- 影响机制（因果推理）
- 预期效果（指标、基线、目标）
- 验证方式

**决策矩阵**：

| 情况 | 决策 |
|------|------|

| 目标未达成，基线不降 | ⚠️ 拒绝，记录教训 |
| 目标未达成，基线也降了 | ❌ 立即回退 |

## 八、模块化重构记录

### 8.1 重构原因

`speaker_matcher.py` 承担了三层职责：
1. 实体清洗（姓氏扩展、过扩展修剪、PER过滤）
2. 候选人提取（从上下文提取NER实体并排序）
3. 角色匹配（把候选人匹配到角色库）

导致每次修改实体问题都牵连排序和匹配逻辑。

### 8.2 重构方案

**新增模块**：`pipeline/entity_cleaner.py`

| 方法 | 来源 | 职责 |
|------|------|------|
| `_expand_surname_entities` | speaker_matcher.py | 复姓扩展（33个复姓） |
| `_trim_overextended_entities` | speaker_matcher.py | 过扩展修剪 |
| `_is_clean_per_entity` | speaker_matcher.py | PER实体干净度检查 |
| `_expand_single_char_entities` | nlp_basics.py | 单字PER向后拼接 |

**修改文件**：
- `speaker_matcher.py` — 删除3个方法，替换为 `entity_cleaner.clean()` 调用
- `nlp_basics.py` — 删除单字扩展方法，回归纯 HanLP 调用
- `pipeline_runner.py` — 初始化 `EntityCleaner` 并注入 `SpeakerMatcher`

### 8.3 重构后架构

```
pipeline/
├── nlp_basics.py          # 纯 HanLP 调用
├── entity_cleaner.py      # 新增：实体清洗层
├── speaker_matcher.py     # 候选人生成 + 角色匹配
├── character_manager.py   # 角色 CRUD
└── pipeline_runner.py     # 管道编排
```

### 8.4 遗留问题

1. 准确率下降约 1.4%（74.0% → 72.6%），可能原因：
   - `entity_cleaner.clean()` 新增了单字扩展和修剪，改变了原来 NER 行为
   - 某些候选人生成/过滤的边缘情况有细微差异
2. 修仙传领域适配不足：
   - 说话动词列表不完整（缺少"传音"、"意念传递"等）
   - 家族名（如"林家"）被 NER 误识别为 PER
   - DIALOGUE_PATTERNS 过度匹配（内心独白、地名引用）

### 8.5 备份文件清理

已删除：
- `pipeline/speaker_matcher.py.backup_before_rollback`
- `pipeline/speaker_matcher_v4_backup.py`
