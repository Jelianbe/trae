## 第 0 步：快照备份（先存再改）

**做什么**：在一切改动开始前，创建一个带时间戳的项目全量快照。这个快照是**回退的唯一凭证**——改动失败时，不需要反向修改代码，直接恢复整个备份目录即可。

**为什么是第 0 步**：备份和实验无关——不验证假设、不依赖基线、不涉及决策。它是所有改动的**前置条件**，所以放在第 1 步之前。

### 执行

```powershell
# 一行命令，自动生成带时间戳的备份
$src = "d:\trae\novel-tts-engine"
$date = Get-Date -Format "yyyyMMdd_HHmmss"
$dst = "d:\trae\backup_novel-tts-engine_$date"
New-Item -ItemType Directory -Path $dst -Force | Out-Null
Get-ChildItem -Path $src | Where-Object {
    $_.Name -notin @('__pycache__', '.git', 'venv', '.venv', 'node_modules',
                     '.pytest_cache', '__pycache__')
} | ForEach-Object {
    Copy-Item -Recurse -Path $_.FullName -Destination "$dst\$($_.Name)" -Force
}
Write-Host "备份完成: $dst"
```

### 结果记录

备份完成后，将备份路径写入假设模板的头部：

```markdown
## 备份信息
- **备份路径**: d:\trae\backup_novel-tts-engine_YYYYMMDD_HHmmss
- **回退命令**: Copy-Item -Recurse "$dst\*" "d:\trae\novel-tts-engine\" -Force
```

### 回退流程

当第 6 步决策为"回退"时：

```powershell
# 从备份恢复
$backup = "d:\trae\backup_novel-tts-engine_YYYYMMDD_HHmmss"
Copy-Item -Recurse "$backup\*" "d:\trae\novel-tts-engine\" -Force
Write-Host "已从 $backup 恢复"
```

**完成回退后**：在基线记录中注明"回退到备份 YYYYMMDD_HHmmss"。

## 第 2 步：v7.0 合规检查

**做什么**：检查改动是否违反 v7.0 的 7 项核心原则。

### 7 项原则自查清单

```
□ 原则1（通用规则优先 / 单一权威源）
  - 问：是否依赖静态词表？是否同一数据在多地维护？
  - 检查：新集合有来源注释吗？有单一权威源吗？
  - 禁止：新增 A→B 业务映射表

□ 原则2（不猜 / Unknown 优于误判）
  - 问：证据不足时，系统输出什么？"未知"路径保留了吗？
  - 黄金法则：不确定时返回 None，绝不猜

□ 原则3（匹配精度约束）
  - 问：是否用了 in / startswith 等子串匹配？
  - 检查：关键词匹配改为精确匹配或基于句法位置的匹配

□ 原则4（回归测试 / 基准锁定）
  - 问：改动前记录基线了吗？改后跑同一测试了吗？

□ 原则5（决策权隔离 / 模块职责单一）
  - 问：是否在一个模块中做了另一个模块的决策？
  - 边界：
    - entity_cleaner：可读角色库（修剪判断）但不可做匹配决策
    - nlp_basics：只做 HanLP 调用，不做实体后处理
    - speaker_matcher：只做说话人匹配，不做情感分析

□ 原则6（频率层级）
  - 问：是否涉及角色重要性判断？层级结构是否符合四层？

□ 原则7（修复位置对）
  - 问：是否在正确的位置修复了问题？
  - 对照：
    - NER 实体增强/过滤 → entity_cleaner.py
    - 说话动词定义 → speech_verb_detector.py
    - 上下文推理 → speaker_matcher.py
    - 说话人匹配决策 → speaker_matcher.py
```

### 违规处理

| 检查结果 | 处理 |
|---------|------|
| 全部合规 | ✅ 继续第 3 步 |
| 原则2 或 原则5 违规 | ❌ **必须重新设计**，不能跳过 |
| 其他原则违规 | ⚠️ 记录违规原因，评估是否可接受为技术债务 |

## 第 3 步：基线锁定（分布拆解版）

**做什么**：记录改动前的准确率——不是只有一个数字，而是**按挑战类型和文体拆解**。

**执行**（以说话人识别为例）：

```bash
python -c "
import sys, json
sys.path.insert(0, '.')
from collections import defaultdict
from pipeline.speaker_matcher import SpeakerMatcher
from pipeline.speaker_matcher_interface import DialogueContext
from pipeline.character_manager import CharacterManager

data = json.load(open('tests/role_emotion_gt_100.json', encoding='utf-8'))
solvable = [d for d in data if d['speaker'] != '未知' and not d['speaker'].startswith('未知')]

cm = CharacterManager()
all_names = set()
for d in solvable:
    all_names.add(d['speaker'])
    for m in d.get('mentioned', []): all_names.add(m)
for name in all_names:
    gender = next((d.get('speaker_gender', 'male') for d in solvable if d['speaker'] == name), 'male')
    cm.add_character(name, gender, 'benchmark')
for char in cm.get_all_characters('benchmark'):
    cm.lock_character(char.id, 'benchmark')

matcher = SpeakerMatcher(cm)
matcher.current_project_id = 'benchmark'

results = []
for d in solvable:
    ctx = DialogueContext(text=d['text'], speaker_hint=None,
        prev_speaker=None, mentioned_characters=d.get('mentioned', []),
        chapter_id=None,
        context_before=d.get('context_before', ''),
        context_after=d.get('context_after', ''))
    r = matcher.match_speaker(ctx)
    correct = r and r.character and r.character.name == d['speaker']
    mt = r.match_type if r else 'none'
    results.append((d, correct, mt))

total = len(results)
correct_count = sum(1 for _, c, _ in results if c)

# 按挑战类型拆解
by_type = defaultdict(lambda: {'c':0,'t':0})
for d, c, mt in results:
    challenge = d.get('role_challenge', mt)
    by_type[challenge]['t'] += 1
    if c: by_type[challenge]['c'] += 1

print(f'BASELINE:{correct_count}/{total}={correct_count/total*100:.1f}%')
print()
print('按挑战类型:')
for t in sorted(by_type.keys(), key=lambda x: -by_type[x]['t']):
    info = by_type[t]
    pct = info['c']/info['t']*100 if info['t'] else 0
    print(f'  {t:30s} {info[\"c\"]:2d}/{info[\"t\"]:2d} = {pct:.0f}%')

# 按文体拆解（如果 GT 有 genre 字段）
genres = set(d.get('genre') for d, _, _ in results if d.get('genre'))
if genres:
    by_genre = defaultdict(lambda: {'c':0,'t':0})
    for d, c, _ in results:
        g = d.get('genre', '未知')
        by_genre[g]['t'] += 1
        if c: by_genre[g]['c'] += 1
    print()
    print('按文体:')
    for g in sorted(by_genre.keys()):
        info = by_genre[g]
        pct = info['c']/info['t']*100 if info['t'] else 0
        print(f'  {g:8s} {info[\"c\"]:2d}/{info[\"t\"]:2d} = {pct:.0f}%')
" 2>&1
```

## 第 5.5 步：过拟合检查（新增，每3轮执行一次）

**为什么**：多轮迭代后，AI 会隐式"学会"测试集的分布特征。V2 版本在 198 条自建测试集上 +15% 但在独立 GT 上 -2% 就是血淋淋的教训。这个步骤就是为了防止重蹈覆辙。

**做什么**：用一个**完全不参与开发**的留出集做方向检查。

**准备留出集**：

1. 从 GT 测试集中随机抽取 20%（10-15 条），标记为"留出集"
2. 留出集**禁止用于任何决策**——不改代码、不调阈值、不参考结果做判断
3. 仅用于方向检查：改前改后各跑一次，看方向是否一致

**执行**：

```bash
# 改前
python -c "
import json, random
# 从 100 条中抽出 15 条作为留出集
data = json.load(open('tests/role_emotion_gt_100.json'))
random.seed(42)
held_out = random.sample(data, 15)
with open('tests/held_out_set.json', 'w') as f:
    json.dump(held_out, f, ensure_ascii=False)
# 剩下的作为开发集
remaining = [d for d in data if d not in held_out]
with open('tests/dev_set.json', 'w') as f:
    json.dump(remaining, f, ensure_ascii=False)
print(f'留出集: {len(held_out)} 条, 开发集: {len(remaining)} 条')
"

# 后面所有迭代都在 dev_set.json 上开发
# 每 3 轮跑一次 held_out_set.json 做方向检查
```

**方向判断**：

| 基准集变化 | 留出集方向 | 判定 | 处理 |
|-----------|:---------:|------|------|
| ↑ | ↑（或持平） | ✅ 通则改进 | 正常接受 |
| ↑ | ↓ | ⚠️ **过拟合风险** | 本轮标记为"待观察"，持续跟踪 |
| ↓ | ↓ | ❌ 方向确认恶化 | 回退 |
| ↓ | ↑ | ⚠️ 反常，检查测试集标注 | 启动根因分析 |
| 连续 2 轮"待观察" | — | ❌ 冻结该方向 | 暂停该方向的迭代 |

## 第 6 步：决策矩阵（规模感知版）

**做什么**：对比第 3 步（改前）和第 5 步（改后）的数据，做出决策。

### 阈值规则

决策阈值**与测试集规模挂钩**：

| 测试集规模 | 1 条对应 | 显著提升 | 可接受持平 | 恶化 |
|:----------:|:--------:|:--------:|:----------:|:----:|
| 51 条 | ≈ 2.0% | ≥ **3.9%（≥2条）** | 0%~3.9% | < 0% |
| 85 条 | ≈ 1.2% | ≥ **2.4%（≥2条）** | 0%~2.4% | < 0% |
| 100 条 | ≈ 1.0% | ≥ **2.0%（≥2条）** | 0%~2.0% | < 0% |

**理由**：51 条测试集上 1 条 ≈ 2.0%，单条波动属于标注噪声范围（2-3 条可能有歧义标注）。要求 ≥ 2 条（3.9%）才认为"显著提升"，避免被标注噪声牵着走。

### 决策矩阵

```
改前总准确率: X%    改后总准确率: Y%
Δ = Y - X
测试集规模: N 条    显著提升阈值 T = ceil(2/N * 100)%  ≈ 3.9%（51条基准）
```

| 场景 | Δ | 分布变化 | 留出集 | 决策 |
|:----:|:----------:|:--------:|:------:|------|
| A | ≥ T（显著提升） | 各题材均不降 | 一致 | ✅ **接受** — 合并代码，更新基线记录 |
| B | ≥ T（显著提升） | 某题材下降 ≥ T | 一致 | ⚠️ **拒绝** — 分析降分原因，记录教训 |
| C | 0% ~ T（持平） | 各题材均不降 | — | ⚠️ **速赢拒绝 / 战略投资接受** |
| D | 0% ~ T（持平） | 某题材下降 | — | ⚠️ **拒绝** — 不要为了整体持平牺牲局部 |
| E | < 0%（下降） | 整体下降 | 一致 | ❌ **立即回退** |
| F | 任何变化 | — | **相反** | ⚠️ **标记为待观察** — 过拟合风险 |

### 细化路径

```
情况 A（Δ ≥ 3.9% + 各题材不降 + 留出集一致）
  → ✅ 接受，更新基线记录

情况 B（Δ ≥ 3.9% + 某题材降了）
  → ⚠️ 拒绝，分析降分原因，记录教训

情况 C（0% ≤ Δ < 3.9% + 各题材不降）
  → 速赢: ⚠️ 拒绝，记录教训（收益不足以覆盖风险）
  → 战略投资: ✅ 接受（结构改善值得容忍短期持平）

情况 D（0% ≤ Δ < 3.9% + 某题材下降）
  → ⚠️ 拒绝

情况 E（Δ < 0%）
  → 速赢: ❌ 立即回退
  → 战略投资且下降 ≤ 3分: ⚠️ 暂时接受（设容忍时限3轮迭代）
  → 战略投资且下降 > 3分: ❌ 立即回退

情况 F（留出集方向相反）
  → 首次: ⚠️ 标记为"待观察"，继续迭代
  → 连续 2 次: ❌ 冻结该方向，启动根因分析
```

### 战略储备库条件

被拒绝的方案满足以下任一条件时，**不入垃圾桶，存入战略储备库**：

1. **结构化优化**：消除硬编码、统一架构、修复系统设计缺陷
2. **认知增强**：赋予系统新的理解能力（语义推理），而非增加规则
3. **上限突破**：在全新文体或压力测试上显著提升鲁棒性

**存储位置**: `docs/战略储备库.md`

## 完整执行示例

### 示例：假设记录 H-20260514-01（移除 NER context_per 路径）

**第 1 步 — 入口判断**

```markdown
# 假设记录 H-20260514-01

**改动内容**: 从 _extract_context_speakers 中移除 NER context_per 路径
**影响机制**: NER 从旁白中提取的 PER 实体（如"族长""骑士"）只是叙述中提到的角色，
            不是说话人。移除后可减少这类噪声候选人的干扰。
**可证伪条件**: 如果「描述性角色」类型的准确率下降超过 5%，则说明 NER 的 PER 实体
             在某种程度上帮助了描述性角色判断，我的"NER 只是噪声"推理是错的。
**预期**: 开发集准确率从 41.2% → ≥ 43.1%
```

**第 2 步 — v7.0 合规**

全部合规（不涉及静态词表、不改变"不猜"逻辑、不越界）。

**第 3 步 — 基线锁定**

```
BASELINE:21/51=41.2%

按挑战类型:
  context_reasoning:描述性角色     11/22 = 50%
  context_reasoning:上下文PER(前)   9/13 = 69%
  none                             0/12 = 0%
  ...

按文体:（无 genre 标签，跳过）
```

**第 4 步 — 执行改动**

删除 speaker_matcher.py 中 NER context_per 两个代码块。pytest 通过。硬编码扫描通过。

**第 5 步 — 验证**

```
AFTER:22/51=43.1%  (+1.9%)

按挑战类型:
  context_reasoning:描述性角色     13/22 = 59%
  context_reasoning:上下文PER(前)   9/13 = 69% （不变，因为 NER 已被移除，走的描述性角色提取）
  none                             0/12 = 0%
```

**第 5.5 步 — 过拟合检查（第 3 轮时执行）**

留出集方向：一致（基准 +1.9% vs 留出集 +0.6%，方向相同） → ✅

**第 6 步 — 决策矩阵**

Δ = +1.9%，低于 51 条基准的显著提升阈值 3.9%。情况 C：持平，速赢。
→ 速赢: ⚠️ **拒绝**（1.9% 不足以保证不是标注噪声）
→ 战略投资（结构优化，消除 NER 噪声源）: ✅ **接受**

最终决策：**接受**（类型为战略投资，允许短期持平）。

| 核心模块 | `pipeline/speaker_matcher.py` | `pipeline/emotion_extractor.py` | `pipeline/entity_cleaner.py` |
| 改造方案 | 已有改造方案文档 | 待创建 | 待创建 |
