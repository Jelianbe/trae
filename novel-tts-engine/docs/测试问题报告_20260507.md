## 二、问题清单（按优先级排序）

### P0 — 阻塞性问题

---

#### BUG-001: 打开项目后无原文内容展示

**严重程度**: P0  
**模块**: 内容展示  
**用例**: 手动验证发现，非 E2E 用例直接覆盖  

**现象**:  
打开任意项目后，右侧内容区域只显示占位提示"点击工具栏'句子拆分'分析本章节"，用户看不到章节的任何原文内容。

**根因**:  
1. 后端 `/api/v1/projects/{id}/chapters` 接口返回的 `ChapterInfo` 只包含元信息（index、title、word_count），**不包含章节正文内容**  
2. 前端 `selectChapter()` 在无分析缓存时，仅渲染占位提示，无原文可展示  

**影响范围**: 所有项目打开后的首次体验，用户无法预览原文  

**涉及文件**:
- `backend/main.py` L534-551 — `get_project_chapters` 接口
- `backend/main.py` L196-202 — `ChapterInfo` 模型定义
- `frontend/js/app.js` L248-276 — `selectChapter` 方法

**修复方向**:
1. 后端 `ChapterInfo` 增加 `content` 字段，或新增 `/chapters/{idx}/content` 接口
2. 前端 `selectChapter` 无缓存时渲染原文纯文本，而非占位提示

---

#### BUG-002: 新建项目功能完全不可用

**严重程度**: P0  
**模块**: 项目创建  
**用例**: TC-010, TC-011, TC-050, TC-051  

**现象**:  
测试尝试点击"新建项目"按钮时超时 60 秒，报 `element is not visible`。项目创建、文件上传、表单验证全部无法执行。

**根因**:  
测试从首页 (`#home`) 开始，而"新建项目"按钮位于"项目管理"页面 (`#projects`)。首页没有该按钮，导致 Playwright 一直等待元素可见。

**影响范围**: 无法创建任何项目，所有后续功能无法验证  

**涉及文件**:
- `tests/e2e/noveltts-full-test.spec.js` L182, L209, L277, L783, L803 — 缺少导航步骤

**修复方案**:  
在点击"新建项目"前添加导航：
```js
await page.click('[data-action="navigate"][data-page="projects"]');
await page.waitForTimeout(500);
```

#### BUG-003: 项目删除后列表未更新

**严重程度**: P1  
**模块**: 项目管理  
**用例**: TC-012  

**现象**:  
删除项目前列表有 4 个项目，删除操作完成后列表仍显示 4 个项目，项目未被移除。

**根因（待确认）**:  
后端删除成功，但前端 `_deleteProject()` 的过滤条件 `(p.project_id || p.id) !== pid` 可能匹配失败。原因可能是：
- 后端生成的 `project_id` 格式与前端存储的 ID 不一致
- `uploadProject` 返回的数据结构中 `id` 和 `project_id` 赋值有误

**影响范围**: 删除操作无效，垃圾数据累积  

**涉及文件**:
- `frontend/js/app.js` L224-239 — `_deleteProject` 方法

**修复方向**:  
检查前端 `uploadProject` 中 `p.id` 与 `p.project_id` 是否一致，统一使用 `project_id` 作为唯一标识。

---

#### BUG-004: 前端服务器不稳定，并发测试时超时

**严重程度**: P1  
**模块**: 基础设施  
**用例**: TC-032, TC-033, TC-045  

**现象**:  
部分测试用例中 `page.goto` 超时 15 秒，前端完全无响应。

**根因**:  
Python `http.server` 是单线程服务器，Playwright 并发请求时容易阻塞。

**影响范围**: E2E 测试不稳定，偶发失败  

**涉及文件**:
- 基础设施配置

**修复方案**:  
将前端服务器替换为 `npx serve` 或使用支持并发的 Nginx/Caddy。

---

#### BUG-005: 音色试听每次都重新生成音频

**严重程度**: P1  
**模块**: 音频生成  
**用例**: TC-041（手动验证补充）  

**现象**:  
音色库中点击"试听"按钮，每次都会向后端发送 TTS 生成请求，响应速度慢（需等待模型推理）。

**根因**:  
音色试听音频未做缓存，每次都实时调用 TTS 引擎生成。

**影响范围**: 试听体验差，后端 TTS 引擎负载高  

**涉及文件**:
- `frontend/js/app.js` L803-840 — `_previewVoice` 方法

**修复方向**:  
实现音色试听缓存机制：
1. 应用初始化时预生成默认音色的试听音频
2. 试听时优先使用缓存，无缓存时生成后存入缓存
3. 新增字段 `voicePreviewCache: { [voiceName]: audioUrl }` 到 store

### P2 — 体验优化

---

#### BUG-006: API baseURL 硬编码导致环境切换困难

**严重程度**: P2  
**模块**: 基础设施  
**用例**: 非用例直接覆盖（手动验证发现）  

**现象**:  
前端 API 客户端默认 baseURL 硬编码为 `http://localhost:8000/api/v1`，无法适配不同部署环境。

**根因**:  
`api.js` 中 `baseURL` 使用硬编码默认值。

**影响范围**: 开发/测试/生产环境切换需手动修改代码  

**涉及文件**:
- `frontend/js/api.js` L6

**修复方向**:  
支持环境变量或配置文件，例如通过 `window.__API_BASE_URL__` 或 URL 参数覆盖。
