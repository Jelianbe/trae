# 项目整合方案 v5.0

> 基于对同行软件 (`D:\yingu`) 的输出目录结构分析，结合 Novel-TTS-Engine 现有架构，设计合理的整合方案。

---

## 1. 同行软件分析

### 1.1 输出目录结构

```
D:\yingu\
└── p5r\                          # 项目名称
    ├── 1\                        # 卷号
    │   └── 1\                    # 章节号
    │       └── audio\            # 音频输出目录
    └── 2\
        └── 40\
            └── audio\
```

**特点：**
- 按 **项目 → 卷 → 章节 → 音频** 层级组织
- 仅包含输出音频，不包含输入文本、中间数据、配置
- 结构简单直观，用户可直接找到对应章节的音频文件

### 1.2 局限性

| 问题 | 说明 |
|------|------|
| 无输入文本 | 不知道音频对应的原文是什么 |
| 无情绪标注 | 无法追溯生成音频时的情绪状态 |
| 无配置记录 | 不知道使用了哪个 TTS 引擎、什么参数 |
| 无中间数据 | 角色识别、说话人匹配结果不可见 |
| 无版本管理 | 无法区分不同版本的生成结果 |

## 2. Novel-TTS-Engine 现有架构

### 2.1 当前项目结构

```
novel-tts-engine/
├── docs/           # 文档
├── pipeline/       # 核心处理管道
├── db/             # 数据库管理
├── utils/          # 工具函数
├── tests/          # 测试文件
├── scripts/        # 脚本工具
├── output/         # 输出目录
├── models/         # 模型文件
├── TTS/            # Index-TTS 引擎目录
└── main.py         # 入口脚本
```

### 2.2 问题

| 问题 | 说明 |
|------|------|
| 无明确项目概念 | 所有输出混在 `output/` 下 |
| 无分层组织 | 卷/章节/音频未分层 |
| 无前端集成 | 用户只能通过命令行操作 |
| 配置分散 | 环境变量、配置文件、硬编码混合 |

## 3. 整合方案设计

### 3.1 核心设计理念

1. **保留现有架构**：不破坏现有管道模块
2. **增加项目管理层**：按项目组织所有输入/输出/配置
3. **前后端分离**：FastAPI 后端 + Streamlit 前端
4. **一键启动**：用户只需运行一个脚本
5. **可追溯**：每个音频都能追溯到原文、情绪、配置

### 3.2 新增目录结构

```
novel-tts-engine/
├── projects/                     # [新增] 项目目录
│   └── {project_id}/             # 每个项目一个目录
│       ├── project.json          # 项目配置（书名、作者、文体风格）
│       ├── input/                # 输入文本（原始小说文本）
│       │   └── novel.txt
│       ├── output/               # 输出音频（按卷/章节组织）
│       │   ├── vol_01/
│       │   │   ├── ch_001/
│       │   │   │   ├── audio/    # 逐句音频

│       │   │   │   └── metadata.json  # 情绪标注、说话人匹配结果
│       │   │   └── ch_002/

│           ├── characters.json   # 角色画像
```

### 3.3 数据流设计

```
用户操作（前端）
    │
    ▼
FastAPI 后端
    │
    ├── 项目管理 → projects/project.json
    ├── 文本导入 → projects/{id}/input/novel.txt
    ├── 角色配置 → projects/{id}/cache/characters.json
    │
    ▼
Pipeline 处理
    │
    ├── ChapterSplitter → 章节划分
    ├── CharacterManager → 角色识别
    ├── EmotionExtractor → 情绪标注
    ├── SpeakerMatcher → 说话人匹配
    │
    ▼
TTS 生成
    │
    ├── IndexTTSEngine → 优先使用
    └── KokoroTTSGenerator → 回退引擎
    │
    ▼
输出存储
    │
    └── projects/{id}/output/vol_{X}/ch_{Y}/audio/
```

### 3.4 一键启动流程

```
用户点击/运行 start.py
    │
    ├── 1. 检查环境（Python、依赖、模型）
    ├── 2. 启动 Index-TTS API（后台静默）
    ├── 3. 启动 FastAPI 后端（端口 5000）
    ├── 4. 启动 Streamlit 前端（端口 8501）
    └── 5. 自动打开浏览器
```

### 3.5 输出目录格式（参考同行 + 增强）

```
projects/{project_id}/output/vol_{X}/ch_{Y}/
├── audio/                          # 逐句音频
│   ├── s_0001.wav
│   ├── s_0002.wav
│   └── ...
├── merged.mp3                      # 合并章节音频
├── metadata.json                   # 元数据
└── metadata.db                     # 情绪标注数据库
```

**metadata.json 格式：**
```json
{
  "project_id": "novel_001",
  "volume": 1,
  "chapter": 1,
  "title": "第一章 重生",
  "text_source": "input/novel.txt",
  "sentences": [
    {
      "id": 1,
      "text": "他睁开眼睛，发现自己回到了十年前。",
      "speaker": "旁白",
      "emotion": "surprise",
      "emotion_confidence": 0.75,
      "tts_engine": "indextts",
      "audio_file": "audio/s_0001.wav",
      "duration_ms": 3200
    }
  ]
}
```

## 4. 实施计划

### 阶段一：项目管理层（1-2天）
- 创建 `projects/` 目录结构
- 实现项目创建、加载、保存功能
- 实现文本导入功能

### 阶段二：API 后端（2-3天）
- 创建 FastAPI 应用
- 实现项目管理 API
- 实现 TTS 生成 API

### 阶段三：前端界面（3-5天）
- 创建 Streamlit 应用
- 实现项目管理页面
- 实现 TTS 生成页面
- 实现音频播放/下载页面

### 阶段四：一键启动（1天）
- 创建 `start.py` 启动脚本
- 自动启动 Index-TTS
- 自动启动后端和前端
