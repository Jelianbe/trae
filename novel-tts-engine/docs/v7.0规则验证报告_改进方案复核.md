### N-1 详细设计：引号内称呼语 → 非说话人排除

**问题**：测试集中 ~14% 的案例属于此模式。当对话以 `"X，"` 开头时，X 是说话人正在称呼的对象（听话人），不是说话人。但当前 `_extract_context_speakers` 的步骤2和步骤3可能将 X 作为说话人候选。

**语言学依据**：中文对话中，句首呼语（vocative）是被称呼的对象。这是跨语言通用的句法规则，不属于静态词表。

**测试集覆盖**（73句中≥10句）：
- P5 `"林轩，你又在偷懒！"` → 林轩是听话人
- P18 `"萧炎，你太弱了！"` → 萧炎是听话人
- P19 `"纳兰嫣然，你变强了。"` → 纳兰嫣然是听话人
- P23 `"加尔文，你背叛了我们！"` → 加尔文是听话人
- P24 `"伊莉雅，别冲动。"` → 伊莉雅是听话人
- P25 `"博士，实验结果如何？"` → 博士是听话人

**伪代码**：

```python
# 在 _extract_context_speakers 中，所有候选人提取完成后、返回前执行
_ADDRESSEE_EXCLUSION = re.compile(r'^([\u4e00-\u9fa5]{2,4})[，！。、,\s]')

if text:  # text = 对话内容（引号内文本）
    m = _ADDRESSEE_EXCLUSION.match(text)
    if m:
        addressed = m.group(1)
        # 从候选列表中排除听话人
        candidates = [(n, r, c) for n, r, c in candidates 
                      if n != addressed and addressed not in n]
```

**置信度设计**：排除操作不涉及置信度——有确定的结构就排除，没有就不排除。这符合原则2（不猜）。

### N-2 详细设计：动作 → 说话紧邻关联

**问题**：当 context_before 的最后一句是"主语 + 动作"（无说话动词），且直接紧邻引号时，动作的发出者很可能是说话人。

**测试集覆盖**：
- P4 `黑衣人抽出长剑。\n"把东西交出来。"` → 说话人：黑衣人
- P15 `林雪拍了一下桌子。\n"这丹药如何？"` → 说话人：林雪
- P28 `苏夜收起剑。\n"你输了。"` → 说话人：苏夜

**当前代码的不足**：步骤3 L552-L556 有类似处理，但触发条件过于苛刻（角色名在片段0-2字符且片段<30字），实际命中率极低。

**伪代码**：

```python
# 在 _extract_context_speakers 中，候选池为空时执行（仅作为后备）
if not candidates and context_before:
    sentences = re.split(r'[。！？\n]+', context_before.strip())
    if sentences:
        last_sent = sentences[-1]
        # 检测最后一句是否以主语+动作结尾（无说话动词）
        if not self.speech_verb_detector.is_speech_related(last_sent):
            action_subject = self._extract_first_per_entity(last_sent)
            if action_subject:
                char = self._match_candidate_to_character(action_subject, context_before,
                                                          skip_speech_check=True)
                if char:
                    candidates.append((char.name, '紧邻动作关联', 0.72))
```

**置信度设计**：使用 0.72，低于说话动词的 0.85~0.88，高于"未知_无法推断"的 0.30。仅在候选池为空时才触发（避免覆盖更强信号）。

**原则合规**：符合原则1（基于句法位置），置信度上限控制了原则2风险。

### N-4 详细设计：对话中"X的"所有格排除

**问题**：对话内容中，`"X的YY"` 结构表示"关于 X 的 Y"。X 是话题而非说话人。但 HanLP 的 NER 可能将 X 识别为 PER 并作为候选人。

**伪代码**：

```python
# 在 analysis_dialogue 中，将对话内容送入 NER 前执行预处理
_POSSESSIVE_PATTERN = re.compile(r'[\u4e00-\u9fa5]{2,4}的')

def _filter_possessive_entities(self, dialogue_text: str, ner_entities: List[str]) -> List[str]:
    """过滤对话中 'X的' 所有格结构中的 X"""
    possessive_matches = _POSSESSIVE_PATTERN.findall(dialogue_text)
    excluded = {m[:-1] for m in possessive_matches}  # 去掉"的"
    return [e for e in ner_entities if e not in excluded]
```

**语言学依据**：中文所有格结构 `X的` 中，X 是领有者/话题，极少是说话人的自称。
