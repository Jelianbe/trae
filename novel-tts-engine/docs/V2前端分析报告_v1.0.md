# NovelTTS V2 前端分析报告

> 基于 `noveltts-v2.html` 演示页面的全面分析，结合竞品 **音谷 (SonicVale)** 技术架构对比


---

## 1. 功能差异分析：V2 演示页 vs 目标 Electron 应用

### 1.1 功能矩阵对比

| 功能模块 | V2 HTML 现状 | 目标 Electron 应用 | 差距 |
|----------|-------------|-------------------|------|
| **项目管理** | Mock 数据，仅前端增删，不持久化 | 真实 CRUD + 文件管理 + 项目配置持久化 | 需要完整后端 API |
| **文件上传** | Textarea 粘贴（纯浏览器操作） | 文件选择器 + 批量导入 + 拖拽上传 | 需要 Electron 文件 API + 后端存储 |
| **章节管理** | Mock 章节树，选择切换 | 章节 CRUD + LLM 智能分割 + 导入导出 | 需要分析引擎对接 |
| **段落编辑器** | Mock 数据，含时间轴编辑、属性和类型选择 | 同左 + 持久化保存 + 版本回溯 | 需要后端持久化 |
| **角色管理** | Mock 角色列表，增删改前端模拟 | 角色 CRUD + 自动识别 + 音色绑定 | 需要角色匹配引擎 |
| **音色库** | Mock 6 个音色卡片，假波形图 | 真实音色管理 + 参考音频上传 + 试听 | 需要 TTS 引擎驱动 |
| **音频播放** | 模拟进度条动画（伪播放） | 真实音频流播放 + 波形可视化 | 需要音频后端 |
| **TTS 生成** | 仅有"试听"按钮（toast 提示） | 批量生成 + 任务队列 + 进度推送 | 需要 TTS 任务队列 |
| **参数调节** | 前端本地暂存 Mock 数据 | 持久化到后端 + 版本管理 | 需要保存 API |
| **导出** | 无 | JSON/SSML/音频导出 | 需要导出 API |
| **撤销/重做** | 本地 JS undoStack（50 步限制） | 同左（可保持客户端实现） | 基本可用 |
| **系统设置** | 前端模拟开关，无真实作用 | 持久化到配置文件/数据库 | 需要配置管理 |

### 1.2 Electron 独有能力差异

| 能力 | V2 无法实现 | Electron 可实现 | 差距分析 |
|------|-------------|----------------|---------|
| **本地文件访问** | ❌ 浏览器沙箱限制 | ✅ `fs` API 直接读写 | 核心差距：Electron 的 `dialog.showOpenDialog` 可打开文件/目录选择器 |
| **子进程管理** | ❌ 无 | ✅ `child_process.spawn` | 自动化集成 TTS 子进程 |
| **系统托盘** | ❌ 无 | ✅ 后台运行时系统托盘 | 长时间运转体验 |
| **自动更新** | ❌ 无 | ✅ `electron-updater` | 版本迭代 |
| **离线运行** | ⚠️ 部分（受 CORS 限制） | ✅ 完全离线 | 本地模型推理 |
| **多窗口** | ❌ 单页限制 | ✅ 多窗口管理 | 设置/角色编辑独立弹窗 |

## 2. 功能实现差异分析：相同功能的 Web vs Electron 实现

### 2.1 段落编辑器

**V2 Web 实现**：
```javascript
// 前端纯内存操作，不支持持久化
let segments = []; // 内存数据
function saveState() {
  undoStack.push(JSON.parse(JSON.stringify(segments)));
}
function updateSegParam(index, param, value) {
  segments[index][param] = parseInt(value); // 仅修改内存
}
```

**Electron 实现**（参考 SonicVale）：
```javascript
// 通过后端 API 持久化
import request from './config';
export function updateLine(lineId, data) {
  return request.put(`/lines/${lineId}`, data); // PUT 到后端持久化
}
// 批量排序
export async function reorderLinesByPut(orderList) {
  return request.put('/lines/batch/orders', orderList);
}
```

**差异本质**：
- **Web**: JavaScript heap 内存 → 页面刷新即丢失
- **Electron**: Vue 组件状态 → HTTP API → 后端数据库 → 持久化存储

### 2.2 音频播放

**V2 Web 实现**：
```javascript
// 模拟进度条动画
function simulateProgress() {
  if (!isPlaying) return;
  let w = parseFloat(fill.style.width) || 35;
  w += 0.3;
  fill.style.width = w + '%';
  requestAnimationFrame(simulateProgress);
}
```

**Electron 实现**（参考 SonicVale）：
```javascript
// 真实波形渲染（wavesurfer.js）
// 需要后端返回音频流
export function generateAudio(projectId, chapterId, body) {
  return request.post(`/lines/generate-audio/${projectId}/${chapterId}`, body);
}
// 播放时调用 wavesurfer.js 加载真实音频 URL
```

**差异本质**：
- **Web**: 纯 UI 动画，无真实音频
- **Electron**: `wavesurfer.js` + 真实音频流 + 后端 TTS 引擎

### 2.3 音色库

**V2 Web 实现**：
```javascript
// 硬编码 6 个音色，含随机波形数据
const voices = [
  { id:1, name:'云深', gender:'male', bars:[40,65,50,80,55,70,...] },
  // ...
];
```

**Electron 实现**（参考 SonicVale）：
```javascript
// 后端管理音色资源文件
export function createVoice(payload) {
  return request.post('/voices', payload);
}
export function processVoiceAudio(audio_path, params) {
  // 后端处理参考音频（音量、速度、静音裁剪）
  return request.post('/voices/process-audio', {...});
}
// 后端按需加载音色文件，前端获取元数据
```

**差异本质**：
- **Web**: 静态 Mock 数据，无真实音频处理能力
- **Electron**: 后端管理音色文件，支持参考音频处理/试听/导入导出

## 3. 优势区间界定

### 3.1 优势对比矩阵

| 评估维度 | V2 HTML | Electron（目标） | 说明 |
|---------|---------|-----------------|------|
| **视觉设计** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | V2 的深色主题、字体选择、间距规范已达到较高水准 |
| **交互流畅度** | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | 纯前端操作无网络延迟，但 Electron 架构更复杂 |
| **数据持久化** | ⭐ | ⭐⭐⭐⭐⭐ | V2 无任何持久化能力 |
| **TTS 集成度** | ⭐ | ⭐⭐⭐⭐⭐ | V2 只能给提示，无法真正生成音频 |
| **文件处理** | ⭐⭐ | ⭐⭐⭐⭐⭐ | 浏览器限制文件操作，Electron 有完整 FS API |
| **离线能力** | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | V2 离线可用前端功能但无后端 |
| **扩展性** | ⭐⭐ | ⭐⭐⭐⭐ | Electron 可集成系统原生功能 |
| **开发迭代速度** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | HTML 修改即生效，Electron 需打包部署 |
| **调试便利性** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | 浏览器 DevTools vs Electron DevTools |
| **分发难度** | ⭐⭐⭐⭐⭐ | ⭐⭐ | HTML 可直部署到静态服务器，Electron 需打包 |

### 3.2 各自适用场景

| 场景 | 推荐方案 | 理由 |
|------|---------|------|
| **快速原型/概念验证** | V2 HTML | 0 部署成本，即改即看 |
| **技术演示/Demo** | V2 HTML | 访客直接打开即可体验 UI |
| **日常生产使用** | Electron | 需要持久化、TTS 集成、文件管理 |
| **多人协作** | Electron + 后端 | 共享数据库和项目文件 |
| **移动端临时访问** | V2 HTML | 浏览器即可打开，无需安装 |
| **批量大规模处理** | Electron | 子进程管理 + 后台任务队列 |

## 7. 分析功能评估

### 7.1 当前实现

V2 前端的"分析"功能全部为模拟：
- "开始分析"按钮 → toast 提示
- 项目进度条 → 硬编码数值
- 状态标签 → 硬编码 `status: 'analyzing'`

### 7.2 后端能力（现有但前端未对接）

实际后端 pipeline 已具备的能力：

| 模块 | 功能 | 接口就绪？ |
|------|------|-----------|
| `ChapterSplitter` | 章节分割 + 自动分块 | ❌ 无 HTTP 端点 |
| `EmotionExtractor` | 6 种情绪识别 | ❌ 无 HTTP 端点 |
| `SpeakerMatcher` | 说话人匹配 | ❌ 无 HTTP 端点 |
| `CharacterManager` | 角色管理 | ❌ 无 HTTP 端点 |
| `SfxDetector` | 拟声词检测 | ❌ 无 HTTP 端点 |
| `IndexTTSEngine` | TTS 音频生成 | ✅ 端口 8300 可用 |
| `TTSGenerator` | 双引擎回退 | ❌ 无 HTTP 端点 |

### 7.3 竞品对比

**SonicVale** 使用 LLM 进行智能分析（`/lines/correct-subtitle-llm/${chapter_id}`），而我们使用专用 NLP 管道。差异在于：
- 我们的方案**无需外部 API**，完全离线运行
- 我们的方案**更可控**，不依赖第三方 LLM 服务
- 但需要实现 HTTP 端点暴露这些能力

### 10.1 当前互动评估

| 互动维度 | 评分 | 说明 |
|---------|------|------|
| **操作便捷性** | ⭐⭐⭐⭐ | 键盘快捷键、内联编辑、拖拽排序均表现优秀 |
| **内容展示清晰度** | ⭐⭐⭐⭐ | 段落类型颜色标识清晰，角色筛选有用 |
| **用户控制自由度** | ⭐⭐⭐⭐ | 批量操作、撤销/重做、插入/拆分/复制/删除完整 |
| **视觉反馈** | ⭐⭐⭐ | Toast 通知和动画到位，但缺少加载状态和错误状态 |
| **错误恢复** | ⭐⭐ | 无错误边界、无自动保存恢复 |

### 10.2 优化建议（按优先级）

| 优先级 | 建议 | 预期效果 |
|--------|------|---------|
| P0 | 加载状态指示器 | 分析/生成时用户不会失去耐心 |
| P0 | 错误边界 + 错误提示 | 防止白屏，用户能知道发生了什么 |
| P1 | 自动保存 + 版本恢复 | 意外关闭后不丢失编辑内容 |
| P1 | 段落操作历史面板 | 用户可直观看到修改记录 |
| P2 | 全局搜索（搜索章节+段落） | 大项目时快速定位内容 |
| P2 | 章节批处理（批量分析/生成） | 减少重复操作 |

| 阶段 | 目标 | 收益 |

## 12. 后续修改建议

### P0 级别（必须尽快修复）

| 序号 | 修改内容 | 位置 | 修改理由 | 预期效果 |
|------|---------|------|---------|---------|
| **1** | **对接 FastAPI 后端，替换所有 Mock 数据** | 全局 JS | 所有数据硬编码，无法用于实际生产 | 真实数据驱动，功能可用 |
| 2 | 实现真实 TTS 调用（试听/生成） | `previewSegment()`, `generateAudio()` | TTS 是核心功能，不能是 Toast | 用户能真正听到生成的声音 |
| 3 | 实现真实音频播放器 | `togglePlay()` + `player-fill` | 伪进度条给用户错误预期 | 真实音频流 + 波形可视化 |
| 4 | 实现数据持久化 | 所有 CRUD 操作 | 刷新页面数据丢失 | 编辑内容长久保存 |

### P1 级别（核心稳定）

| 序号 | 修改内容 | 位置 | 修改理由 | 预期效果 |
|------|---------|------|---------|---------|
| 5 | 引入状态管理 | 全局变量 → Pinia/Vuex | 函数间耦合严重 | 可维护性提升 |
| 6 | 添加错误边界 + 加载状态 | 全局 | 无错误处理，白屏后无法恢复 | 用户友好，可调试 |
| 7 | 实现自动保存 | 段落编辑 | contenteditable 无保存触发 | 编辑内容不会意外丢失 |
| 8 | 系统设置生效 | settings 页面 | 所有开关无真实作用 | 设置可配置系统行为 |

### P2 级别（完善体验）

| 序号 | 修改内容 | 位置 | 修改理由 | 预期效果 |
|------|---------|------|---------|---------|
| 9 | 章节筛选后状态自动重置 | `filterByCharacter()` | 切换章节后筛选状态残留 | 交互更自然 |
| 10 | 新建项目弹窗内容实际使用 | `createProject()` | 粘贴内容未被用于分析 | 一步到位完成数据输入 |
| 11 | 渲染性能优化 | `renderContent()` | 每次全量重建 DOM | 大段落列表时性能提升 |
| 12 | 批量操作扩展 | `batchActions()` | 当前只有批量改类型/删除 | 增加批量分配角色/调参/导出 |

### 修改时间线建议

```
Day 1-2:  P0-1 (对接 API) + P0-2 (真实 TTS)
Day 3:    P0-3 (音频播放器) + P0-4 (持久化)
Day 4-5:  P1-5 (状态管理) + P1-6 (错误边界)
Day 6:    P1-7 (自动保存) + P1-8 (设置生效)
Day 7:    P2-9 ~ P2-12 (完善体验)
```
