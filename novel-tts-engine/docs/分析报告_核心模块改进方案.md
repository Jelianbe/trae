## 1. 背景介绍

### 1.1 项目定位

Novel-TTS-Engine 是一个面向网络小说的文本到语音转换引擎，旨在将非结构化的小说文本自动转化为多角色、带情绪的有声书。项目的核心挑战在于：

1. **人物识别**：从非结构化文本中自动提取所有说话角色
2. **对话识别**：区分对话、旁白、内心独白、书面内容等文本类型
3. **对话归属**：将每段对话准确地归属到正确的说话人

### 1.2 核心功能模块

项目采用 Pipeline 架构，核心模块包括：

| 模块 | 文件 | 职责 |
|------|------|------|
| NLP 基础 | `nlp_basics.py` | 基于 HanLP 的分词、词性标注、NER |
| 说话角色过滤 | `speaker_role_filter.py` | 只保留出现在对话引导词附近的 PER 实体 |
| 实体验证 | `context_diversity_validator.py` | 基于右邻字符多样性验证实体有效性 |
| 实体链接 | `entity_linker.py` | 将 NER 实体链接到已注册角色 |
| 实体聚类 | `entity_clusterer.py` | 将不同称呼归一化（如"苏夜"/"苏兄"/"苏公子"） |
| 说话人匹配 | `speaker_matcher.py` | 六级漏斗匹配（精确/语义/别名/触发词/活跃度/代词） |
| 引号分类 | `quotation_classifier_v2.py` | 区分对话、书面内容、内心独白等 |
| 对话分类 | `dialogue_classifier_v2.py` | 细分 thought/written/dialogue 等类型 |

### 1.3 系统架构

```
输入: 小说文本 (.txt)
       ↓
┌──────────────────────────────────────────────────────┐
│                   PipelineRunner                     │
└──────────────────────┬───────────────────────────────┘
                       ↓
    ┌──────────────────┼──────────────────┐
    ↓                  ↓                  ↓
┌────────┐       ┌──────────────┐   ┌─────────────┐
│Step 1  │       │ Step 2~4     │   │  Step 5~6   │
│章节划分│       │NER+验证+过滤 │   │ 说话人匹配  │
│        │       │+拟声词检测   │   │ +情绪标注   │
└────────┘       └──────────────┘   └─────────────┘
    ↓                  ↓                  ↓
Chapter            LinkedEntity       SentenceData
Splitter           + SfxWords         + Speaker
                                        + Emotion
                                        + QuotationType
```

## 2. 现状分析

### 2.1 当前系统架构

系统基于 **纯本地、低资源、规则为主** 的设计约束：

- **分词引擎**: HanLP（统计式分词+词性标注）
- **语义匹配**: BGE 向量 + L2 语义排序器
- **匹配策略**: 六级漏斗（精确匹配 → 语义相似度 → 别名/头衔 → 触发词推理 → 活跃度推理 → 代词消解）
- **验证机制**: 上下文多样性统计（右邻字符多样性）
- **聚类方法**: BGE 语义相似度 + 层次聚类（threshold=0.6）

## 3. 痛点剖析

### P1: HanLP 误合并识别

**严重程度**: P1（高）  
**影响范围**: 所有题材，尤其修仙/西幻  
**具体表现**:

HanLP 的 NER 模块会将"人名 + 动词/形容词"误合并为更长的人名实体：

| 误合并示例 | 正确拆分 | 影响 |
|-----------|---------|------|
| "萧炎冷" | "萧炎"（PER）+ "冷"（形容词） | 说话人匹配失败 |
| "林雪说道" | "林雪"（PER）+ "说道"（动词） | 角色名错误 |
| "苏夜看着" | "苏夜"（PER）+ "看着"（动词） | 语义匹配失败 |
| "老陈"被识别为单字"陈" | 应为完整人名"老陈" | 单字姓氏识别失败 |

**根因分析**:

HanLP 采用的是统计式 NER，基于字符序列标注（BIO/BMES），在以下情况下容易出错：

1. **边界歧义**：人名后的动词/形容词与人名之间没有明确边界标记
2. **训练数据偏差**：HanLP 的训练数据以新闻/通用文本为主，缺乏小说语料
3. **缺乏上下文感知**：统计模型无法理解"冷笑道"中"冷"是动词修饰语而非人名

**当前缓解措施**:

系统已在 [speaker_matcher.py](file:///d:/trae/novel-tts-engine/pipeline/speaker_matcher.py) 中实施了部分缓解：
- `_is_verb()` 方法：使用 HanLP 词性标注验证候选角色名
- `_is_valid_character_name()` 方法：过滤包含动词/介词/量词的垃圾输出
- 预过滤已知说话修饰词（沉声、冷冷、淡淡等 20+ 个词）
- [context_diversity_validator.py](file:///d:/trae/novel-tts-engine/pipeline/context_diversity_validator.py) 中的 `_detect_mis_merged_entities` 方法

### P2: 单字姓氏+称呼词不稳定

**严重程度**: P1（高）  
**影响范围**: 都市、历史、修仙题材  
**具体表现**:

| 输入 | 期望输出 | 实际输出 | 问题 |
|------|---------|---------|------|
| "老陈说道" | "老陈" | "陈"（单字） | "老"被识别为修饰语 |
| "小王" | "小王" | 未被识别为 PER | 昵称/简称过滤过严 |
| "赵师兄" | "赵师兄" | "赵"（单字） | 称呼词被剥离 |
| "张长老" | "张长老" | 可能识别为 "张长老" 或 "张" | 不一致 |

**根因分析**:

1. **HanLP 词性标注偏差**："老"、"小"等前缀在某些上下文中被标注为形容词而非人名组成部分
2. **虚假人名过滤过严**：`_filter_false_persons` 方法中的词典过滤可能误杀常见昵称模式
3. **SpeakerRoleFilter 窗口大小不足**：当前 15 字符的上下文窗口可能不足以捕获完整的称呼结构

**影响评估**:

根据测试报告，都市异能题材中"老陈"类称呼的 NER F1 仅 50-70%，显著低于其他实体类型。

### P3: 西方人名译名变体

**严重程度**: P1（高）  
**影响范围**: 西幻题材  
**具体表现**:

| 问题类型 | 示例 | 影响 |
|---------|------|------|
| 名/姓分离 | "哈利"、"波特"、"哈利波特"被识别为三个独立实体 | 角色实体碎片化 |
| 译名变体 | "伏地魔"vs"汤姆·里德尔"vs"黑魔王" | 同一角色多个身份 |
| 缩写/简称 | "哈利·波特"→"哈利"→"波特" | 共指消解困难 |
| 中间名处理 | "阿不思·珀西瓦尔·伍尔弗里克·布赖恩·邓布利多" | 超长实体名 |

**根因分析**:

1. **HanLP 默认未开启外文名合并**：需手动调用 `enable_foreign_name_merge()`
2. **译名库缺失**：系统没有维护西方人名译名知识库（如"Harry"↔"哈利"↔"哈利波特"）
3. **实体聚类阈值过高**：BGE 相似度 threshold=0.6 对于中文译名变体可能不够敏感

**当前缓解措施**:

- 系统已有 `enable_foreign_name_merge()` 功能（默认关闭）
- [entity_clusterer.py](file:///d:/trae/novel-tts-engine/pipeline/entity_clusterer.py) 使用 BGE 向量进行语义聚类

### P5: 引号内容一律视为对话

**严重程度**: P2（中高）  
**影响范围**: 所有题材  
**具体表现**:

| 引号内容类型 | 示例 | 当前处理 | 期望处理 |
|------------|------|---------|---------|
| 人物对话 | "你好啊，苏夜。" | 朗读（正确） | 朗读 |
| 石碑铭文 | "太古苍龙，陨落于此" | 朗读（错误） | 不朗读或特殊处理 |
| 书信内容 | "亲爱的母亲：见字如面..." | 朗读（错误） | 不朗读或标记为书面 |
| 内心独白 | "我到底该怎么办？" | 朗读（错误） | 内心独白音色 |
| 功法秘籍 | "炼气三重，气沉丹田" | 朗读（错误） | 不朗读 |

**根因分析**:

1. **DialogueClassifier 规则覆盖不全**：虽有 `dialogue_classifier_v2.py` 增加了 thought/written 类型，但分类逻辑仍依赖固定模式
2. **QuotationClassifier 评分算法局限**：虽有 60+ 标识词和文言文检测，但对上下文语义理解不足
3. **缺乏段落级上下文**：当前分类基于局部模式，无法利用章节级上下文判断引号内容性质

### P8: 固定窗口丢失长距离关联

**严重程度**: P2（中高）  
**影响范围**: 所有长篇小说  
**具体表现**:

| 场景 | 问题 |
|------|------|
| 跨章对话归属 | 第 5 章的角色在第 50 章回归，但角色状态已丢失 |
| 远距离代词消解 | "他"指代的角色可能在 3 章前才出现过 |
| 称呼变化未追踪 | "沈先生"→"阿砚"→"沈少侠"的称呼演变无法关联 |
| 低频角色遗忘 | 间隔 10+ 章才出现的配角被判定为不活跃 |

**根因分析**:

1. **SpeakerRoleFilter 窗口仅 15 字符**：`_get_dialogue_contexts` 方法中的 `max(0, start-15)` 窗口
2. **章节级处理隔离**：Pipeline 按章节独立处理，缺少跨章节状态维护
3. **代词消解仅依赖局部上下文**：`pronoun_resolver.py` 的代词消解仅在当前章节内有效

### P9: "未知"角色比例过高

**严重程度**: P2（中高）  
**影响范围**: 对话无明确引导词的场景  
**具体表现**:

| 场景 | 示例 | 当前输出 |
|------|------|---------|
| 无"说道"引导词 | "炎儿，这么晚了怎么还待在这上面呢？" | 未知_角色 |
| 多人对话轮替 | 连续对话无说话人标记 | 全部标记为"未知" |
| 自称词无匹配 | "老臣以为..." | 未知_文臣（正确但体验差） |

**根因分析**:

1. **漏斗匹配失败率较高**：L1-L6 六级漏斗在无明确线索时全部失败
2. **"通则推理、拒绝猜测"策略**：系统在证据不足时返回"未知"类型而非猜测
3. **对话上下文利用率不足**：未充分利用对话内容、前文说话人等信息进行推断

## 4. 建议方案

### 4.1 P1 改进方案：HanLP 误合并修复

**方案概述**: 引入基于大模型的 NER 增强层，在 HanLP 结果之上添加边界校验。

#### 方案 1.1：LLM 边界校验器（推荐）

**核心思路**: 使用轻量级 LLM（Qwen2-1.5B LoRA 微调）对 HanLP 提取的实体进行边界校验。

**实施步骤**:

1. **创建 `pipeline/ner_boundary_validator.py`**：
   - 输入：HanLP 提取的实体列表 + 上下文
   - 处理：使用 Qwen2-1.5B NER LoRA 模型进行边界校验
   - 输出：修正后的实体边界

2. **实现逻辑**:
   ```python
   def validate_entity_boundary(entity_text: str, context: str, nlp_model) -> str:
       """校验实体边界并返回修正后的实体名"""
       # 使用 LoRA 微调的 Qwen2-1.5B NER 模型
       # 输入 prompt: "请从以下文本中提取准确的人名实体：{context}"
       # 对比 HanLP 结果，修正边界
       return corrected_entity
   ```

3. **集成到 Pipeline**: 在 `pipeline_runner.py` 的 NER 步骤后、验证步骤前插入

**预期效果**:
- HanLP 误合并率降低 60-80%
- 角色识别准确率提升 5-10%

**资源需求**:
- Qwen2-1.5B 模型（约 3GB）+ LoRA 适配器（约 50MB）
- 推理延迟：~50ms/实体

#### 方案 1.2：规则增强边界检测（低成本替代方案）

**核心思路**: 在不引入 LLM 的前提下，通过增强规则修复误合并。

**实施步骤**:

1. **扩展误合并检测词表**：
   ```python
   # 动词后缀模式
   VERB_SUFFIXES = [
       "笑道", "说道", "问道", "喊道", "答道", "冷笑道", "沉声道",
       "看着", "望着", "盯着", "盯着", "想着", "走到", "来到",
   ]
   
   # 形容词后缀模式
   ADJ_SUFFIXES = ["冷", "热", "快", "慢", "轻", "重", "淡", "浓"]
   ```

2. **实现后缀剥离算法**:
   ```python
   def strip_false_suffix(entity_text: str) -> str:
       """剥离误合并的动词/形容词后缀"""
       for suffix in VERB_SUFFIXES + ADJ_SUFFIXES:
           if entity_text.endswith(suffix) and len(entity_text) > len(suffix):
               return entity_text[:-len(suffix)]
       return entity_text
   ```

3. **集成到 `context_diversity_validator.py`**

**预期效果**:
- 误合并率降低 30-50%
- 零额外资源消耗

### 4.2 P2 改进方案：单字姓氏+称呼词稳定性

**方案概述**: 引入称呼词词典+上下文感知的人名识别增强。

#### 方案 2.1：称呼词词典+模式匹配

**实施步骤**:

1. **构建称呼词词典**（参考 GenWebNovel 数据集统计）：
   ```python
   # 前缀称呼
   PREFIX_TITLES = ["老", "小", "大", "阿"]
   
   # 后缀称呼（修仙/武侠）
   SUFFIX_TITLES = [
       "师兄", "师姐", "师弟", "师妹", "师父", "师叔", "师尊",
       "长老", "宗主", "殿主", "峰主", "管家", "公子", "小姐",
       "少爷", "大人", "阁下", "前辈", "晚辈",
   ]
   
   # 后缀称呼（都市）
   SUFFIX_TITLES_URBAN = [
       "先生", "女士", "老师", "医生", "博士", "教授", "总裁",
       "经理", "总监", "队长", "局长", "主任",
   ]
   ```

2. **修改 `nlp_basics.py` 的 `_filter_false_persons` 方法**:
   ```python
   def _is_valid_surname_with_title(self, text: str) -> bool:
       """检查是否为 单字姓氏+称呼 模式"""
       # 单字+后缀称呼
       for suffix in self.SUFFIX_TITLES:
           if text.endswith(suffix) and len(text) == 1 + len(suffix):
               return self._is_valid_surname(text[0])
       # 前缀+单字名
       for prefix in self.PREFIX_TITLES:
           if text.startswith(prefix) and len(text) == 2:
               return self._is_valid_surname(text[1])
       return False
   ```

### 4.4 P5 改进方案：引号内容分类增强

**方案概述**: 引入上下文感知的引号内容分类器，利用段落级信息判断引号性质。

#### 方案 4.1：段落级引号分类器

**实施步骤**:

1. **创建 `pipeline/contextual_quotation_classifier.py`**:
   - 输入：引号内容 + 前后 3 句上下文
   - 输出：dialogue / monologue / written / inscription / thought / telepathy

2. **实现分类逻辑**:
   ```python
   def classify_quotation(self, quote_text: str, context_before: str, 
                          context_after: str) -> str:
       """基于上下文的引号内容分类"""
       # 1. 检查前文是否有"看到"、"发现"、"石碑上刻着"等视觉提示
       visual_cues = ["看到", "发现", "石碑", "碑文", "刻着", "写着"]
       if any(cue in context_before for cue in visual_cues):
           return "inscription"
       
       # 2. 检查是否有"信"、"书信"、"遗书"等书面提示
       written_cues = ["信", "书信", "遗书", "密信", "书信中"]
       if any(cue in context_before for cue in written_cues):
           return "written"
       
       # 3. 检查是否有"心想"、"暗自"等内心独白提示
       thought_cues = ["心想", "暗自", "想道", "思索"]
       if any(cue in context_before for cue in thought_cues):
           return "thought"
       
       # 4. 降级到现有 quotation_classifier_v2 的逻辑
       return self.fallback_classifier.classify(quote_text)
   ```

   class CrossChapterEntityTracker:
       """跨章节实体状态追踪器"""
       def __init__(self):

       def update(self, entity_text: str, chapter_id: int, 
                  context: str, is_speaker: bool):
           """更新实体状态"""

               self.entities[entity_text] = EntityState(
                   name=entity_text, last_seen_chapter=chapter_id
               )
           state = self.entities[entity_text]

           if is_speaker:
