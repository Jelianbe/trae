## 一、问题描述

### 1.1 核心问题

情绪提取器正站在**"补丁堆"与"重构"的岔路口**，面临三大结构性问题：

| 问题 | 严重程度 | 当前表现 |
|------|---------|---------|
| 过拟合 | 🔴 严重 | 自建测试集 +15.2%，客观 GT -2.0% |
| 情绪麻木 | 🔴 严重 | 70% 案例预测为 neutral |
| 补丁堆维护成本 | 🟡 中等 | 规则指数增长，维护成本不可控 |

### 1.2 量化表现

| 测试集 | v1 L2 准确率 | v2 L2 准确率 | 变化 |
|--------|------------|------------|------|
| 100 条 GT（客观） | 29.0% | 27.0% | **-2.0%** |
| 198 条 v2 自建 | 38.9% | 54.0% | +15.2% |
| 4 部小说（真实文本） |  anger 9.0% | anger 3.0% | 过度下降 |

### 1.3 具体 Bug 清单

| 编号 | Bug | 影响 | 根因 |
|------|-----|------|------|
| BUG-01 | 脏话词边界漏判 | anger 漏判 3 条 | `_SINGLE_CHAR_DIRTY_RE` 正则过于严格 |
| BUG-02 | 否定词误杀 | anger 误判为 neutral | 否定词处理逻辑过于激进 |
| BUG-03 | neutral 阈值过高 | 70% 案例预测为 neutral | 阈值 0.35，大部分文本够不着 |
| BUG-04 | fear 识别率为 0% | 所有 fear 案例均未识别 | 信号覆盖严重不足 |

## 二、根因分析

### 2.1 深层根因：进化路径迷失

**表象**：v2 改动量巨大（否定词、情绪衰减、词典扩展、信号守卫、脏话修复），但在客观数据上未见提升。

**根因**：v2 的改动策略是**"看到某个 case 错了，就加一条规则去修它"**——这是典型的"补洞思维"。

| 阶段 | 改动 | 结果 |
|------|------|------|
| v1→v2 | 否定词处理、重复计分修复、词典扩展 | 自建测试集提升，客观 GT 下降 |
| v2→v3 | 信号守卫系统 | 减少误触发，但规则越来越"脆" |
| v3→v4 | 情绪衰减机制 | 多轮对话场景改善，单句无效果 |

**核心矛盾**：
- 太保守（neutral 阈值 0.35）→ 麻木
- 太激进（特定关键词直接 +0.4）→ 一旦触发就严重倾斜
- **不平衡的分类器**——少数强信号统治一切，缺乏中间强度的情绪信号

### 2.2 测试策略的结构性风险

| 问题 | 数据 1 | 数据 2 | 说明 |
|------|--------|--------|------|
| 两个测试集两个世界 | GT: 29% | 自建: 54% | 差距 25%，不可能是统计波动 |
| 过拟合风险 | v2 自建大幅提升 | GT 下降 | v2 更适配自建分布 |
| 验证集被污染 | 150 条新数据用于"哪里不够补哪里" | — | 这是训练集思维，不是验证 |

## 三、修复方案

### 3.1 方案概述

采用**"三步走"变轨策略**：
1. **第一步：紧急修复** — 修 Bug，建立独立测试网关
2. **第二步：信号系统重构** — 从"手工写特征权重"到"特征提取+决策融合"
3. **第三步：战略升级** — 引入轻量分类器辅助规则系统

### 3.2 第一步：紧急修复（1-2 天）

#### 3.2.1 修复 BUG-01：脏话词边界正则

```python
# 当前（有问题）：
_SINGLE_CHAR_DIRTY_RE = re.compile(
    r'(?:^|[^一-龥])(?:滚|草|靠|日)(?:[^一-龥]|$)'
)

# 修复方案：放宽边界条件
# 方案 A：仅排除"后面紧跟另一个中文字"的情况
_SINGLE_CHAR_DIRTY_RE = re.compile(
    r'(?:滚|草|靠|日)(?![一-龥])'
)

# 方案 B（推荐）：更精确的词边界
_SINGLE_CHAR_DIRTY_RE = re.compile(
    r'(?<![一-龥])(?:滚|草|靠|日)(?![一-龥])|'  # 独立脏字
    r'(?:滚|草|靠|日)(?![一-龥])'                  # 脏字开头
)
```

**验证标准**：
- ✅ "你给我滚出去" → anger
- ✅ "我，我草" → anger
- ✅ "草木" → neutral（不误判）
- ✅ "滚" → anger

#### 3.2.2 修复 BUG-03：降低 neutral 阈值

```python
# 当前
if best_score <= 0.35:
    return 'neutral', 0.3

# 修复后
if best_score <= 0.25:
    return 'neutral', 0.3
```

**预期效果**：情绪信号敏感度提升，neutral 占比从 70% 降至 50-60%

#### 3.2.3 建立独立测试网关

**新建 200 条纯净测试集**：
- 从真实网文章节中直接抽取对话
- 标注由不熟悉算法的人做，只标注"情绪"不标注"特征"
- 覆盖 10 种文体，每种至少 20 条
- 此测试集**不参与任何开发过程**，仅用于回归验证

**网关规则**：
```
每次改动 → 跑纯净测试集 → 
  如果提升或持平 → 允许合并
  如果下降 > 2% → 拒绝合并，分析原因
```

#### 3.2.4 文档净化

**问题**：`战略储备库.md` 存在编码污染，出现大量 `?` 乱码字符。

**净化措施**：
1. 将文件从 GBK/ANSI 编码转换为 UTF-8
2. 修正所有乱码字符
3. 建立文档编码规范：所有文档必须使用 UTF-8 编码
4. 在仓库根目录添加 `.editorconfig` 文件，统一编码格式

### 3.3 第二步：信号系统重构（1-2 周）

#### 3.3.1 问题：当前信号系统的不平衡性

| 信号类型 | 权重范围 | 问题 |
|---------|---------|------|
| 强信号（如"恐惧"） | +0.4 | 一旦触发就严重倾斜 |
| 中等信号（如"哈哈"） | +0.3-0.4 | 覆盖不足 |
| 弱信号（如感叹号） | +0.1-0.2 | 大量堆积才能达到阈值 |
| neutral 保底 | +0.35 基础 | 从"垃圾桶"变成"黑洞" |

#### 3.3.2 重构方案：特征提取 + 决策融合

**架构设计**：
```
原始文本
  ↓
规则系统（特征提取层）
  ├─ 标点密度特征
  ├─ 情绪词命中特征
  ├─ 句式特征
  ├─ 重复模式特征
  └─ 上下文情绪特征
  ↓
决策融合层（轻量分类器）
  ├─ 决策树 / 随机森林
  ├─ 输入：规则系统输出的特征向量
  └─ 输出：最终情绪标签 + 置信度
```

**具体实施**：

1. **保留现有规则系统的特征提取能力**
   - 感叹号密度 → 特征 F1
   - 情绪词命中 → 特征 F2-Fn
   - 句式特征 → 特征 Fn+1-Fm

2. **用决策树/随机森林替代手工阈值**
   - 不再手工设 `if score > 0.35`
   - 让模型学习特征之间的交互关系
   - 可解释性强（可输出决策路径）

3. **渐进式迁移**
   - Phase 1：规则系统 + 分类器并行运行
   - Phase 2：对比两者表现，调优分类器
   - Phase 3：分类器达到或超过规则系统后，替换为主系统

**预期收益**：
- 泛化能力提升（分类器不依赖具体词汇）
- 维护成本降低（不再需要逐条加规则）
- 可解释性保持（决策树可输出决策路径）

### 3.4 第三步：战略升级（长期）

#### 3.4.1 激活战略储备库方案

| 方案 | 启动条件 | 预期收益 |
|------|---------|---------|
| #20260503-02 DIALOGUE_WORDS 统计发现 | 硬编码密度成为瓶颈 | 消除误合并检测中的硬编码依赖 |
| #20260503-03 引号内容分类器 | 情绪标注需要区分引号类型 | 正确处理石碑、书信、内心独白 |

#### 3.4.2 文体自适应

不同文体使用不同的情绪阈值和信号权重：
- 修仙：anger 信号更强（宣言、咆哮类多）
- 都市：surprise 信号更敏感（反转、惊讶多）
- 西幻：fear 信号需增强（恐怖、危险场景多）

#### 3.4.3 Index-TTS 情绪控制集成

情绪模块的最终价值在于**指导 TTS 如何说话**。Index-TTS 集成后：
- 情绪标签 → TTS 语气参数
- 置信度 → 情绪强度
- 需要重新定义情绪标注的评估标准（不再是"是否准确"，而是"TTS 效果是否好"）
