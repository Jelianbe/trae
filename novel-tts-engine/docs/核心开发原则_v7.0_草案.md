**版本**: 7.0-draft  
**日期**: 2026-05-13  
**替代**: v6.1 原则章节  
**状态**: 待审核

## 原则1：通用规则优先于静态词表

所有识别和判断逻辑必须基于**语言学结构**（语法位置、句法关系），不能依赖枚举式的静态词汇列表。

**示例**：
- ✅ 正确：检测"角色名 + 的 + 动作/属性 + 引号"这个结构来判断说话人
- ❌ 错误：维护一个 `[说道、问道、笑道、沉声道...]` 的说话动词列表来匹配

**如果必须保留某个静态集合**，必须满足以下全部条件：
1. 标注语言学或统计学来源（如《现代汉语语法》、网文高频统计等）
2. 标注集合性质（封闭集合 vs 经验枚举）
3. 设置上限约束（通过 assert 或文档声明）
4. 所有使用该集合的地方必须从**单一权威源**引用，禁止多处独立维护

**合规集合示例**：
- 中文人称代词 → 封闭集合，无需来源
- 复姓列表 → 源自《中国姓氏大辞典》，33项
- 说话动词 → 源自 GB/T 15834-2011 + 现代汉语语法，统一在 `speech_verb_detector.py` 中维护

**违规集合示例**：
- ❌ 在多个模块中各自定义说话动词列表
- ❌ 身份词映射表 `{"长老": "药老"}`（违反原则3，但同时也是静态词表问题）

## 原则2：不确定时返回"未知"，不做硬猜测

当系统无法以足够置信度确定说话人时，必须返回"未知"，而不是强行匹配一个可能的角色。

**原因**：强行猜测会引入错误，而且这些错误会污染角色库（创建错误角色、错误累计频率），导致后续识别进一步恶化。

**数据验证**：曾将"不确定就返回未知"改为"不确定就继续猜"，导致准确率从 76.4% 跌到 58.9%。回退后立即恢复。

**具体要求**：
1. 候选人生成阶段无候选时，必须返回 `('未知_无法推断', '无上下文线索', 0.30)`
2. 角色匹配阶段跳过以"未知_"开头的候选
3. 所有 Fallback 链仅在已有正向信号时触发（如 NER 发现人名、代词消解成功），不在"无任何线索"时尝试

## 原则3：禁止新增静态映射表

不允许创建"词A → 角色B"的静态映射。角色身份必须由**频率**（出现次数）和**上下文**（语法位置）动态决定。

**示例**：
- ❌ 错误：`身份词映射表 = {"长老": "药老", "掌柜": "孙掌柜"}`
- ✅ 正确：通过角色在全文中的累计出现频率和当前上下文的语法位置来推断

**已执行的清理**：身份词提取模块（`_extract_identity_words`）已从代码中完全删除。

**允许的例外**：
- "词 → 身份类型"映射（如自称词映射 `{"朕": "皇帝", "妾身": "女性"}`），因为不涉及具体角色
- "性别 → 词汇集合"（如 `GENDER_HINTS`），因为不涉及具体角色
- 语言学封闭集合（如复姓列表、人称代词列表），因为不涉及角色映射

**匹配精度约束**：头衔/描述性角色匹配必须使用**核心词精确匹配**，禁止使用子串包含（`in`）判断。例如：
- ✅ 正确：`"长老"` 的核心词是 `"长"`，只匹配核心词为 `"长"` 的角色
- ❌ 错误：`"长老"` 匹配任何名称包含 `"长"` 的角色（如"张长老"、"长生"）

## 原则4：修改后必须跑回归测试

任何对 `pipeline/` 下核心模块的修改，提交前必须运行：

```bash
# 标准测试集（73句）
python analysis_reports/评估脚本/evaluate_v6_improvements.py

# 真实小说测试（可选但推荐）
python tests/run_novel_test.py
```

**验收标准**：模式B准确率不得低于修改前。如果下降，必须定位根因并修复后才能提交。

**基准锁定机制**：每次修改前自动记录当前基线到 `analysis_reports/基线记录.md`，格式如下：

```markdown
## 基线记录 #N
- 日期：YYYY-MM-DD
- 修改内容：[简要描述]
- 修改前准确率：XX.X%
- 修改后准确率：XX.X%
- 变化：+/-X.X%
```

## 原则5：核心模块职责单一（决策权隔离）

每个模块有且仅有一个决策职责。允许跨模块读取数据，但**不允许越权做决策**。

### 职责定义

| 模块 | 决策权（只能做的事） | 允许读取的数据 | 禁止做的事 |
|------|---------------------|---------------|-----------|
| `nlp_basics.py` | HanLP 调用，输出原始 NER 结果 | 无 | 不做实体后处理，不查角色库，不做增强 |
| `entity_cleaner.py` | 实体完整性修复（扩展、修剪、过滤） | 角色库（仅用于修剪判断） | 不做候选人排序，不做角色匹配 |
| `speaker_matcher.py` | 候选人排序 + 角色匹配 + 上下文推理 | entity_cleaner 输出、角色库 | 不做实体清洗（委托给 entity_cleaner） |
| `character_manager.py` | 角色 CRUD + 持久化 + 频率管理 | 无 | 不参与匹配决策 |
| `speech_verb_detector.py` | 说话动词检测（唯一权威源） | 无 | 不参与角色匹配 |

### 核心概念：决策权 vs 数据访问权

- **决策权**：某模块是否有资格做出"这是不是说话人"、"这个词应该归哪个角色"等判断
- **数据访问权**：某模块是否可以读取其他模块的数据来辅助自己的决策

**示例**：
- `entity_cleaner` 可以读取角色库（数据访问权），但只能用来判断"这个实体是否被过扩展"（修剪决策），不能用来判断"这个词是说话人"（角色匹配决策）
- `speaker_matcher` 是唯一有权做出"这个词对应哪个角色"决策的模块

### 跨模块通信

通过 `SpeakerMatcher` 统一对外接口，不允许多个模块直接互相调用形成网状依赖。

## 原则6：角色身份由频率决定（含实施约束）

角色是否为"主要角色"，由其跨章节累计出现频率决定。

### 频率层级

| 层级 | frequency 阈值 | scope | 匹配优先级 | 存储 |
|------|---------------|-------|-----------|------|
| 临时 | < 3 | temp | 最低 | 仅内存，不持久化 |
| 单章角色 | 3 ≤ freq < 10 且仅 1 章出现 | chapter | 低 | SQLite |
| 项目角色 | 10 ≤ freq < 30 且跨章节 | project | 中 | SQLite |
| 主要角色 | freq ≥ 30 或用户锁定 | main | 最高 | SQLite |

### 晋升规则

1. 首次出现的角色名默认为临时角色（仅内存）
2. 达到频率阈值后自动晋升到对应层级
3. 晋升后持久化到 SQLite
4. 用户锁定可跳过频率阈值，直接成为主要角色

### 实施约束

**v7.0 前必须完成**：
1. `characters` 表新增 `frequency`、`scope`、`chapter_ids` 字段
2. 实现临时角色的内存存储（不持久化）
3. 实现频率阈值晋升逻辑
4. 匹配优先级按层级递减

**当前状态**：v6.1 中原则6标注为"未实现"，导致其形同虚设。v7.0 必须完成最小实现。

## 原则7：修复位置要对

每个问题只在它所属的模块里修，不允许跨模块牵连。

### 修复位置对照表

| 问题类型 | 修复位置 | 禁止位置 |
|---------|---------|---------|
| NER 分词问题 | `nlp_basics.py` 或 `entity_cleaner.py` | `speaker_matcher.py` 的候选人排序 |
| 说话动词识别问题 | `speech_verb_detector.py` | `_extract_context_speakers` |
| 实体过扩展 | `entity_cleaner.py` | `speaker_matcher.py` |
| 被动动作主体过滤 | `entity_cleaner.py` | `speaker_matcher.py` |
| 上下文推理逻辑 | `speaker_matcher.py` | 任何实体清洗模块 |

### 历史教训

- NER 分词问题 → 曾在 `speaker_matcher.py` 的候选人排序里打补丁 → 导致匹配器逻辑混乱 → 最终迁移回 `entity_cleaner.py` 修复
- 说话动词识别 → 曾在 6 个模块中独立维护 → 导致信息不同步 → 最终统一为 `speech_verb_detector.py`

## 原则8：上下文范围应由任务决定

不同任务需要不同粒度的上下文，不能一刀切。

### 上下文层级

| 任务 | 上下文粒度 | 范围 | 用途 |
|------|-----------|------|------|
| 说话人识别（"这句话谁说的"） | 局部 | 引号前后最近的文本 | 判断当前句的说话人 |
| 角色活跃度分析（"谁最活跃"） | 段落/章节 | 当前段落或当前章节 | 追踪角色出现频率 |
| 对话轮次推断（"下一句谁说的"） | 对话轮次 | 最近 N 轮对话 | A→B→A→B 模式推断 |
| 角色关系推断（"谁对谁说话"） | 对话 | 当前对话块 | 判断说话人和听话人关系 |

### 具体要求

1. **说话人识别**：使用当前引号前后的文本片段（局部上下文）
2. **角色活跃度**：在章节级别维护，不清空（跨段落连续）
3. **对话轮次**：追踪对话的 A→B 模式，保留最近 N 轮
4. **各层级数据独立维护**，不能混用：
   - `_recent_speakers`（活跃度）不应在每次 `analyze_dialogue` 时清空
   - 局部上下文（引号间文本）不应包含整章信息

### 评估脚本要求

评估脚本应支持两种模式：
- **逐段模式**（当前）：每段独立调用，用于快速回归测试
- **连续模式**：整章连续处理，段落间保持活跃度，用于模拟真实场景
