# 假设记录 H-20260515-05

- **日期**: 2026-05-15
- **投资类型**: 速赢
- **状态**: 已接受
- **对应的改造方案节**: 自定义 — 说话人检测+对话轮换+称呼排除综合优化

## 改动内容
三项综合优化，针对 45 条错误中 82% 的核心根因：

1. **说话动词检测增强（解决 71% 错误）**：
   - 在 `_extract_context_speakers()` 的角色库匹配中，只有"角色名+说话动词（道/说/问/答/笑道）"才赋予高置信度（0.75）
   - 纯动作描述（端起/翻开/走到/坐下/打开）只给低置信度（0.55），因为这些角色是动作执行者，不一定是当前说话人

2. **对话轮换模型（解决 71% 错误中的轮换部分）**：
   - 当 context_before 最后一条对话是"角色A 说：xxx"时，当前对话更可能是其他角色在回答
   - 对最近发言人施加额外惩罚（-0.15），使其在排序中低于其他候选

3. **称呼排除增强（解决 11% 错误）**：
   - 当对话以"XX，"开头时（如"赵总监，这个我..."），XX 是被称呼者而非说话人
   - 在候选池中降低被称呼角色的置信度（-0.20）

## 影响机制
当前系统的核心缺陷：将"旁白中提到角色"等同于"角色在说话"。
- "赵总监端起杯子" → 系统认为赵总监在说话 → 实际上赵总监说完后是别人在回答
- "赵总监，xxx" → 系统认为赵总监在说话 → 实际上赵总监是被称呼者

三项优化后：
- 动作描述不再赋予高置信度，减少误判
- 对话轮换让系统理解"A 说完后 B 回答"的模式
- 称呼排除防止被称呼者被误认为说话人

## 可证伪条件（必填）
如果发生以下现象，说明我的因果推理是错的：
- **改动后"角色库旁白匹配(动作主语)"类型的正确率反而上升**，说明动作主语检测本身不是问题，而是其他特征导致的误判
- **短文本准确率下降超过 5%**，说明对话轮换和称呼排除的逻辑过于激进，破坏了简单场景的匹配
- **"未知"跳过的对话数增加超过 50%**，说明置信度降得太低，导致大量候选被过滤

## 预期效果
- 指标: 都市长文本说话人识别准确率
- 当前基线: 47.1%（40/85）
- 目标值: ≥70%（提升 ≥23%，解决 82% 的错误根因）
- 不作牺牲: 短文本准确率不低于 72%

- 变化: +5.9%
- 短文本准确率: 77.0% → 75.7%（-1.3%，在容忍带内）
- UNKNOWN 数变化: 未增加
- 留出集方向: 不适用
- 决策: 接受
- 原因: 
  1. 长文本从 40.0% 提升至 45.9%（+5.9%，未达目标 +12% 但显著正向）

  3. 说话动词检测增强有效：区分"角色在说话"vs"角色做动作"解决了 ~18% 的错误
  4. 称呼排除增强有效：解决了 ~11% 的错误
  5. 对话轮换模型效果有限：仅在置信度 < 0.70 时触发，覆盖范围不足
