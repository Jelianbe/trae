### 改动内容

为角色候选池引入频次过滤机制：每个角色名在分析中被提及一次，后台计数器+1。当计数器 < CHARACTER_ELIGIBLE_MIN_FREQ (=5) 时，该角色不进入 speaker_matcher 的候选人池。

### 影响机制

**因果链：**
```
角色名在文本中出现 → 计数器+1（仅计数，不加入候选池）
  ↓
计数器 ≥ 5 → 角色进入候选人池，可被 match_speaker 选为说话人
  ↓
计数器 < 5 → 角色不出现在候选人池中，不参与匹配竞争
```

**核心逻辑：**
- 角色仍然正常创建到 DB（`add_character` / `find_or_create` 行为不变）
- 活动度追踪（`update_activity` / `_character_activity`）不变
- **唯一变化**：`get_all_characters()` 的调用被 `get_eligible_characters()` 替换——只返回频次达标的角色

**原因：** 长文本场景下，临时角色（服务员、路人、报信者等一次性角色）与主要角色在候选池中平等竞争，导致候选池信噪比下降。频次过滤使一次性角色自然沉淀，仅高频角色（大概率是主要角色）进入候选池。

### 预期效果

- **长文本准确率**: 当前 51.8% → 目标 ≥ 55.0%（+3.2%）
- **短文本准确率**: 当前 75.3% → 不降（或微降 ≤ 1%）
- **候选池平均大小**: 预期减少 30~50%（当前角色库可能含较多一次性临时角色）

### 可证伪条件

1. 长文本准确率下降超过 2% → 假设不成立，回退
2. 长文本准确率未提升但短文本下降超过 2% → 假设不成立，回退
3. 长文本准确率提升 < 0.5% 且短文本下降 → 假设不成立，回退
4. 长文本中新增"未知说话人"结果超过 3 条 → 表明阈值过高，需要调整

### 验证方式

1. 运行 `python tests/test_urban_long_text.py` → 对比当前基线 51.8% (44/85)
2. 运行 `python tests/baseline_rules_speaker.py` → 对比当前基线 75.3% (183/243)
3. 分类统计：正确 / 错误 / 未知 分布变化
4. 检查 `_extract_context_speakers` 返回的候选人数

### 回退条件

- 长文本准确率低于 49.8%（当前 -2%）
- 或短文本准确率低于 73.3%（当前 -2%）
- 满足任一条件立即从备份恢复

## 改动说明

### 涉及文件

| 文件 | 改动类型 | 说明 |
|------|---------|------|
| `utils/config.py` | 新增常量 | 加 `CHARACTER_ELIGIBLE_MIN_FREQ = 5` |
| `pipeline/character_manager.py` | 新增方法 | 加 `_frequency_map` + `increment_frequency()` + `get_eligible_characters()` |
| `pipeline/speaker_matcher.py` | 替换调用 + 加钩子 | 候选池处 `get_all_characters()` → `get_eligible_characters()`；关键入口加 `increment_frequency()` |

### 改动细则

**1. config.py**
```python
CHARACTER_ELIGIBLE_MIN_FREQ: int = int(os.environ.get('CHARACTER_ELIGIBLE_MIN_FREQ', '5'))
```

**2. character_manager.py**
- `__init__`: 加 `self._frequency_map: Dict[str, Dict[str, int]] = {}`
- 新方法 `increment_frequency(name, project_id)`: 频次+1
- 新方法 `get_frequency(name, project_id) -> int`: 查询频次
- 新方法 `get_eligible_characters(project_id, min_freq) -> List[Character]`: 仅返回频次≥min_freq 的角色

**3. speaker_matcher.py** — 替换 `get_all_characters()` 在候选池的 6+ 处调用
- `_extract_context_speakers` 的语境角色优先、动态候选、旁白匹配
- `_extract_action_subject`
- `_find_nearby_characters`
- `_infer_from_address`
- `match_by_semantic` (L2)
- `match_by_trigger_words` 的 ADDRESS_TRIGGERS 分支

频次递增钩子加在：
- `_register_temporary_character()` — 尝试注册时
- `_extract_context_speakers()` — 每个候选生成后
- `_extract_from_ner()` — NER 提取后
- `update_activity()` — 角色活动时

### 不修改
- 数据库 Schema
- `add_character` / `find_or_create`
- 活动度追踪算法本身
- 其他模块（hybrid_speaker_matcher / entity_linker / entity_cleaner 等）

## 实验结果

| 指标 | 基线 | 改后 | 变化 |
|------|------|------|------|
| 长文本准确率 | 51.8% (44/85) | 51.8% (44/85) | ±0% |
| 短文本准确率 | 75.3% (183/243) | 75.3% (183/243) | ±0% |
| 长文本正确 | 44 | 44 | — |
| 长文本错误 | 41 | 41 | — |
| 长文本未知 | 6 | 6 | — |

**分析**：测试中所有 6 个角色均为预注册（`freq==0`），不在频次过滤范围内。候选池大小不变，因此结果完全一致。零退化证明改动安全，但**在当前测试集上无实际收益**，因为测试没有模拟动态角色发现的场景。

**决策**: ❌ 已回退 — 测试集预先注册了所有角色，频次过滤机制未实际命中。判定为"设计正确但当前测试无法验证"，用户选择回退。
