## 一、改造目标

**一句话**：把项目从"技术展示品"变成"能用的产品"。

### 核心功能范围（MVP）

| 模块 | 状态 | 说明 |
|------|------|------|
| 章节划分 | ✅ 保留 | 基础结构功能 |
| NER人名识别 | ✅ 保留 | 角色识别基础 |
| 说话角色过滤 | ✅ 保留 | 过滤非人名候选 |
| 实体链接 | ✅ 保留（简化） | 仅保留精确匹配+别名 |
| 说话人匹配 | ✅ 保留 | 六级漏斗，当前52-71%准确率 |
| 情绪标注 | ✅ 保留 | 接受28-30%准确率，置信度透明输出 |
| TTS音频生成 | ✅ 保留 | Kokoro默认，Index-TTS可选 |
| 拟声词检测 | 📦 储备 | 前端不渲染，TTS不支持音效 |
| 引号内容分类 | 📦 储备 | 用户只需对话/旁白，不需要心理描写 |
| 上下文多样性验证 | ✅ 保留 | NER管道的必要环节，过滤低质量实体，不应移除 |
| 实体聚类 | 📦 储备 | 别名精确匹配已够 MVP 用（恢复条件见2.5） |

### 改造后的Pipeline

```
输入: 小说文本 (.txt)
    ↓
[章节划分器] ChapterSplitter
    ↓ 输出: List[Chapter]
    
[NER分析器] NLPBasics (简化版)
    - 仅保留人名识别
    ↓ 输出: List[Entity]
    
[说话角色过滤器] SpeakerRoleFilter
    ↓ 输出: List[Entity]
    
[实体链接器] EntityLinker (简化版)
    - 精确匹配 + 基础别名
    ↓ 输出: List[LinkedEntity]
    
[说话人匹配器] SpeakerMatcher
    - 六级漏斗逻辑
    ↓ 输出: SentenceData.speaker
    
[情绪标注器] EmotionExtractor (降级版)
    - 规则系统，接受28-30%准确率
    ↓ 输出: SentenceData.emotion
    
[TTS生成器] TTSGenerator
    - Kokoro默认，Index-TTS可选
    - 对话/旁白声线分离
    ↓ 输出: 音频文件
```

## 四、执行计划

> **关键路径**：阶段A → 阶段B → 阶段C → 阶段D → 阶段E  
> **最短完成时间**：约 5 天 | **最长完成时间**：约 7 天

### 阶段A：数据库简化（0.5-1天）

> 自底向上原则：先定数据库结构，后续所有代码改造以此为基准

| 任务 | 状态 |
|------|------|
| 更新 schema.sql（简化表结构，移除 sfx_words、progress 表） | ⏳ |
| 编写数据迁移脚本 | ⏳ |

**DoD（完成标准）**：
1. `sqlite3 novel_tts.db ".schema"` 输出的表结构与方案第2.3节定义一致
2. 数据迁移后，原 characters/sentences 表数据100%无损迁移
3. 启动 backend/main.py，对已有 project 执行 `GET /api/v1/projects/{id}/chapters/{idx}` 不报错

### 阶段B：Index-TTS 独立验证（0.5-1天）← 关键路径

> 在所有代码改造之前验证核心引擎。验证不通过→MVP方案需要重新评估。

| 任务 | 说明 | 状态 |
|------|------|------|
| Index-TTS 音质验证 | 用测试文本生成完整音频，确认音质达标（盲测>=4/5） | ⏳ |
| 角色声线区分验证 | 3+不同说话人分配不同音色，人工可明显区分 | ⏳ |
| 情感向量参数验证 | 同一文本不同 emotion_vector，生成2个版本，人工可感知语气差异 | ⏳ |
| 中文发音准确率验证 | 检查专有名词、生僻字发音准确性 | ⏳ |

**DoD（完成标准）**：
1. 至少10个样本盲测，人工评分 >= 4/5
2. 3+不同说话人声线可区分
3. 同一文本不同 emotion_vector，语气差异可感知

**验证结果决策**：
- ✅ 通过 → MVP默认引擎改为 Index-TTS
- ❌ 不通过 → MVP保留 Kokoro 默认，Index-TTS 作为可选

## 六、风险评估

| 风险 | 可能性 | 影响 | 应对 |
|------|--------|------|------|
| 阶段C 移动文件后未断开 import 导致 pipeline 崩溃 | 极高(90%) | **致命** | 阶段C 必须同步完成移动+断开 import，不可分步 |
| Index-TTS 验证不通过但 MVP 强行发布 | 高(70%) | **严重** | 阶段B 有明确 DoD，不通过则保留 Kokoro 默认 |
| 数据库迁移丢失数据 | 低 | 高 | 完整备份，迁移后验证行数一致 |

| 储备模块恢复困难 | 低 | 中 | recovery_guide.md 写清楚依赖和步骤 |
| SentenceData 字段移除导致兼容问题 | 中 | 中 | 保留向后兼容的默认值 |
