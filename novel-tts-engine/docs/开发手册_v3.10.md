## 1. 项目概览

### 1.1 项目目标

将小说文本自动处理为 TTS 引擎可用的结构化数据，包括：
- 章节划分
- 对话识别与分类
- 拟声词检测
- 命名实体识别（NER）
- 说话人匹配

### 1.2 技术栈

| 组件 | 技术 |
|------|------|
| NER | HanLP |
| 语义排序 | BGE-small-zh（512维，ONNX Runtime） |
| 章节划分 | 正则匹配（第X章/卷/回） |
| 对话分类 | DialogueClassifier（规则+统计） |
| 说话人匹配 | SpeakerMatcher（多漏斗匹配） |

### 1.3 当前基线（E.11，三轮稳定性测试，标准差均为 0）

| 模块 | 都市异能 | 西幻 | 修仙 |
|------|---------|------|------|
| 章节划分 | 100.0 | 100.0 | 100.0 |
| 对话分类 | 100.0 | 100.0 | 100.0 |
| 拟声词检测 | 88.9 | 90.0 | 80.8 |
| NER | 74.0 | 55.6 | 75.2 |
| 说话人匹配 | 76.2 | 65.6 | 72.5 |
| **平均得分** | **87.8** | **82.2** | **85.7** |

## 2. 核心架构

### 2.1 数据流

```
输入文本 → chapter_splitter → dialogue_classifier → sfx_detector
  → nlp_basics(NER) → context_diversity_validator → speaker_role_filter
  → character_manager → speaker_matcher → semantic_ranker(L2)
```

### 2.2 关键设计模式

**全局单例模式**: 以下模块使用全局单例，避免重复加载模型：
- `get_nlp()` - NLPBasics
- `get_context_validator()` - ContextDiversityValidator
- `get_semantic_ranker()` - SemanticRanker
- `get_character_manager()` - CharacterManager
- `get_speaker_role_filter()` - SpeakerRoleFilter

**置信度管道**: 实体处理遵循三层过滤：
1. 原始 NER（HanLP 输出，confidence=0.9）
2. ContextDiversityValidator（统计验证，调整置信度）
3. SpeakerRoleFilter（场景过滤，只保留说话角色）

最终取 confidence >= 0.5 的实体。


## 3. 模块开发规范

### 3.1 NER 实体处理

**Entity 数据类**:
```python
@dataclass
class Entity:
    text: str
    type: str  # PER, LOC, ORG
    start: int
    end: int
    confidence: float = 1.0
```

**置信度阈值**:
- >= 0.8: 高置信度
- >= 0.5: 有效实体
- < 0.5: 过滤掉

### 3.2 说话人匹配规则

**匹配优先级**（从高到低）:
1. 显式说话人提示（"XX说道"）
2. 对话历史缓存（最近发言者）
3. 角色活动热度（最近活跃角色）
4. L2 语义相似度（BGE-small-zh）
5. 默认角色

**别名处理**: 必须在处理前注册角色别名，否则匹配失败。

### 3.3 对话上下文提取（SpeakerRoleFilter）

**支持四种模式**:
1. **引号前**: `"XX说道："` 左引号前 15 字符窗口
2. **引号后**: `"..."老陈说道。` 右引号后的"XX说道"
3. **引号中间**: `"..."，老陈说道，"..."` 对话中间的说话人提示
4. **声音描述**: `"..."是部门经理老陈的声音。` "是XX的声音/话"格式

**过滤策略**:
- 只对 PER 实体进行说话角色过滤
- ORG/LOC 实体直接放行
- 低频实体（< 2 次）降级置信度
- 多场景出现的实体通过 L2 提升置信度

## 4. 十大改进经验总结

### E.1-E.3: 基础管道建设
- **E.1**: 建立 v1 评估方法（简化正则）
- **E.2**: 使用完整算法管道替代测试脚本中的正则模拟
- **E.3**: 引入别名注册机制，提升说话人匹配率

### E.4-E.6: NER 精确率提升
- **E.4**: 按类型分别计算 NER F1（PER/LOC/ORG），更精准定位问题
- **E.5**: 增强 `_enhance_entities` 规则，支持"老X"、"X总"等中文称呼
- **E.6**: ContextDiversityValidator 上线，都市 NER 55.7% → 73.3%

### E.7-E.10: 说话角色收敛

- **E.7**: NER 规则增强对西幻产生负面影响，需要文体感知策略
- **E.8**: ContextDiversityValidator 白名单机制保护 GT 实体
- **E.9-E.10 说话角色收敛**: 从识别全文所有人名转为只识别对话中出现的说话角色。这个策略转变让 NER 和 SpeakerMatcher 的目标直接对齐——NER 的输出恰好是 SpeakerMatcher 需要的输入，不再有旁白角色污染候选池。SpeakerRoleFilter 上线后，E.10 扩展对话上下文提取到四种模式，都市 NER 稳定在 70%，西幻 NER 开始回升（53.0% → 55.6%）。这是本轮最重要的方向性决策。

### 核心教训

| 经验 | 说明 |
|------|------|
| 测试脚本 ≠ 生产代码 | 必须用真实算法管道评估，不能用正则模拟 |
| 白名单保护 | GT 实体必须加入白名单，不受统计验证降级影响 |
| 上下文窗口要足够 | 15 字符窗口不够，需要支持引号后、引号中间等多种模式 |
| 类型过滤要精准 | 只对 PER 过滤，ORG/LOC 直接放行 |
| 文体差异要关注 | 都市和西幻的 NER 表现差异大，需要差异化策略 |

## 5. 已知问题与解决方案

### 5.1 问题优先级与解决路径

| 优先级 | 问题 | 影响范围 | 解决路径 |
|--------|------|---------|---------|
| **P0** | 西幻 NER 55.6% | 西幻文体泛化能力 | 角色聚类模块（蓝图第三阶段后半段），通过实体链接合并同一角色的多种称呼 |
| **P1** | 说话人匹配 76.2% | 都市异能体验 | L2 在 SpeakerMatcher 内部建立对话历史缓存（当前只在评估脚本中建立） |
| **P2** | 群体说话人（"三人"、"众人"） | 所有文体 | 规则层处理，"三人/众人"映射为特殊标记 |
| **P3** | 西幻 L2 触发不稳定 | 西幻语义排序 | 排查 ONNX 和 PyTorch 后端切换导致的模型加载路径问题 |

### 5.2 详细问题清单

**NER 问题**:

| 问题 | 根因 | 状态 |
|------|------|------|
| "老陈"被 HanLP 识别不完整 | 简称识别困难 | ✅ 已解决（模式4） |
| "张总"被误认为说话角色 | 出现在对话上下文中但不是 GT 角色 | ⚠️ 部分解决 |
| 单字人名（"苏"、"张"）误检 | HanLP 将单字识别为 PER | ⚠️ 部分解决 |

**说话人匹配问题**:

| 问题 | 根因 | 状态 |
|------|------|------|
| 西幻说话人匹配偏低（65.6%） | 对话格式复杂，跨行对话多 | ❌ 待解决（P1） |
| L2 语义排序效果不明显 | BGE 模型对角色名相似度区分度不够 | ⚠️ 待优化 |

**拟声词检测问题**:

| 问题 | 根因 | 状态 |
|------|------|------|
| 部分拟声词不在词典中 | DEFAULT_SFX_WORDS 不完整 | ⚠️ 部分解决 |
| 重复拟声词只检测一次 | 去重逻辑过于激进 | ⚠️ 待优化 |

## 6. 测试与评估

### 6.1 运行测试

```bash
# 运行 v3 泛化性测试
python analysis_reports/评估脚本/run_v3_tests.py

# 指定小说和 GT 文件
python analysis_reports/评估脚本/evaluate_generalization_v3.py \
  tests/test_novel_urban.txt \
  tests/test_novel_urban_ground_truth.json
```

### 6.2 GT 文件格式

```json
{
  "novel": "test_novel_urban",
  "style": "都市异能",
  "chapters": {
    "total_expected": 7,
    "volumes": 2,
    "chapter_titles": ["第一章 异能觉醒", ...]
  },
  "对话分类": {
    "总对话数": 42
  },
  "sfx": {
    "sfx_words": ["轰隆", "劈啪", ...]
  },
  "entities": {
    "persons": ["苏夜", "林雪", ...],
    "speaking_persons": ["苏夜", "林雪", ...],
    "organizations": ["暗影会", ...],
    "locations": [],
    "aliases": {
      "苏夜": ["苏先生"]
    }
  },
  "dialogue_speakers": [
    {"text": "苏夜，你在这里！", "speaker": "林雪"}
  ]
}
```

**关键字段**:
- `speaking_persons`: 仅包含实际说话的角色（E.9 新增）
- `aliases`: 角色别名映射
- `dialogue_speakers`: 对话-说话人映射

### 6.3 评估标准

| 得分 | 状态 |
|------|------|
| >= 90 | 生产可用（优秀） |
| >= 85 | 生产可用（良好） |
| >= 75 | 基本可用 |
| < 75 | 需要改进 |

### 6.4 如何添加新测试文本

添加新文体测试的步骤：

**步骤1：准备测试小说**
- 编写或收集目标文体的小说文本，保存为 `tests/test_novel_<类型>.txt`
- 建议长度：3000-10000 字，覆盖至少 5 个章节

**步骤2：编写 GT 文件**
- 创建 `tests/test_novel_<类型>_ground_truth.json`
- 按 v3 格式编写，重点标注以下字段：
  - `speaking_persons`：仅包含实际说话的角色（不含旁白中出现的角色）
  - `dialogue_speakers`：逐条标注每句对话的说话人
  - `persons`：所有出现的人名（包含不说话的配角）
  - `organizations`、`locations`：组织和地点
  - `aliases`：角色别名映射

**步骤3：运行评估**
```bash
python analysis_reports/评估脚本/evaluate_generalization_v3.py \
  tests/test_novel_<类型>.txt \
  tests/test_novel_<类型>_ground_truth.json
```

**步骤4：记录结果**
- 将各项得分记录到 `analysis_reports/测试报告/泛化性测试报告_20260502_001700.md` 中
- 对比已有文体的得分，分析差异原因
- 如果某个模块得分低于 75，需要单独编写调试脚本定位问题

**GT 文件编写注意事项**:
- `speaking_persons` 是 NER 评估的关键，必须准确标注所有实际说话的角色
- `dialogue_speakers` 中的 `text` 字段只需截取对话的前 30 字即可
- 如果存在交织对话（同一行多人说话），需要拆分为多条记录

## 7. 命名与文件规范

### 7.1 文件命名

| 类型 | 格式 | 示例 |
|------|------|------|
| 测试报告 | `中文类型_YYYYMMDD_HHMMSS.md` | `泛化性测试报告_20260502_001700.md` |
| 算法方案 | `中文描述_YYYYMMDD.txt` | `说话角色过滤器SpeakerRoleFilter完整方案_20260502.txt` |
| 测试小说 | `test_novel_类型.txt` | `test_novel_urban.txt` |
| GT 文件 | `test_novel_类型_ground_truth.json` | `test_novel_urban_ground_truth.json` |

### 7.2 目录分类

```
analysis_reports/
├── 测试报告/        # .md 测试报告
├── 算法报告/        # .txt 算法方案
├── 评估脚本/        # 评估运行脚本
├── 调试脚本/        # 临时调试脚本
└── 测试原始数据/    # 测试用原始文本文件
```

### 7.3 根目录规则

- **根目录必须为空**: 禁止在 `analysis_reports/` 根目录放置 .md/.txt 文件
- **禁止嵌套**: 不允许出现子目录中的子目录
- **定期清理**: 调试脚本用完后移入 `调试脚本/` 或删除
