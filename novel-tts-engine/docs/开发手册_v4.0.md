## 1. 项目概览

### 1.1 项目目标

Novel-TTS-Engine 是一个面向中文网文的离线 TTS 预处理引擎。核心目标：将非结构化的小说文本自动转换为**带说话角色标注、情绪标注、音效标记的结构化数据**，供下游 TTS 引擎生成多角色、多情绪的有声书音频。

### 1.2 关键设计原则

1. **离线优先**：不依赖外部 API，所有 NLP 模型本地运行
2. **中文网文优化**：针对网络小说的语言特点（别名、称号、省略号、口语化）专门设计
3. **双管道架构**：角色识别与情绪标注并行处理，互不依赖
4. **冷启动机制**：前 3000 字自动构建角色画像，后续动态更新
5. **降级策略**：任何模块失败不阻塞整条流水线
6. **通则推理、拒绝猜测、标识未知**：证据不足时诚实标注"未知"，不再硬猜测

### 1.3 技术栈

| 层级 | 技术 | 用途 |
|------|------|------|
| NLP 基础 | HanLP (本地模型) | 分词、词性标注、NER |
| 语义匹配 | BGE-base-zh / BGE-small-zh | 角色语义相似度排序 |
| 实体聚类 | sentence-transformers | 别名归一化 |
| LLM 基准 | Qwen2.5-1.5B-Instruct | 情绪标注 ML benchmark |
| TTS 引擎 | Kokoro 82M (离线) ⚠️ *待 Index-TTS 集成后替换* | 语音生成 |
| 数据库 | SQLite | 角色画像持久化 |

| 组件 | 技术 |
|------|------|
| 章节划分 | 正则匹配（第X章、第X回） |
| 对话分类 | DialogueClassifier（规则+统计） |
| 说话人匹配 | SpeakerMatcher（多漏斗匹配） |
| 音频合并 | pydub + soundfile（自动回退） |

### 2.3 数据流

```
输入文本
  ↓
  ├─ 公共阶段
  │   ├─ chapter_splitter → dialogue_classifier → sfx_detector
  │   ├─ nlp_basics(NER) → context_diversity_validator → speaker_role_filter
  │   ├─ character_manager → speaker_matcher → semantic_ranker(L2)
  │   └─ backfill_unknown_speakers（冷启动回填）
  │
  ├─ 管道1（角色管道）：保持现有逻辑 → speaker 输出
  │
  └─ 管道2（情绪管道）：emotion_extractor → emotion 输出
       独立于管道1，直接从原始文本窗口提取情绪特征
       
  └─ 合并层：speaker 决定声线，emotion 决定语气 → tts_generator
     → 音频合并 → 输出（JSON + MP3/WAV）
```

### 2.4 数据模型

**核心数据结构** (定义于 `pipeline_runner.py`):

```python
@dataclass
class SentenceData:
    text: str                     # 句子文本
    type: str                     # "dialogue" | "narration"
    speaker: str                  # 说话人名称
    emotion: str                  # joy/anger/sadness/surprise/fear/neutral
    speed: float                  # 语速倍率 (默认 1.0)
    tone: str                     # 音调 (normal/high/low)
    sfx: List[str]               # 拟声词列表
    entities: List[dict]         # 命名实体列表
    sentence_id: int             # 句子序号
    quotation_type: str          # none/dialogue/written/thought
    sentence_start: int          # 原文起始位置
    sentence_end: int            # 原文结束位置

@dataclass
class ChapterResult:
    chapter_id: int
    title: str
    volume: int
    sentences: List[SentenceData]
    statistics: dict
```

### 2.5 关键设计模式

**全局单例模式**: 以下模块使用全局单例，避免重复加载模型：
- `get_nlp()` - NLPBasics
- `get_emotion_extractor()` - EmotionExtractor
- `get_emotion_tagger()` - EmotionTagger
- `get_character_manager()` - CharacterManager（使用连接池，线程安全）
- `get_semantic_ranker()` - SemanticRanker
- `get_entity_clusterer()` - EntityClusterer
- `get_entity_linker(char_manager)` - EntityLinker
- `get_context_validator()` - ContextDiversityValidator
- `get_speaker_role_filter()` - SpeakerRoleFilter
- `get_kokoro_generator()` - KokoroTTSGenerator
- `get_pipeline_runner()` - PipelineRunner

**置信度管道**: 实体处理遵循四层过滤：
1. 原始 NER（HanLP 输出，confidence=0.9）
2. ContextDiversityValidator（统计验证 + 误合并检测）
   - 统计验证：根据右邻字多样性、出现次数、章节分布调整置信度
   - 误合并检测（2026-05-03 新增）：检测"人名+动词"误合并（如"萧炎道" → "萧炎" + "道"）
3. SpeakerRoleFilter（场景过滤，只保留说话角色）
   - 高频实体保留（2026-05-03 新增）：出现次数 >= 3 的 PER 实体即使未出现在对话上下文中也放行
   - 多引号类型支持（2026-05-03 新增）：支持 `""「」『』''` 等所有中文小说常见引号
   - L2 补偿限制：不能超过原始置信度的 1.5 倍
4. EntityLinker（别名映射）

最终取 confidence >= 0.5 的实体

**管道一致性保证**（2026-05-03 新增）:
- 统计验证降级的实体不能被后续组件提升到高于原始值的 1.5 倍
- 误合并检测在 `ContextDiversityValidator` 中执行，利用全文级别统计信息
- 已创建 `test_pipeline_consistency.py` 单元测试，防止未来违反此原则

## 3. 核心模块详解

### 3.1 章节划分 (`chapter_splitter.py`)

**职责**：将连续小说文本按章节标题分割为结构化章节。
**算法**：多正则优先级匹配，支持 7 种章节标题格式 + 3 种卷标题格式。

### 3.2 NLP 基础 (`nlp_basics.py`)

**职责**：提供分词、词性标注、命名实体识别基础能力。
**核心功能**：
- 基于 HanLP 的中文分词与词性标注
- PER/LOC/ORG 实体提取
- **虚假人名过滤** (`_filter_false_persons`)：通过词典+上下文规则过滤非人名 PER 实体
- **外文名合并** (`enable_foreign_name_merge`)：将 "亚历山大·普希金" 合并为单个实体
- 章节标题过滤：自动排除章节标题中的干扰实体

### 3.3 对话分类 (`dialogue_classifier.py`)

**职责**：识别文本中的对话片段。
**算法**：基于引号类型（`""「」『』''`）和对话标记词（`说：`, `道：`, `问道`）的混合匹配。

### 3.4 拟声词检测 (`sfx_detector.py`)

**职责**：检测文本中的拟声词（如 "轰隆隆", "哗啦啦"），供 TTS 引擎添加音效。
**算法**：
1. 预定义拟声词词典（500+ 词条）
2. 正则模式匹配（ABB 型如 "轰隆隆", ABAB 型如 "哗啦哗啦"）
3. 去重机制：相邻重复拟声词合并

### 3.5 角色管理 (`character_manager.py`)

**职责**：管理所有角色的身份信息、别名、性别、活跃状态。
**数据结构**：
```python
@dataclass
class Character:
    name: str                      # 主名称
    aliases: Set[str]             # 别名集合
    gender: str                   # male/female/unknown
    titles: Set[str]             # 头衔/称号
    is_confirmed: bool           # 是否已确认
    dialogue_history: List[str]  # 对话历史（用于画像更新）
    last_seen_chapter: int       # 最后出现章节
```

### 3.6 实体聚类 (`entity_clusterer.py`)

**职责**：将不同称呼归一化为同一角色（如 "苏夜"、"苏兄"、"苏公子" → "苏夜"）。
**算法**：
1. 使用 BGE 向量计算实体间语义相似度
2. 层次聚类（threshold=0.6）
3. 降级策略：无向量时使用编辑距离
4. 写回机制：将聚类结果写回 CharacterManager

### 3.7 实体链接 (`entity_linker.py`)

**职责**：将 NER 提取的实体链接到已注册角色。
**算法**：精确匹配 + 别名匹配 + 模糊匹配。

### 3.8 上下文多样性验证 (`context_diversity_validator.py`)

**职责**：验证 NER 实体的有效性，过滤低质量实体。
**算法**：基于右侧相邻字符多样性统计（右邻字符种类 < 阈值 → 可能是误识别）。

### 3.9 说话角色过滤 (`speaker_role_filter.py`)

**职责**：只保留出现在对话上下文中的 PER 实体。
**算法**：
1. 扩展引号匹配（支持 `""「」『』''`）
2. 提取引号内对话周围的实体
3. **高频实体保留**：出现 >= 3 次的实体跳过对话上下文检查

## 4. 数据处理流程

### 4.1 流水线步骤
```
Step 0: 输入验证（文本非空、长度 <= 10MB）
   → Step 1: 章节划分（ChapterSplitter）
     输出: List[Chapter]
   → Step 2: NER 分析（NLPBasics.analyze）
     输出: List[Entity]
   → Step 2.1: 上下文多样性验证（ContextDiversityValidator）
     过滤低质量实体
   → Step 2.2: 说话角色过滤（SpeakerRoleFilter）
     只保留对话上下文中的 PER 实体
   → Step 3: 实体链接（EntityLinker）
     将实体链接到已注册角色
   → Step 4: 拟声词检测（SfxDetector）
     输出: List[SfxWord]
   → Step 5: 说话人匹配（SpeakerMatcher）
     输出: Dict[dialogue_text → speaker_name]
   → Step 6: 情绪标注（双管道并行）
     管道1: emotion_tagger.tag()（基于规则的旧系统）
     管道2: emotion_extractor.classify()（基于文本特征的新系统）
     合并: 优先管道2 (confidence >= 0.5)
     输出: List[ChapterResult] → 可导出为 JSON / SSML
```

### 4.2 冷启动机制
```
处理前 N 章 → 累积实体 → 达到 COLD_START_CHARS_THRESHOLD (3000字)
   → 触发批量聚类（EntityClusterer.cluster(write_back=True)）
   → 所有 PER 实体升级为 is_confirmed=1
   → 回填未知说话人：用全文角色库重新匹配前3000字内的"未知_角色"
   → 后续章节使用完整角色画像
```

### 4.3 暂停/恢复机制

- 基于 `threading.Event` 实现
- 每个章节处理前检查暂停状态
- 支持进度回调 (`progress_callback`)

## 5. 双管道情绪标注架构

### 5.1 架构背景

旧系统（单管道）的问题：
- 情绪标注依赖角色匹配完成后的 `emotion_tagger.tag(sentence, speaker)`
- 角色匹配准确率高（F1=92.3%），但情绪标注 F1 仅 26.7%
- 情绪信号存在于原始文本中，不应等角色匹配完再标注

### 5.2 方案设计（方案B）
```
原始文本窗口
    ↓
    ├─ 管道1（角色）：speaker_matcher → speaker 决定声线
    │  └─ ROLE_VOICE_MAP.get(speaker, default_voice)
    └─ 管道2（情绪）：emotion_extractor → emotion 决定语气
       └─ emotion_extractor.classify(emotion_context)
          情绪信号：标点密度、感叹号、脏话、句式、情绪词、重复模式
          合并策略：优先管道2（confidence >= 0.5），否则与管道1投票
```

**核心思想**：情绪提取完全独立于角色管道，从原始文本窗口直接提取。

### 5.3 合并策略

```python
# 管道2 结果
emotion_feature, emotion_conf = emotion_extractor.classify(emotion_context)

if emotion_conf >= 0.5:
    emotion = emotion_feature           # 管道2 置信度高，直接使用
else:
    # 与旧规则系统投票
    rule_emotion = emotion_tagger.tag(sentence, speaker)
    if rule_emotion != 'neutral':
        emotion = rule_emotion          # 旧系统有明确判断，使用旧系统
    else:
        emotion = emotion_feature       # 否则使用管道2
```

## 6. 情绪提取器（EmotionExtractor）

### 6.1 模块信息

- **文件**: `pipeline/emotion_extractor.py`
- **设计原则**: 不依赖管道1（角色管道）的任何输出
- **情绪类别**: joy, anger, sadness, surprise, fear, neutral（6 类）

### 6.2 特征体系

| 特征类型 | 具体特征 | 权重 |
|---------|---------|------|
| 标点密度 | 感叹号密度、问号密度、省略号计数 | 基础 |
| 句式特征 | 感叹句、反问句、祈使句、短句连续 | +0.2~0.4 |
| 情绪词 | 脏话/粗口词表（40+词条）、情绪副词（20+）、情绪动词（20+） | +0.3~0.5 |
| 关键词 | 恐惧词、悲伤词、惊讶词、喜悦词 | +0.3~0.4 |
| 重复模式 | 字符重复 3+ 次 | +0.1 |

### 6.3 打分规则（部分核心规则）

**ANGER（愤怒）**：
- 脏话命中：+0.5
- 感叹号密度 > 0.3 + 祈使句：+0.3
- 祈使句 + 感叹号（非恐惧场景）：+0.15
- 情绪动词（怒吼、咆哮）：+0.2
- 宣言类（河东/河西/放肆/狂妄）：+0.4

**FEAR（恐惧）**：
- 情绪动词 + 颤抖/发抖/哆嗦：+0.4
- "害怕"/"恐惧"/"别伤害"：+0.3
- "不要"+"不要过来"：+0.4
- "恐惧"：+0.4

**SURPRISE（惊讶）**：
- 反问句：+0.3
- "怎么"/"居然"/"竟然"/"天哪"：+0.4
- 高感叹号(>=2) + 非愤怒词：+0.2
- "还活着"/"没死"/"不敢相信"：+0.4

**JOY（喜悦）**：
- 感叹句模式（哈哈、太好了）：+0.4
- 笑声/笑：+0.3
- "完美"/"赢了"/"太好了"：+0.3
- "哼"+"本事/就这/这点"（嘲讽）：+0.4

### 6.4 置信度阈值
```python
# 如果最高分 <= 0.35，归为 neutral
if best_score <= 0.35:
    return 'neutral', 0.3
```

## 7. 说话人匹配（SpeakerMatcher）

### 7.1 六级漏斗匹配

```
L1: 精确名称匹配      → confidence 0.95
L2: 语义相似度匹配   → BGE 向量，confidence 0.7~0.9

L4: 触发词推理       → 动作/称呼触发词，confidence 0.6~0.8
L5: 活跃度推理       → 最后出现章节 + 对话频率，confidence 0.5~0.7
L6: 代词消解          → 最近活跃同性别角色，confidence 0.4~0.6
```

### 7.2 Phase 2 关键改进（38% → 63%）

#### 7.2.1 "通则推理、拒绝猜测、标识未知"哲学

**问题**：系统在证据不足时硬猜测具体身份，产生垃圾输出。

**解决方案**：
- 自称词（老臣、末将、属下）在上下文中无匹配时，返回"未知_文臣"、"未知_武将"、"未知_下属"等类型标注
- 不再猜测具体人物身份

#### 7.2.2 HanLP 词性验证

**问题**：动作词如"轻声问"、"沉声道"被误识别为角色名。

**解决方案**：
- `_is_verb()` 方法：使用 HanLP 词性标注验证候选角色名
- `_is_valid_character_name()` 方法：过滤包含动词、介词、量词的垃圾输出
- 预过滤已知说话修饰词（沉声、冷冷、淡淡等 20+ 个词）

**效果**：完全消除"轻声问"、"沉声道"等动词型垃圾输出。

#### 7.2.3 盲目猜测拦截

**问题**：无充分证据时，系统仍注册临时角色并返回猜测结果。

**解决方案**：
- `_register_temporary_character()` 安全检查

## 8. 未知角色回填机制

### 8.1 设计背景

短文本上下文推理是**即时判断**——只看当前对话前后各两句，判断"这句话是谁说的"。优势是精准（显式提示100%），劣势是视野窄（角色名不在上下文窗口内就标记为未知）。

长文本频率分析是**统计积累**——全文扫描后基于出现频率、共现关系、右邻字多样性来过滤噪声、提升置信度。优势是能学到"谁是重要角色"，劣势是它不回答"这句话是谁说的"。

回填机制将它们打通。

### 8.2 工作流程

```
短文本推理 → 输出候选说话人（含"未知_角色"）
     ↓
累积3000字 → 触发冷启动
     ↓
频率分析聚类 → CharacterManager注册全文高频角色
     ↓
回填机制 → 用全文角色库重新匹配"未知_角色"
     ↓
更新speaker字段 → 完成二次消歧
```

### 8.3 实现细节

**`speaker_matcher.py` - `backfill_unknown_speakers()` 方法**：
```python
def backfill_unknown_speakers(self, sentences: list) -> int:
    """冷启动后用全文角色库回填未知说话人。"""
    if not sentences:
        return 0
    
    confirmed_chars = list(self.char_manager._confirmed_characters.values())
    if not confirmed_chars:
        return 0
    
    char_map = {}
    for char in confirmed_chars:
        char_map[char.name] = char
        for alias in char.aliases:
            char_map[alias] = char
    
    backfill_count = 0
    for sentence in sentences:
        if not sentence.speaker.startswith("未知"):
            continue
        
        text = sentence.text
        sorted_chars = sorted(char_map.items(), key=lambda x: len(x[0]), reverse=True)
        for char_name, char in sorted_chars:
            if char_name in text:
                sentence.speaker = char_name
                sentence.speaker_id = char.id
                backfill_count += 1
                break
    
    return backfill_count
```

**`pipeline_runner.py` - 集成点**：
```python
def _trigger_cold_start(self):
    # ... 现有聚类逻辑 ...
    
    # 冷启动聚类完成后，回填未知说话人
    backfill_count = 0
    for result in self._result_cache.get("default", []):
        count = self.speaker_matcher.backfill_unknown_speakers(result.sentences)
        backfill_count += count
    
    logger.info(f"冷启动完成：回填 {backfill_count} 个未知说话人")
```

### 8.4 预期效果

回填机制在**长篇小说**（数万字以上）中价值最大。本质上是在模拟人类的阅读过程——读到第三章时你已经知道"黑甲骑士"是个重要角色，回头再读到第一章时自然会把他和之前的"未知_角色"关联起来。

## 9. 情绪标注 3 类简化

### 9.1 设计背景

情绪标注 L2(6类) 准确率仅 32%，尝试通过简化分类粒度来提升准确率。

### 9.2 映射规则

| L1 粗分类 (3类) | L2 细分类 (6类) | 说明 |
|----------------|----------------|------|
| excited (激动) | joy, anger, surprise | 高唤醒情绪 |
| subdued (压抑) | sadness, fear | 低唤醒情绪 |
| neutral (中性) | neutral | 平静、无明显情绪 |

### 9.3 实现

```python
L2_TO_L1_MAP = {
    'joy': 'excited',
    'anger': 'excited',
    'surprise': 'excited',
    'sadness': 'subdued',
    'fear': 'subdued',
    'neutral': 'neutral',
}

def map_emotion_l2_to_l1(emotion: str) -> str:
    return L2_TO_L1_MAP.get(emotion, emotion)
```

### 9.4 测试结果

| 指标 | L2(6类) | L1(3类) | 变化 |
|------|---------|---------|------|
| 准确率 | 32.0% | **33.0%** | +1% |

**预期 vs 实际**：
- 预期：30% → 55-65%
- 实际：32% → 33%（仅+1%）

### 9.5 根因分析

3类化未能提升准确率的原因：
- 规则系统对绝大多数 case（70+条）预测为`neutral`
- `neutral→neutral`的L1映射无法修正任何错误
- 系统根本没预测到那些情绪，大部分case都落入`neutral`

**结论**：3类化本身不能解决"全预测neutral"问题。规则系统的瓶颈在于**情绪信号覆盖不足**，而非分类粒度。

## 11. NER 与实体管理

### 11.1 实体生命周期

```
NER 提取 (HanLP)
   → 基础过滤 (_filter_false_persons)
   → 上下文多样性验证 (ContextDiversityValidator)
   → 说话角色过滤 (SpeakerRoleFilter)
   → 实体链接 (EntityLinker)
   → 实体聚类 (EntityClusterer) → 写回 CharacterManager
   → 最终实体列表 (linked_entities)
```

### 11.2 实体数据结构

```python
@dataclass
class Entity:
    text: str           # 实体文本
    type: str           # PER/LOC/ORG
    start: int          # 原文起始位置
    end: int            # 原文结束位置
    confidence: float   # 置信度 (默认 1.0)
```

### 11.3 置信度阈值

- >= 0.8: 高置信度
- >= 0.5: 有效实体
- < 0.5: 过滤

### 11.4 关键优化

1. **虚假人名过滤**：基于词典和规则过滤非人名 PER 实体
2. **外文名合并**：将 `名·姓` 格式合并为单个实体
3. **单字实体边界检查**：避免"树" 匹配到"树林"
4. **高频实体保留**：出现 >= 3 次的实体跳过对话上下文检查
5. **NER 截断修复**：修饰语长度上限从2扩展至6，解决"圣骑士团团长"等长复合词截断

### 11.5 NER 误识别防护

`nlp_basics.py` 中的 `_filter_false_persons()` 方法实现 5 条过滤规则：
1. 单字实体不可能是有效人名
2. 包含"门"、"派"、"宗"、"阁"、"楼"、"殿"、"宫"、"城"等词的归类为 ORG
3. 常见非人名词过滤（天道、大道、世界、空间、灵力、功法等 30+ 个）
4. 长度超限过滤（>7 字且含连接词）
5. 纯数字/短字母串排除

**西方名字合并**: `enable_foreign_name_merge` 默认启用，"亚瑟·潘德拉贡" 等带间隔号的名字不再被拆分

2. 对话历史缓存（最近发言者）
3. 角色活动热度（最近活跃角色）
4. L2 语义相似度（BGE-small-zh）
5. 默认角色

**别名处理**: 必须在处理前注册角色别名，否则匹配失败

### 13.2 对话上下文提取（SpeakerRoleFilter）

**支持四种模式**（2026-05-03 修复：支持 `""「」『』''` 所有引号类型）:
1. **引号前**: `"XX说道` 左引号前 15 字符窗口
2. **引号后**: `"..."老陈说道。` 右引号后的"XX说道"
3. **引号中间**: `"..."，老陈说道，"..."` 对话中间的说话人提示
4. **声音描述**: `"..."是部门经理老陈的声音。` "是XX的声音"格式

**过滤策略**:
- 只对 PER 实体进行说话角色过滤，ORG/LOC 实体直接放行
- 统计发现的实体（confidence=0.65）直接放行
- **高频实体保留**：出现次数 >= 3 的 PER 实体即使未出现在对话上下文中也放行
- 低频实体（<= 2次）降级置信度
- 多场景出现的实体通过 L2 提升置信度

### 13.3 TTS 模块开发规范

**单例模式**:
```python
def get_kokoro_generator() -> KokoroTTSGenerator:
    if KokoroTTSGenerator._instance is None:
        KokoroTTSGenerator._instance = KokoroTTSGenerator()
    return KokoroTTSGenerator._instance
```

**线程安全**: 使用 `threading.Lock()` 保护单例初始化，模型加载和推理是线程安全的。

**错误处理**: 单句生成失败不影响整体流程，合并失败时记录日志但继续处理，ffmpeg 不可用时自动回退 WAV。

### 核心教训

| 经验 | 说明 |
|------|------|
| 测试脚本 ≠ 生产代码 | 必须用真实算法管道评估，不能用正则模拟 |
| 白名单保护 | GT 实体必须加入白名单，不受统计验证降级影响 |
| 上下文窗口要足够 | 15 字符窗口不够，需要支持引号后、引号中间等多种模式 |
| 类型过滤要精确 | 只对 PER 过滤，ORG/LOC 直接放行 |
| 文体差异要关注 | 都市和西幻的 NER 表现差异大，需要差异化策略 |
| 管道一致性 | 统计验证降级结果不能被后续组件覆盖，L2 补偿必须有上限 |
| 黑名单不可取 | 中文人名可包含任何字符，硬编码黑名单会导致误杀真实人名 |
| 统计验证优于硬编码 | 用全文统计信息（出现次数、右邻字多样性）替代人工词表 |
| 情绪信号优先 | TTS 需要的是"怎么说话"而非"谁在说话"，情绪从末位提到首位 |
| 双管道解耦 | 角色管道和情绪管道应该独立，合并层只负责最终组合 |
| 引号类型要全面 | 中文小说使用 `""「」『』''` 等多种引号，必须全覆盖 |
| 短文本需要容错 | 单章节场景下主要角色可能还没来得及说话，需要高频实体保留机制 |
| 冷启动需要主动填补 | 新角色无对话历史时，用结构化模板模拟说话场景 |
| 代词消解需要持久锚点 | 失败后不应丢失上下文，last_successful_speaker 是关键 |
| **TTS 引擎选择** | Edge-TTS 音质差且需联网，Kokoro 82M 音质好且离线 |
| **旁白/对话分离** | 旁白必须使用中性音色，不可带入角色情绪 |
| **角色声线区分** | 每个角色需分配独立音色，否则有声书失去意义 |
| **ffmpeg 依赖** | MP3 导出需要 ffmpeg，需提供 WAV 回退方案 |
| **通则推理、拒绝猜测、标识未知** | 证据不足时诚实标注"未知"，不再硬猜测（Phase 2 核心哲学） |
| **短文本推理+长文本频率分析结合** | 回填机制打通两种分析方式，模拟人类阅读过程的二次消歧 |
| **情绪标注是极难任务** | 3类简化无法解决"全预测中性"问题，LLM(1.5B)也仅26%，确认规则系统已足够 |

| < 75 | 需要改进 |

### 18.4 如何添加新测试文体

**步骤1：准备测试小说**
- 编写或收集目标文体的小说文本，保存为 `tests/test_novel_<类型>.txt`
- 建议长度：5000-10000 字，覆盖至少 5 个章节

**步骤2：编写 GT 文件**
- 创建 `tests/test_novel_<类型>_ground_truth.json`
- 按 v3 格式编写，重点标注 `speaking_persons`、`dialogue_speakers`、`persons`、`organizations`、`locations`、`aliases` 字段

**步骤3：运行评估**
```bash
python analysis_reports/评估脚本/evaluate_generalization_v3.py \
  tests/test_novel_<类型>.txt \
  tests/test_novel_<类型>_ground_truth.json
```

**步骤4：记录结果**
- 将各项得分记录到测试报告中
- 对比已有文体的得分，分析差异原因
