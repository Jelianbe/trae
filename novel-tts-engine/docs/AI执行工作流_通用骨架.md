# AI 执行工作流：通用骨架

**版本**: v1.0
**创建日期**: 2026-05-16
**定位**: 所有优化项的通用执行骨架，不包含任何特定类型的执行细节

---

## 触发条件

当用户提出以下任一意图时自动触发：
- 优化某个功能/模块
- 修复某个问题
- 集成新功能
- 重构代码结构
- 调整配置参数
- 任何需要验证效果的改动

---

## 第 -1 步：优先级裁定

### 检查当前阻塞项
1. 扫描所有开放任务（TASKS.md / 待办清单）
2. 检查是否有未处理的 P0 问题
3. 如有 P0 问题 → 输出裁定结果，建议优先处理 P0
4. 如无 P0 问题 → 进入下一步

### 优先级分类
| 等级 | 定义 | 响应时间 |
|------|------|---------|
| P0 | 核心功能不可用、数据丢失、安全风险 | 立即处理 |
| P1 | 重要功能异常、性能严重下降 | 当前阶段处理 |
| P2 | 次要功能问题、体验优化 | 可排期 |
| P3 | 边缘场景、建议性优化 | 战略储备 |

---

## 第 0 步：备份检查

### 备份要求
- 备份目录格式：`backup_novel-tts-engine_YYYYMMDD_HHMMSS`
- 必须包含：代码、文档、数据、基线记录
- 验证备份完整性（文件数对比）

### 检查清单
- [ ] 备份目录是否存在
- [ ] 备份是否完整（核心文件齐全）
- [ ] 基线记录是否已更新

如备份不存在，执行备份后进入下一步。

---

## 第 1 步：任务类型识别

### 识别逻辑
根据用户意图和优化内容，判断任务类型：

| 类型 | 识别特征 | 加载表单 |
|------|---------|---------|
| 算法迭代 | 调整算法逻辑、优化匹配策略、引入新特征 | `优化项表单/算法迭代.md` |
| 配置调优 | 调整阈值、参数、超时时间、重试次数 | `优化项表单/配置调优.md` |
| Bug 修复 | 修复代码错误、异常处理、逻辑缺陷 | `优化项表单/Bug修复.md` |
| 模块集成 | 接入新模块/功能、LLM 集成、服务对接 | `优化项表单/模块集成.md` |
| 架构重构 | 模块拆分、代码重组、依赖关系调整 | `优化项表单/架构重构.md` |

### 加载表单
识别类型后，加载对应的优化项表单，按表单定义的步骤执行。

---

## 第 2 步：入口检查

### 通用检查项
- [ ] **需求编号**: 是否有关联的 BR-XXX 编号
- [ ] **假设模板**: 是否需要填写假设记录（算法迭代类必填）
- [ ] **基线数据**: 是否有可对比的基线指标
- [ ] **测试环境**: 测试环境是否可用

### 类型专属检查项
由加载的表单定义。

### 检查不通过处理
- 如缺少关键信息，提示用户补充
- 如基线缺失，先建立基线再执行
- 如测试环境不可用，阻塞任务

---

## 第 3 步：执行路由

根据任务类型，路由到不同的执行路径：

| 类型 | 步骤数 | 核心差异 |
|------|--------|---------|
| 算法迭代 | 9 步 | 含假设驱动、过拟合防御、规模感知阈值 |
| 架构重构 | 7 步 | 含结构对比、迁移验证 |
| 配置调优 | 6 步 | 侧重基准对比 |
| Bug 修复 | 6 步 | 侧重根因分析和回归测试 |
| 模块集成 | 6 步 | 侧重接口对接和集成测试 |

---

## 第 4 步：执行改动

### 通用要求
1. 遵循 R-012：最小化范围，不顺手优化
2. 遵循 R-016：硬编码必须有来源注释
3. 遵循 R-005：关键逻辑必须有注释或决策记录
4. 每次只做一个改动，验证后再做下一个

### 改动记录
在表单中记录：
- 改动了哪些文件
- 改动了什么内容
- 改动的原因

---

## 第 5 步：验证

### 通用验证项
- [ ] 功能验证：改动是否解决了问题
- [ ] 回归测试：是否引入新的问题
- [ ] 性能影响：是否影响性能

### 类型专属验证项
由加载的表单定义。

### 验证不通过处理
- 定位问题原因
- 如是小问题，修复后重新验证
- 如是结构性问题，回退并分析

---

## 第 6 步：决策矩阵

### 通用决策规则
| 情况 | 决策 | 操作 |
|------|------|------|
| 目标达成，无副作用 | ✅ 接受 | 合并改动，更新文档 |
| 目标达成，有副作用 | ⚠️ 评估 | 权衡利弊后决策 |
| 目标未达成，无退化 | ⚠️ 记录 | 记录教训，可入战略储备 |
| 目标未达成，有退化 | ❌ 回退 | 恢复备份，清空改动 |

### 战略储备
如方案有价值但短期不达标，存入 `docs/战略储备库.md`

---

## 批量执行模式

### 适用场景
当有多个独立优化项需要连续执行时

### 执行规则
1. 每个优化项独立走完整流程
2. 每项完成后更新基线
3. 每项完成后做一次备份（可选，视改动大小）
4. 全部完成后输出汇总报告

### 批量任务清单
| 序号 | 优化项编号 | 类型 | 状态 | 决策 |
|------|-----------|------|------|------|
| 1 | | | | |
| 2 | | | | |

## 文档同步

### 执行完成后
1. 更新 TASKS.md 任务状态
2. 更新基线记录（如有指标变化）
3. 更新假设记录（如有假设实验）
4. 归档优化项表单（移动到 `docs/优化项表单/已完成/`）

### 双向绑定检查
- 需求 → 任务：每个 BR-XXX 是否有对应任务
- 任务 → 需求：每个任务是否有 BR-XXX 引用
