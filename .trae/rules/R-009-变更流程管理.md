# R-009: 变更流程管理

## 规则内容
当发现问题需新增需求，必须先查询 requirements.md。确认是新需求后，生成一个"变更提案"，提案须包含对新需求的说明和插入项目流程的具体位置（如"在阶段三的说话人匹配模块中……"）。只有在批准后，才能修改对应文件。提案未获批准时阻止修改任何相关文件。

## 触发场景
当进行以下操作时自动触发：
- 新增需求请求
- 用户提出功能变更
- 发现需要新增需求
- 讨论新功能
- 提出改进建议

## 变更提案模板
```markdown
## 变更提案

### 提案编号
CP-XXX

### 提案日期
YYYY-MM-DD

### 需求描述
[新需求的详细描述]

### 需求类型
- [ ] 新功能
- [ ] 功能变更
- [ ] 功能扩展
- [ ] 性能优化
- [ ] 其他

### 插入位置
[在哪个阶段、哪个模块中实现]

### 影响分析
- 影响的需求：[列出受影响的现有需求]
- 影响的模块：[列出受影响的代码模块]
- 预计工作量：[小/中/大]

### 提案状态
- [ ] 待批准
- [ ] 已批准
- [ ] 已拒绝

### 批准记录
批准人：[姓名]
批准日期：[YYYY-MM-DD]
```

## 流程检查
```
发现问题 → 查询 requirements.md → 确认是新需求 → 生成变更提案 → 提交批准 → 等待批准 → 批准后实施

未批准时：
→ 不得修改任何文件
→ 不得创建任何代码
→ 仅作为讨论记录
```

## 优先级
常规优先级 - 保障质量与协作
