# R-004: 准出标准（DoD）

## 规则内容
每个阶段开始前都必须定义完成标准。没有标准，不得开发。每个阶段的 DoD 必须包含至少 3 条可验证标准，DoD 未定义或不完整时阻止阶段启动。

## 触发场景
在任何开发阶段开始前必须检查：
- 项目启动时
- 阶段性任务开始时
- 新功能模块开发时

## DoD 质量标准
每个标准必须满足 SMART 原则：
- **S**pecific（具体的）
- **M**easurable（可测量的）
- **A**chievable（可实现的）
- **R**elevant（相关的）
- **T**ime-bound（有时限的）

## DoD 示例（第一阶段）
1. pytest tests/ 全部通过
2. sqlite3 novel_tts.db ".schema" 输出的表结构与设计文档一致
3. 启动 app.py，访问 localhost，上传测试文件后，前端无报错，显示正确的分章数和词性标签
4. 模拟断网环境，重复测试步骤，功能完全正常

## 强制检查
```
阶段开始前检查：
□ DoD 是否存在？
□ DoD 是否包含至少 3 条标准？
□ 每条标准是否可验证？
□ 是否有明确的验收条件？

如果任何一项为"否"：
→ 阻止阶段启动
→ 提示完善 DoD
```
