# R-006: 全流程文档化 - Bug调试记录

## 规则内容
任何调试时间超过15分钟的Bug，必须在 docs/bug_tracking.md 文件中记录："Bug现象 - 定位过程 - 最终原因 - 修复方案"。这是为了防止未来踩同样的坑。记录必须包含这四个要素。

## 触发场景
当进行以下操作时自动触发：
- Bug调试时间超过15分钟
- 完成Bug修复并准备提交
- 进行代码审查
- 提交修复代码

## Bug 记录模板
```markdown
## [Bug ID] [简短描述]
- 日期：[YYYY-MM-DD]
- Bug现象：[具体表现]
- 定位过程：[如何找到问题]
- 最终原因：[根本原因]
- 修复方案：[如何修复]
- 预防措施：[如何避免再次发生]
```

## 四要素检查
每个记录必须包含：
1. ✅ **Bug现象** - 问题具体表现
2. ✅ **定位过程** - 如何找到问题根因
3. ✅ **最终原因** - 根本原因
4. ✅ **修复方案** - 如何修复

## 文件位置
- 主文件：`docs/bug_tracking.md`
- 或使用：`docs/debug-log.md`
- 或使用：`BUGS.md`

## 优先级
常规优先级 - 保障质量与协作
