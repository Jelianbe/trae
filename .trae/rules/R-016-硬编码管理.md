# R-016: 硬编码管理

## 规则内容
所有静态词表、映射表和常量必须有来源注释。禁止新增 A→B 业务映射表。阈值必须外置到 config.py。

## 触发场景
在任何 Python 代码开发时自动触发：
- 新增常量定义时
- 修改静态词表时
- 添加配置参数时
- 提交代码前（CI 扫描）

## 核心原则
1. **通则推理**: 优先使用句法、词性、标点等通用语言特征做判断，关键词只能是辅助信号
2. **不建新映射表**: 禁止新增任何"A→B"形式的静态映射表
3. **未知优于误判**: 置信度不足时返回"未知"
4. **语言学/统计学依据**: 任何保留的静态集合必须有明确来源

## 硬编码分类

### 禁止类（一律不得新增）
| 类型 | 示例 | 替代方案 |
|------|------|---------|
| A→B 业务映射表 | `{'三人': 'GROUP:3'}` | 正则+数量提取/句法检测 |
| 经验型阈值 | `if score > 0.5:` | 必须外置到 config.py |

### 需审批类（新增必须走审批流程）
| 类型 | 示例 | 审批条件 |
|------|------|---------|
| 静态词表 | `TITLE_WORDS = {...}` | 必须说明来源、边界、上限 |
| 正则模式 | `re.compile(r'...说道')` | 必须说明语言学依据 |

### 可接受类（无需审批，但须有来源注释）
| 类型 | 示例 | 条件 |
|------|------|------|
| 语言学封闭集 | 人称代词、标点符号 | 必须是语言学公认的封闭集合 |
| 统计发现的常量 | 基于全文扫描发现的阈值 | 必须标注统计来源 |
| 协议/标准常量 | GB/T 15834-2011 | 必须标注标准编号 |

## 标准注释模板
所有硬编码词表必须使用以下格式：
```python
# CONSTANT_NAME
#
# 用途：[这个词表用来做什么]
# 来源：[基于什么文献/统计数据/语言学分类]
# 边界：
#   - [哪些东西应该往里加]
#   - [哪些东西不应该往里加]
# 上限：[约N条/词，不应无限制扩容]
# 更新日期：[YYYY-MM-DD]
# 维护者：[维护此词表的规则/责任人]
CONSTANT_NAME = {'...', '...'}
```

## 强制检查
```
新增常量前检查：
□ 是否可以用统计/语言学方法替代？
□ 是否有明确的来源？（语言学分类/国家标准/统计结果）
□ 是否有清晰的边界？（什么该加、什么不该加）
□ 是否违反"不建新映射表"原则？
□ 如果是阈值，是否已外置到 config.py？

提交代码前检查：
□ 运行 python scripts/scan_hardcode.py --ci
□ CI 检查必须通过（退出码=0）
```

## 违规处理
| 等级 | 定义 | 处理 |
|------|------|------|
| P0-严重 | 新增 A→B 映射表 | 立即拒绝，必须改造 |
| P1-高 | 新增硬编码无来源注释 | 要求补充注释后重新提交 |
| P2-中 | 新增阈值未外置到 config | 要求迁移后重新提交 |

## 自动化检测
- 扫描脚本: `scripts/scan_hardcode.py`
- CI 模式: `python scripts/scan_hardcode.py --ci`
- JSON 输出: `python scripts/scan_hardcode.py --json`

## 优先级
高优先级 - 防止技术债务再次积累
