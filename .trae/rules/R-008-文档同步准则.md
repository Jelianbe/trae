# R-008: 文档同步准则

## 规则内容
一旦代码逻辑发生改变，必须检查这种改变是否影响到需求或任务。如果是，必须将更新文档作为变更的一部分，严禁先改代码后补文档。文档未同步时阻止代码提交。

## 触发场景
当进行以下操作时自动触发：
- 代码逻辑发生变更
- 提交代码
- 修改涉及需求或任务功能
- API 接口变更
- 配置文件变更
- 数据库结构变更

## 同步检查流程
```
代码变更 → 检查影响 → 判断是否需要文档更新

需要更新的情况：
□ 需求功能变更
□ API 接口变更
□ 配置项变更
□ 用户可见的行为变更
□ 性能特征变更

同步要求：
1. 文档更新必须与代码变更同时提交
2. 严禁先提交代码，后补文档
3. 文档未同步完成不得合并代码
```

## 文档更新清单
- [ ] requirements.md（如果需求功能变更）
- [ ] TASKS.md（如果任务状态变更）
- [ ] README.md（如果使用方式变更）
- [ ] API 文档（如果接口变更）
- [ ] 注释更新（如果代码逻辑变更）

## 优先级
常规优先级 - 保障质量与协作
