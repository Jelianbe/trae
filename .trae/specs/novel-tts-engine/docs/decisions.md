# 决策记录

## 算法选择决策

### 对话/旁白分类 - 规则+FastText混合策略
- **决策理由**: 规则方法在明确模式下准确率高（约70%场景），FastText作为兜底处理边缘情况，平衡准确率与性能
- **数据结构设计**: 使用双层分类器架构，规则引擎优先，统计模型兜底

### 说话人匹配 - 四级匹配策略
- **决策理由**: 别名匹配最快最准确，标准名匹配次之，向量匹配处理模糊情况，活跃度作为最终兜底
- **数据结构设计**: 角色库采用SQLite持久化，角色向量使用FastText/BGE-small向量化

### 情绪标注 - 规则+朴素贝叶斯混合策略
- **决策理由**: 规则覆盖常见情绪表达模式，朴素贝叶斯处理复杂上下文，规则优先保证可解释性

## 技术选型决策

### 框架选择 - FastAPI + Streamlit
- **决策理由**: FastAPI提供高性能异步API，Streamlit快速构建原型界面，两者组合实现快速迭代

### NLP工具 - HanLP完整离线版
- **决策理由**: 纯离线运行、功能完整（分词、词性标注、NER、句法分析），满足本地部署需求

### 向量化模型 - FastText + BGE-small ONNX
- **决策理由**: FastText轻量快速，BGE-small提供更好的语义相似度，ONNX格式支持跨平台优化

## 架构设计决策

### 模块划分原则
- **决策理由**: 按功能职责划分模块，每个模块单一职责，便于测试和维护
- **模块结构**: pipeline/（核心处理）、db/（数据库）、models/（模型封装）、utils/（工具函数）、frontend/（前端）

### 数据流转设计
- **决策理由**: 单向数据流，章节→分词→分类→匹配→标注→输出，便于追踪和调试
- **数据格式**: 统一使用JSON作为内部数据交换格式，便于序列化和调试
